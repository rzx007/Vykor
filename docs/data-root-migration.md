# 用户数据根与迁移恢复

> 状态：当前数据位置与迁移约定。实际验证范围见[验收记录](./data-root-verification.md)。

`dataRoot` 是整个用户数据根，默认是 `~/.vykor`，其中的 `data/` 只是运行数据子目录。桌面、CLI、系统后台和 Node SDK 使用同一个根。进程启动时依次选择首位 `--data-root <绝对路径>`、`VYKOR_CONFIG_DIR`、home 下的 `.vykor-root.json` 定位记录、默认值；选定后本进程不再切换根。

## 数据放在哪里

根下保留 `cache/`、`channels/`、`data/`、`local_rules/`、`output_styles/`、`plugins/`、`skills/`、`teams/`、`worktrees/`，并包含 `workspaces/`、`agents/`、`SOUL.md`、`USER.md`、`user_profile_pending/` 及凭据、设置等原有文件。未知文件原样保留。所有默认位置由 `@vykor/host-config/paths` 派生。

- 正式会话数据库：`data/session-runtime/sessions.db`；同级保存附件、笔记、存储策略和用量设置。
- 普通聊天草稿、未保存笔记和图片批注：`data/desktop/`。业务导出清单只保存来源摘要与处理状态。
- 无项目聊天工作目录：`workspaces/`；渠道工作目录：`channels/`；受管任务 worktree：`worktrees/`。
- 规则、记忆、运行环境密钥、记忆备份、导出和审计继续由同一个根派生。迁移后项目 ID 和内容来源保持。

临时会话的消息、普通 Run（一次执行）、目标、权限和事件只放内存，重启后不会从数据库、草稿或迁移记录恢复。临时来源附件、工作流、显式长期记忆和工具文件仍按原生命周期保存；迁移只统一其位置。

真实项目、共享技能、外链插件来源及其它工具的凭据保持原位置。Electron 的浏览器缓存、窗口偏好、主题、材质和宠物设置仍留在原 `userData`；迁移不会整体复制或清空 localStorage。

## 先预检，再迁移

```text
vk data-root inspect --from <完整旧根> --to <完整目标根>
vk data-root migrate --from <完整旧根> --to <完整目标根>
vk data-root recover --journal <完整迁移记录路径>
vk data-root recover --startup-lock
```

`inspect` 只读取：列出来源、复制清单、冲突、空间估算和重启影响，不创建锁、目录、定位记录或数据库，也不输出凭据、消息或草稿。旧 `VYKOR_DATA_DIR`、`VYKOR_CHANNELS_DIR`、图片缓存覆盖及旧数据库位置用于识别迁移来源；它们不再把正式运行数据分散到根外。旧覆盖与新规则不同，或真正外部固定的根与目标冲突时，先处理预检冲突；程序不修改用户全局环境变量。

桌面可用 `Vykor data-root` 打开受限本机维护窗口，明确旧根时使用首位参数 `Vykor --data-root <旧根> data-root`。此入口在正常业务对象创建前运行，旧分离数据布局也能导出；不会为了分类草稿创建另一空会话库。桌面恢复使用 `Vykor data-root recover --journal <记录>`，只有死亡普通启动锁且没有待完成迁移时使用 `--startup-lock`；两种恢复参数不能同时传入。

只有旧环境变量记录了分离目录时，维护导出会把已经核实的来源路径和目录身份保存在 `data/desktop/legacy-import.json` 的 `legacySources` 中，绑定原根和宿主 profile/Documents。用户清除旧覆盖并重新打开维护后，程序从该收据补回缺省来源，再完整预检；当前明确来源和已有正式数据库优先。收据不接受 renderer 自报路径，身份变化或多个数据集冲突会拒绝；只在目标暂存副本标记已处理，源收据保留，后续迁移不会复活旧数据库。

桌面迁移前先冻结编辑，等待所有窗口保存业务数据，再产生本次导出扫描。未知归属的旧草稿仍保留原键，用户明确选择保留旧副本后，只确认当前来源摘要，不导出未知正文。CLI 不解析 Electron 的 LevelDB；涉及桌面业务内容时必须完成实际桌面导出。

草稿 flush（最后一次写入）失败且尚未封闭写入口时保留窗口和内存内容；只有确认原根身份未变、恢复已放行源且没有待完成记录后，才恢复编辑并允许重试。已经封闭写入口的旧对象不再复用，成功或回退后都重新启动。

## 执行和保留副本

迁移先取得 home 中的固定锁并记录待完成状态，阻止普通进程重新打开源。已有执行、终端、上传、插件和渠道写入必须结束；只停止已经核对 PID、登记和鉴权身份的后台。系统常驻定义先私有备份，再暂停，保持原本的启用状态。

随后复制到目标相邻的暂存目录，校验停写后的数据库与 WAL（尚未归并进主文件的已提交写入），再按复制清单归并。只改已知结构里的受管绝对路径；消息、Markdown、命令文本、授权和外部路径不做全局替换。Git 使用实际 `worktree repair` 并核对分支、HEAD、索引、脏文件和未跟踪文件。

目标由独立验证进程打开已有数据库；验证期间不运行恢复任务、定时任务、渠道或资源清理。验证通过后提交定位记录、放行目标写入，再启动全新的普通后台和桌面。旧进程不会原地换库。

默认保留源数据。同根归拢先将源改名为备份再安装暂存目录；跨盘使用独立复制，不依赖跨盘 rename 或硬链接。主迁移记录位于目标父目录的 `.vykor-migration-<ID>.json`，私有服务定义和验证备份位于它旁边；记录不存正文或密钥。

## 失败后使用哪个根

- 待完成记录或坏定位记录会阻止普通启动，避免意外创建第二套空会话。使用报错给出的迁移记录运行 `recover`，保留现场文件。
- 目标尚未放行写入：恢复按同一记录核对数据库、目录、Git 和原服务定义，再恢复源选择；重复恢复不会重复导入。
- 目标已经放行写入：保留目标选择，只允许向前修复，不能自动切回旧副本覆盖新内容。本迁移的 pending 若在中断时尚未清除，`recover` 核对当前目标身份后补完清除；重复调用保留新写入，不再按旧摘要回退数据。
- 源已在恢复中重新放行：后续服务启动失败只修服务，不回退源的新写入，也不覆盖下一次迁移的待完成记录。
- 遇到未知文件变化、活进程、身份不符、权限不足或无法证明恢复安全时，保留副本并报告失败阶段、当前根与记录位置；不强制解锁或删除未知数据。

home 中 `.vykor-root.json` 和 `.vykor-root.json.lock` 是正常情况下根外的启动元数据。它们负责选择与互斥，不是可随手删除的缓存。完整根的人工清理规则见[开发数据重置](./development-data-reset.md)，后台停写顺序见[运维与恢复](./operations-and-recovery.md)。
