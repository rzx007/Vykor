## 迁移与恢复的贯通证据

- 不同中文根连续迁移两次，真正的 CLI 验证子进程打开目标，SDK `ensure/discover/stop` 控制实际新后台；全新目标进程恢复原正式会话并实际续聊，关闭退出后再次迁移。原数据库保留，凭据不是硬链接，历史文件路径映射链仍可读。
- 临时会话实际执行并创建目标，正文不进入源/目标数据库或迁移记录；临时草稿不导出，未知旧草稿只留原键。正式草稿的原 inputId、较新编辑、窗口偏好和缓存保留。
- 同根安装后注入故障，执行同一记录的两次恢复，核对原数据库字节、原选择和业务导入。实际 Git 分支、HEAD、索引、脏文件与未跟踪文件由同分类真实 Git 测试覆盖。
- 仅旧环境变量记录的分离库，先由宿主导出来源收据，再清 pin 重启，仍能找到原库、渠道与图片来源；当前正式数据库优先，伪造绑定或目录身份变化拒绝。只在目标副本消费收据，源仍保留。
- 最终审查发现并补齐“已持久化放行标记、尚未清 pending 就中断”的入口：真实 `vk data-root recover --journal ...` 向前完成目标选择。重复调用保留新写入，目标身份不符、其它 pending 或错误选择均拒绝；不会恢复旧目录、Git 或源服务。

- WSL Debian 使用官方临时 Node 22 和真实 SQLite/Git，`/tmp` 与 `/dev/shm` 是不同文件系统，完整复制、提交、恢复和 Git 恢复中断已验证。这不替代 Windows 结果。
- Windows Git 2.53 已验证；源主仓库保留且主仓库路径改变时要求 Git 2.48 以上。Debian Git 2.47.3 的外部主仓库及同根路径未变场景已有实测，每次仍检查实际修复结果。
- macOS/Linux 服务定义使用独占目录及适配器，未注册真实用户系统服务。Desktop 的重启参数、原环境来源、preload/IPC、flush 和草稿导出由受控 app、真实业务模块与 jsdom 验证；没有把它们冒充真实 Electron profile/图形重启实测，A13 该部分仍未完成。
