# 工具结果与运行终止分离

## 目标与设计

按已确认的 Codex 处理方向，工具超时、普通执行失败和结果未知均交付模型，包含错误、已有输出和恢复提示。`unknown` 只说明操作效果无法确认，不决定运行终止。

入口仍为 `executeCheckedTools()`，模型、SDK 显式调用和工具内部调用共用此入口。执行器返回工具结果和独立的致命失败通道；只有运行限额、宿主存储、实际调用跟踪或生命周期交付等无法继续可靠执行的错误进入致命通道。父子受检执行通过独立的致命失败上报能力和启动门禁连接，不依赖代理是否捕获异常；门禁不取消已经开始的调用。已知操作未解决时拒绝重新派发，拒绝本身作为工具反馈返回。

宿主 `ToolOperationService` 和 SQLite 账本继续决定写入是否允许：结果未知的写入阻止同一会话树中的后续危险操作，可信只读工具可以核查。新调用 ID、替换工具名和普通成功读取均不能解除这项保护。迟到回执仍只更新原操作，不重复交付模型；确认完成后，后续操作才恢复。取消仍遵守原来的运行边界。

不将 Shell 命令名、工具自由声明或 `safeToRetry` 当成可信只读证明。不自动重试，也不迁移存储结构。

## 验收

1. Shell 超时后模型能读到错误与已有输出，并完成解释或核查。
2. 相同未解决操作不会重放；新 ID 和其他写工具仍受宿主账本保护。
3. 未解决写入存在时，可信只读操作和模型解释仍能继续；未经宿主确认的读取不能解除保护。
4. 收到真实迟到成功回执后可恢复后续写入，但不会追加第二个同调用结果。
5. 保存回执失败、交付失败、运行取消和限额仍按原边界阻止执行。

## 验证与审查

回归先复现旧机制的 `has an unknown outcome` 错误。独立审查又发现原先依赖该错误隐式兜底的嵌套宿主故障及调用跟踪故障；增加红测后显式上报。代理捕获准备保存、回执保存和生命周期交付错误后再次调用工具的三个回归，均验证后续调用未启动且仍传播原始致命错误。最新版本复审无必须修复项。

Core 499 项、Agent 跨包集成 129 项、Server 相关 40 项及 MCP 代理 17 项通过；Core/Server 类型检查、文档和退役入口检查通过。Server 另一个后台 Shell 宿主夹具用例读取旧接口，在原始 HEAD 的临时快照中同样失败，本次未修改该功能，定向 Server 回归排除此项。模型取消仍停止请求，SDK 显式调用按既有契约返回 interrupted 错误结果。

提交前再次独立审查职责边界：操作账本持有写入保护，受检执行器持有批次启动门禁和致命失败，QueryEngine 负责交付与继续模型请求。删除了没有独立行为的错误子类，直接复用现有策略错误；保留有实际回归场景的父子故障上报与启动门禁，没有增加全局状态或新的运行控制层。全仓 `pnpm check-types`（含 Server/Client 契约检查）通过。
