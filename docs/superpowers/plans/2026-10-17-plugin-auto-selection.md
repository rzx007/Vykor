# Plugin Auto Selection Implementation Plan

**Goal:** 在主执行前按已启用插件摘要选择一个插件，保留明确指定和手动延续，自动结果只属于本轮。

**Architecture:** 服务端执行器决定是否需要选择；运行时复用当前客户端进行一次无工具辅助请求；校验后仍通过现有 RunCapabilityView 执行。选择结果保存到 Run 元数据，不变更会话 activePluginId。

**Spec:** 本聊天已确认的 B 最小方案。

**Constraints:** 不做 ToolSearch；不安装或升级插件；不扩大工具或子任务权限；不自动切换正在执行的插件；UI 复用现有组件，只进行代码检查。

## Task 1: 无工具选择与运行时接入

- [x] 添加测试：摘要选择一个或不选、未知 ID/损坏 JSON/失败退回公共能力、取消与预算限制、一次请求、用量结算。
- [x] 运行新增测试，确认缺少选择行为而失败。
- [x] 实现短摘要和严格结果校验，复用当前请求配置及辅助模型请求封装。
- [x] 运行时提供候选及版本内容校验，Agent 提供受维护锁保护的宿主选择入口。

## Task 2: 本轮决策与权限边界

- [x] 添加执行器测试：自动结果只保存 Run、主执行仅有公共工具和选中插件、明确选择跳过请求、空结果不重选、禁用与取消、准备失败不换包。
- [x] 在创建能力清单前接入选择；将限额检查放在辅助请求之前，保存结果及来源。
- [x] 重试复用 Run 已解析决定；运行中输入继续遵守现有排队边界；移除调用方伪造的选择元数据。

## Task 3: 用户控制与验证

- [x] 补充自动选择开关的协议及桌面现有控件，支持清除手动选择恢复自动，显示实际本轮选择。
- [x] 运行涉及的协议、运行时、服务端和桌面测试及类型检查。
- [x] 检查差异及授权/版本/取消/重试边界，修复发现的问题。

按用户授权在当前工作区顺序实施。保留既有调研资料，不进行提交、合并、发布或新增依赖。

## 实现与验证记录

- 选择请求复用当前模型和客户端，工具列表为空；最多一次，15 秒超时，输出上限 256 token，不自动重试。无候选、手动选择或关闭自动选择时不发请求。
- 自动结果只保存 Run，显式指定与手动延续仍使用现有路径。无匹配、未知 ID、格式错误和请求失败退回公共能力；取消、限额阻止和插件来源变化会终止本轮。
- 恢复复用已解析结果并核验版本及内容；已关闭或变化的插件不会被替换成另一插件。输入中的伪造选择元数据被移除。
- 普通输入补充到当前轮次时沿用该轮能力清单；“立即补充”同样支持，显式引用或已解析冲突仍拒绝。不会将该自动选择写成会话手动选择。
- 通过运行时选择与单插件清单、服务端执行/恢复/补充/投影、Goal 用量、事件校验、协议以及桌面控件/状态/IPC 的定向测试；通过相关包与桌面 node/web 类型检查及 `git diff --check`。
- 独立只读复核发现的队列补充、关闭插件后恢复两项问题，均先补失败回归，再修复并复核。
- 未调用真实模型评估匹配质量，未进行界面样式预览；这些仍需实际使用验证。
