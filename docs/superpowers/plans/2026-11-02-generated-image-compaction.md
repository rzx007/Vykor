# 手动压缩保留生成图引用

**目标：** 手动压缩、重复压缩及服务重启后，同会话生成图仍可读取和继续编辑；文本中的伪造地址不能授权，删除资源载体或会话后撤销访问。

**机制：** 复用当前生成图与成功工具调用的授权判断。近期仍保留的生成调用补回附件部分；被摘要的生成图，把最小调用凭据和附件引用存入现有压缩完成记录，放在摘要之后、保留的近期消息之前。所有引用与新转录一次写入。该展示记录不进入模型历史，宿主在压缩边界文本中确定性写入有界附件目录；不依赖模型摘要，不复制旧调用的大参数或结果，不新增表。

## 实施与验证

- [x] 提取现有生成图引用判定，供授权读取、压缩保存和目录共同使用。
- [x] 先写归档、近期保留、重复压缩及伪造来源的单元回归，再实现最小转录保留逻辑。
- [x] 压缩完成记录和附件凭据纳入同一次 `replaceTranscript()`；同步温热实例的模型历史。
- [x] 用真实 Agent、真实压缩、真实附件存储验证读取、编辑、重启、再次压缩、删除撤销及跨会话拒绝。
- [x] 更新目录说明，运行相关测试及服务端类型检查。
- [x] Ponytail 独立复核复杂度和权限边界；最终仓库检查后，仅提交本次改动并推送。

测试使用现有 Vitest；外部模型和图片服务使用替身，压缩摘要故意省略附件地址。生成图原件校验值必须保持一致。

最终相关回归为 9 个文件、91 项通过。压缩机制单元回归 12 项，真实生命周期回归 3 项（轻量压缩、完整摘要压缩、外会话伪造地址）。覆盖重启、编辑最新用户消息、原图再编辑、多次压缩、重复调用 ID、多边界目录去重及保存失败时关闭内存实例。保留全部授权凭据，模型目录只展示最近 20 项、最多 12000 字符的完整 URI 行。
