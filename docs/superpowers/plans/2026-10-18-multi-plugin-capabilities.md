# 多插件能力自主使用：第一阶段实现计划

**目标：** 取消独立选择模型。默认执行 Agent 直接使用本轮已启用、已授权的多个插件，保留显式限制、队列和恢复的原有边界。

**架构：** 输入由宿主保存范围快照，Run 开始时验证来源并捕获不可变能力绑定。模型只决定使用哪些已允许能力，Skill 正文按需读取。core 继续处理通用执行和绑定来源，不负责插件路由。

**约束：** 不构建、不调用真实模型、不安装依赖，不实现 UsePlugin、ToolSearch 或 BM25。保留工作区已有的两个 goal 文档删除。

## 任务与验收

- [x] 运行时范围与来源：修改 `run-capability-view.ts`、`runtime-integrations.ts`、原生工具和子任务校验。覆盖同时允许 P/Q、限制 P、伪造归属、跨范围子任务和 UI。
- [x] 输入、队列与恢复：修改 server 的范围解析、输入接收、executor 和 run-control。覆盖先入队后 @、补充转队列、恢复、禁用和来源变化；包含活动 Run 尚未完成范围解析的窗口。
- [x] 能力发现提示：添加有界插件摘要，合并本轮与 Goal 的系统指导；ListSkills 增加分页和来源过滤。摘要不授权，正文继续经 Skill 读取；空范围明确说明限制，禁止借扫描安装目录来发现未授权能力。
- [x] 清理独立选择接口和测试，保留历史用量分类；桌面自动模式文案改为多能力语义，手动限制继续延续。
- [x] 集成回归：模拟客户端完成 knowledge → office 顺序调用、零选择请求、Skill 来源、MCP 和私有数据边界验证。
- [x] 宿主生成输入：目标和 UI 交接复用现有范围服务；目标续跑沿用同一正文版本保存的范围，兼容旧版已解析的单插件和空范围。普通子 Agent 重建基础工具时保持插件空范围。
- [x] 直接运行相关包源码 Vitest、必要的无输出类型检查和 `git diff --check`；不运行 pnpm/turbo 根检查脚本。

## 验证入口

在目标包目录使用 `node ../../node_modules/vitest/vitest.mjs run --config ../../vitest.config.ts <相关测试路径>`。桌面使用已有 Vitest 配置。类型检查只使用已存在的 TypeScript `--noEmit` 配置，不触发依赖构建。

## 完成要求

每条实际执行能力有捕获的来源；自动结果不写会话手动选择；队列输入不受后续 @ 污染；恢复不扩大来源，禁用和来源变化明确失败；所有验证报告实际命令与结果。
