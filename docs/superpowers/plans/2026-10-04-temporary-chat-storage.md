# 临时聊天存储实现计划

**Goal:** 正式与侧边聊天在同进程复用业务逻辑，聊天数据按创建时归属分别提交到 SQLite/JS 内存。

**Spec:** ../specs/2026-10-04-temporary-chat-storage-design.md

**Architecture:** 保留单个应用/共享读模型，用明确的 ChatPersistence 路由提交和 checkpoint。持久资源共用原存储并记录来源，临时控制记录不引用 SQLite 中不存在的聊天外键。

## 任务

- [x] 核心：添加 SQLite/JS 内存聊天存储接口和实现；SessionRepository 保存不可变 storage 归属，普通子会话继承；过滤所有聊天记录与事件；支持回滚、checkpoint、删除和异步提交边界。
- [x] 创建链路：Protocol/Client/HTTP/SessionCommand/desktop fork 传 storage；侧边关联仅存在内存；临时默认自动记忆关闭，显式记住允许。
- [x] 持久资源：附件/工作流记录来源；处理临时 owner 外键和引用清理；Drizzle 生成增量迁移并更新必要验证。
- [x] 临时控制：Goal、请求/continuation、projection settlement 等必要运行控制数据使用内存，并参与同一失败恢复；保留共用业务计算。
- [x] 验证：先写针对性失败测试，再实现；独立审查；测试、类型和打包/迁移检查按实际范围运行。

## 范围约束

- 根代理处理 services 会话核心和集成；并行代理分别处理创建/UI/记忆策略、持久资源来源、临时控制记录，避免覆盖互相改动。
- 新增异步边界必须等待提交后才发布，不能静默忽略 Promise；既有纯内存读取不全部 async。
- SQL 迁移是正常产物，保留既有迁移；不实现 MySQL/PG，不处理 browser annotations 相关修改。

## 验证记录

- 提交前存储回归：28 个文件、292 项测试通过；包括 SQLite/内存并存、重开生命周期、checkpoint、事件去重、同步入口拒绝 Promise、回滚与持久资源来源。
- 服务端：9 个文件、126 项测试通过；完整 Client/HTTP 输入、运行、工具事件、权限回复、结束与重启另有真实混合会话测试通过（模型/Agent 为既有外部依赖替身，存储和业务流程真实）。
- services/server/protocol/client 类型检查通过，Desktop node/web 类型检查通过。
- CLI/Desktop 数据库初始化与重开打包验证、Drizzle db:check、架构边界及 clean-slate 检查通过。
- 独立审查已修复跨存储审批、跨会话输入/Run 引用、重复事件、异步提交误判、工作流恢复回写已消失的临时会话、transcript 附件来源遗漏。前端重启恢复、两份草稿保留和检查槽清理竞态已修复并通过独立复查。
- 最后侧边聊天与临时状态检查：2 个文件、50 项通过（侧边 46 项、临时状态 4 项）；此前相关桌面状态/操作回归也通过。
- 最终审核补充修复：全局事件序号预留覆盖临时事件，正式快照游标重启不回退；临时正文立即保存到 JS 存储，无关 SQLite 保存失败不丢已接受增量，失败事务内增量仍回滚。两项测试先复现失败、修复后通过，独立复查已关闭。
- 最后 HTTP 全流程回归通过，验证正式与临时会话共用输入、运行、工具、审批和结束流程，重启仅恢复正式聊天。
- 所有独立审查问题已修复并复查关闭；未扩展到通用数据库框架、第二个应用或 MySQL/PG 实现。
