# 三档授权与独立计划模式设计草案

> 状态：当前。已实现三档授权、独立计划模式和自动审批；跨平台真实系统隔离不在本轮验证范围。

## 1. 目标与范围

授权菜单提供“请我批准 / 帮我批准 / 完全访问权限”。计划模式由 `@ / +` 唤起，并作为独立的当前会话状态显示。已有 `/plan` 继续作为同一个开关的快捷入口。

本次调整覆盖桌面主聊天、侧边聊天、目标创建会话，以及共用协议的客户端。复用现有输入框、授权卡片、会话配置和模型客户端，不增加一套编辑器或新的凭据管理方式。

不在本次范围内实现原生 Windows 的新系统沙箱后端。当前平台没有系统隔离时必须准确说明能力；不能把工具参数检查描述成对任意命令和子进程的隔离。

## 2. 对用户的行为

| 授权选项 | 行为 |
| --- | --- |
| 请我批准 | 已允许的操作直接执行；其余需要授权的操作显示用户审批。 |
| 帮我批准 | 已允许的操作直接执行；其余先由独立审查请求判断，可以自动通过、请求用户决定或拒绝。 |
| 完全访问权限 | 在系统和强制策略允许的范围内扩大当前会话的文件、命令与网络访问，通常不再请求普通操作审批。 |

新安装首次默认“请我批准”；不在这次改造中额外改变用户已保存的有效默认值。用户可主动选择另外两档。完全访问只授权当前执行环境，不授予系统管理员权限，也不替代外部应用自己的登录和同意流程。

选择计划模式后，输入框附近出现可移除的“计划模式”标记，授权按钮保留原选项。发送消息后标记继续显示；切换聊天或重启后从会话记录恢复。用户移除标记、再次执行 `/plan`，或明确点击“开始执行”后退出。

计划模式允许可信只读工具，阻止文件修改、命令执行、后台任务变更及其他有副作用的工具。授权为完全访问时也必须遵守计划限制。用户开启的计划模式不能被模型调用 `ExitPlanMode` 自行解除；模型临时进入计划仍只缩小权限，退出最多恢复用户当前选择。

## 3. 状态放在哪里

协议增加两类独立状态：

```ts
export type ApprovalMode = "ask" | "auto_review" | "full_access";
export type WorkMode = "execute" | "plan";
```

- `settings.permission.mode` 保存新聊天采用的默认授权档位，不保存计划开关。
- `session.metadata.runtime.approvalMode` 保存当前聊天授权档位。
- `session.metadata.runtime.workMode` 保存当前聊天工作模式。
- 新聊天尚未创建时，工作模式仅存在当前新聊天的内存状态。首次发送和创建目标时一起写入会话；不因此修改全局默认。
- 正文和附件仍保存在原有草稿里，不把工作模式伪装成纯文本、Skill 或插件引用。
- 每次运行记录当时的模式与配置修订号，历史展示读取真实运行状态，不使用当前菜单值回填。

运行时可以把两类状态计算成现有工具检查器的只读或自动执行限制；内部计算结果不是第三份可写会话状态。必须同时更新给模型的工具与模式说明，以及真正拦截工具的检查器。

## 4. 一次操作怎样得到决定

```text
模型提出工具与参数
  → 检查工具来源、强制禁止规则和计划限制
  → 已有明确允许规则：直接执行
  → 其余根据授权档位处理
      请我批准：保存授权请求 → 用户决定
      帮我批准：保存授权请求 → 独立审查 → 自动通过 / 转用户 / 拒绝
      完全访问：使用当前会话允许的扩大访问策略
  → 执行前确认请求没有取消、过期或被配置变更替代
  → 执行并记录真实结果
```

保留 `allow | ask | deny` 的工具检查结果和 `approved | denied | expired` 的授权终态。审查过程作为授权请求的附加记录，不混用现有“完成后代码检查”的 `autoReview` 状态。

普通聊天问题和必须由用户完成的应用授权不交给自动审批。主代理、插件参数、工具输出或引用文档中的“已获批准”文字都不构成人类授权证据。

## 5. 帮我批准的第一版

使用独立、无工具的模型请求审查一项具体操作；复用当前会话的模型服务商和凭据解析。不给审查请求执行工具、写文件、改变权限或再次申请审批的能力。

输入包含：真实工具来源与用途、准确参数、当前访问边界、适用禁止规则、用户直接指令，以及必要的有界上下文。用户直接指令从持久输入记录和当前运行的 inputId 读取；宿主转交请求时保留 inputId、cwd、agentId。工具结果和引用内容明确标为资料。机密值不重复放入审查提示；缺少必要证据时转用户。

建议审查结果结构：

```ts
export interface ApprovalReviewResult {
  decision: "approve" | "ask_user" | "deny";
  risk: "low" | "medium" | "high" | "unknown";
  authorization: "explicit" | "task_implied" | "missing";
  reason: string;
}
```

- 与明确任务一致的普通项目修改可自动通过。
- 删除大量文件、向外部发送内容、部署、凭据与系统设置变更等操作检查具体授权范围；范围缺失或不能确定时询问用户。
- 强制禁止规则命中的操作直接拒绝，审查模型不能覆盖。
- 未知插件、动态脚本及无法判断影响的命令不能只凭工具名自动通过。
- 当前环境没有可靠系统隔离时，不能仅凭命令声称在项目目录运行，就自动批准任意 Shell；没有足够证据的调用转用户。
- 第一版审查超时上限为 30 秒、输出上限为 1024 tokens、理由上限为 1000 字符。失败或格式不合法时转用户，操作保持未执行。
- 自动通过只适用于该次请求的准确工具、参数与配置修订，不生成整个工具的会话级通行证。
- 取消或重启使未完成请求过期；迟到的审查结果不得恢复执行。审查拒绝后不能换工具或改写命令来实现同一被拒绝操作。
- 先建立等待与结算机制，再启动自动审查；人工先回复时以已经保存的终态为准，不能因自动结果先于 waiter 注册而挂起，也不能结算两次。

界面区分“正在自动审查 / 已自动批准 / 需要你确认 / 已拒绝 / 审查超时”，并可查看简短理由。例行已允许操作不额外发模型请求，减少等待与费用。

## 6. 完全访问与配置切换

完全访问必须通过会话级执行策略作用于文件工具、网络工具、Shell、PTY 和后台任务，不写入全局 `sandbox.enabled = false`。强制禁止、计划限制和外部环境限制仍然先行。当前代码的主要传递点包括 `session-execution-environment.ts`、沙箱执行环境、文件 `sandbox-guard.ts` 和网络 `sandbox-network.ts`；后台任务不能重新读回全局设置而丢失会话策略。

切换授权或工作模式时，界面等待后端确认后再允许依赖新模式的发送。正在执行的工具不被中途伪装成使用了新模式；尚未开始的授权请求取消或过期，再在新的安全执行边界读取配置。计划限制需要在下一个工具开始前生效。

主聊天、侧边聊天和派生会话不能互相覆盖模式。子代理继承父运行的限制，不能自行取得更宽权限。计划模式不能通过调用插件、内部代理或自动钩子绕开。

## 7. 存量数据转换

存量值在共用读取函数中集中归一；新界面写入独立字段，写回新模式时清除旧会话字段。底层工具检查器保留内部只读限制值，不在各界面散落存量判断。

| 旧状态 | 新状态 |
| --- | --- |
| 会话 `permissionMode: default` | `approvalMode: ask, workMode: execute` |
| 会话 `permissionMode: plan` | `approvalMode: ask, workMode: plan` |
| 会话 `permissionMode: full_auto` | `approvalMode: auto_review, workMode: execute` |
| 全局 `mode: plan` | 默认授权 `ask`；新聊天工作模式为 `execute` |
| 全局 `mode: full_auto` | 默认授权 `auto_review`，审查不可用时逐项转用户 |

旧自动批准不静默升级成完全访问。已有拒绝规则和路径规则保留。旧历史运行记录按其记录解释，不能改写成当时存在自动审查。

## 8. 实施与验收顺序

1. 先打通独立模式的类型、持久化、创建与恢复、运行时限制。
2. 桌面 `@/+`、`/plan` 和模式标记共用一个会话动作，修复退出计划覆盖授权的问题。
3. 实现无工具的独立审批请求和结果校验，再接入现有持久授权链路。
4. 实现当前会话的完全访问策略与各执行入口一致性。
5. 完成旧数据转换、CLI / 前端 / 定时任务等共用入口适配，最后启用三档完整菜单。

每一步运行对应模块测试，不重复全量套件。界面样式由用户查看反馈，不启动预览或截图。完整菜单只在对应行为可执行后发布，不展示尚未接通的占位选项。

验收必须证明：退出计划保留授权档位；计划加完全访问仍拒绝修改；自动审批不扩大边界且不能自批；超时、取消和重启不能放行；主聊天与侧边聊天状态独立；旧自动批准不会升级成完全访问。
