# Desktop Browser 二期：Developer mode 设计

> 状态：已按四类受控检查范围实现。用户能力与当前限制见 [Desktop 浏览器能力](../../browser-capabilities.md)。

## 目标与范围

在 Desktop 设置中提供默认关闭的 Developer mode。开启后，Agent 仍须就当前网页取得单独授权，才能检查 DOM、计算后的样式、控制台和网络请求。普通 `Browser` 的动作、站点授权及页面观察结果保持现状。没有 Desktop Browser 宿主的运行环境不获得此能力。

本期的“完整 CDP 检查能力”指覆盖上述四类排障信息，不等于向 Agent 开放任意 CDP 命令。任意命令可执行脚本、修改页面、读取 Cookie 或绕过输出限制，不能通过一个只用于“检查”的开关隐式授权。原始网络头、Cookie、请求正文和响应正文也不进入本期工具结果。

## 已有基础

- Server 的 `Browser` 工具只接受 `inspect`、`navigate`、`click`、`type`、`scroll`，经 `BrowserHost` 交给 Desktop 主进程执行。
- Desktop 主进程通过窗口已附着的 guest WebContents、标签页绑定和活动标签页检查确定目标；网页运行在独立持久分区的沙箱化 `<webview>` 中。
- 普通站点授权由 Browser 服务按 Agent 会话及 origin 记录。Server 权限中介会按工具名复用“本会话允许”，且子会话可继承父会话的普通权限；它不能直接充当 CDP 的站点级授权。
- Desktop 本地偏好已有读取、校验、保存和设置 IPC 通路，适合保存仅在 Desktop 生效的开关。

## 模块边界

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| Desktop 设置 | 展示开关、说明风险；将布尔值保存在本机偏好，默认 `false` | 授予某网站的调试权限；持有 CDP 数据 |
| Server 工具入口 | 暴露独立的 `BrowserDeveloper` 检查动作、校验参数、通过权限中介请求当次批准并格式化有限结果 | 持有 WebContents；直接发送 CDP 命令 |
| Desktop Browser 服务 | 核对开关、会话、活动标签页、网页 origin 和授权状态；管理调试采集的开始、读取、停止 | 接受 Agent 自选 CDP 方法；改变普通 `Browser` 的权限 |
| Desktop CDP 检查器 | 只附着已核对的 guest WebContents；执行固定的只读检查命令，过滤并限制输出，清理监听和缓冲 | 决定用户是否授权；跨标签页或跨会话共享缓冲 |
| 授权卡 | 对 `BrowserDeveloper` 显示站点或本地文件、检查类别、数据范围与风险，提供仅本次批准 | 从网页内容推断授权；把开关状态当作批准 |

检查器是 Browser 服务内部的小模块，不新建通用 CDP 传输框架。它只接收已经选定的 WebContents 和固定操作类型。设置值在主进程读取，Renderer 的开关状态不作为执行时的授权依据。

## 工具与执行流程

`BrowserDeveloper` 与普通 `Browser` 分开，避免扩大一期动作类型及模型已有的普通 Browser 授权。最小动作是 `inspect_dom`、`inspect_styles`、`start_diagnostics`、`read_diagnostics`、`stop_diagnostics`：

1. 先核对 Developer mode、当前活动标签页和页面 URL。若页面由用户手动打开，尚无当前 Agent 会话的普通站点授权，则先走现有 `requireOrigin` 流程请求该授权；被拒绝就结束，不发起 CDP 请求。`file:` 页面沿用工作区限制，但 CDP 检查还要解析真实路径，确认文件确实仍在工作区内，并在授权卡展示具体文件。普通授权之后才请求本次 CDP 授权。
2. 单次 DOM/样式检查：请求批准前记下 WebContents ID、标签页 ID、主框架地址和导航序号。批准后若这些信息有变化，立即作废；否则附着该 guest，读取、过滤并限制结果，输出前再核对一次。若同一会话正在采集诊断事件，则复用该 guest 的附着连接；否则检查结束即断开。样式检查即使在采集期间也需单独批准。
3. 控制台/网络排障：`start_diagnostics` 经同样检查与批准后才开启 `Runtime` 和 `Network` 事件，记录 Agent 会话、WebContents ID、标签页 ID、获批的主框架 origin（本地页为实际文件路径）、当前页面地址、导航序号和截止时间。用户或 Agent 随后可用普通 Browser 复现问题；`read_diagnostics` 只读这次采集的有限结果，无需重新批准，但每次都核对采集身份与当前导航序号；`stop_diagnostics` 立即清理。采集自动超时，且只能同时存在一个活动采集期；其他会话发起采集时返回占用错误。
4. 授权等待期间发生任何主框架导航，批准作废。已开始的诊断采集允许同 origin 重载（本地页只允许同一实际文件重载）：导航开始时暂停接收事件、清空旧文档事件与未完成请求，并递增导航序号；确认新主文档和默认执行上下文后才恢复采集，同时更新当前页面地址。读取只返回当前导航序号的数据，旧请求的迟到事件一律丢弃。跨 origin 导航或本地页转到另一文件一开始就停采并清空，不能等新页面加载完成。切换标签页、关闭开关、开始删除任一 Desktop 会话或关闭 Desktop 同样立即停采；一次只允许一个采集期，因此删除其他会话也会结束它。

普通 `Browser` 的站点授权不能代替 CDP 授权。权限中介对 `BrowserDeveloper` 增加“仅本次”规则：不查找或复用 session 批准，不把请求归到父会话；即使 API 收到 `decision: "session"`，也只按本次批准处理。现有权限卡只显示工具名，不显示 `reason`，因此须让 `BrowserDeveloper` 授权卡实际渲染经过校验的 `payload.reason` 和检查类别，并只提供“拒绝 / 允许本次”。提示应明确主页面站点、第三方子资源 URL 范围及可能暴露的内部数据；`file:` 页面显示具体文件。设置服务关闭开关时须直接通知 Browser 服务清理当前采集，不能只等下一次工具调用。

## CDP 与数据边界

- 主进程只选择已绑定的 guest WebContents，绝不附着主窗口、DevTools 页面或由 Agent 给出的任意 target/session ID。Agent 不能提交原始 CDP 方法、JavaScript 表达式、文件路径或调试端口。
- DOM/样式只检查主框架，使用固定读取命令和有上限的节点、属性、样式数量；不遍历嵌入框架。过滤密码、隐藏输入及明显凭据字段；输出仍按不可信网页内容处理。样式查询只针对本次 DOM 结果中的节点，不接受跨页面的裸 node ID。
- 控制台只接收主框架默认执行上下文的事件，保留有限条消息、级别、时间和经过处理的来源位置；嵌入框架的控制台内容不返回。网络仅接收由主框架发起的请求，包含它请求的第三方子资源，但不接收嵌入框架发起的请求；输出标出目标站点，并只保留方法、去掉凭据/查询参数/片段的 URL、资源类型、状态、失败原因和耗时。不读取或返回请求/响应头、Cookie、POST 数据、响应正文及 WebSocket 帧。
- 在事件进入缓冲前完成筛选和长度限制；缓冲只在主进程内存中存在，不写日志、附件库或本地文件。工具结果设置总字节上限并标记截断。网页可以把秘密写入 DOM 文本、路径或控制台自由文本，规则无法保证全部识别，授权提示不得声称“完全脱敏”。
- 采集器只接收其 WebContents 且符合上述主框架范围的事件；不自动附着子 target。跨 origin 导航、CDP 被 DevTools 抢占、命令超时或附着失败时清理并返回明确错误。所有异步读取完成后仍须复核授权状态和导航序号，避免把过期页面的结果发给 Agent。

## 参考代码的取舍

本地 `minimax-code/packages/browser-core` 提供有用的实现思路：有限事件缓冲、按主框架过滤控制台事件、网络请求与响应关联、URL 处理及导航时清理。这里仅参考设计，不移植该包或源码。它的 `startDOMListener` 会同时启用控制台与网络监听，且该包不管理本项目的设置和人工授权，直接接入会破坏“授权后才采集”的边界。Codex 官方 Browser 文档中“设置开关 + 网站检查前再批准”的交互可作产品参考，不作为本项目安全实现的替代。

## 验证重点

- 默认关闭、配置损坏回退关闭、关闭后立即拒绝新检查并清理活动采集；普通 Browser 动作继续工作。
- 普通站点授权、普通 `Browser` 权限、父会话权限和一次 CDP 批准均不能意外授权另一会话、另一站点或另一标签页。
- 用手动打开的页面和 `file:` 页面验证普通授权先行、真实路径仍在工作区内、授权卡展示具体目标与风险；模拟错误的 `decision: "session"`，确认 CDP 不复用、不继承。
- 授权等待、CDP 命令执行和输出前分别模拟切换标签页、同 origin 导航、跨 origin 导航、关闭开关及销毁 guest，确认没有越界输出。
- 控制台与网络采集只从批准后开始；同 origin 重载清空旧文档事件并继续采集，跨 origin 导航开始即停止；嵌入框架事件不返回，主框架的第三方子资源只返回受限元数据；缓冲、结果和生命周期都有上限。
- 用含 Cookie、Authorization、查询 token、密码字段及自由文本秘密的合成页面检查过滤行为，同时验证无法保证识别的内容已在授权提示中说明。

## 本期边界

“完整 CDP”按上述四类受控检查理解；如果需要任意 CDP 命令或原始网络数据，需要另行设计更高权限的授权和数据边界。
