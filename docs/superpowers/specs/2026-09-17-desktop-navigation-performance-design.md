# Desktop 页面切换性能收敛设计

## 背景

当前从对话页进入设置页时，`MainLayout` 会卸载并释放会话事件订阅；返回对话页后又重新订阅，并调用 `resyncActiveSessionSnapshot()` 拉取当前会话快照。与此同时，每个包含文件变更摘要的历史助手回复都会独立调用 `git.changes()`。一次 `git.changes()` 会执行三条 Git 命令，因此长对话重新挂载时可能产生大量重复子进程。

本次只处理两个已经确认的放大因素：

1. 页面切换导致会话事件订阅反复解绑、重连和同步。
2. 同一项目、同一查询范围的 Git 状态请求没有合并。

## 目标

- 主窗口从对话页切换到设置页，再返回对话页时，会话事件订阅保持不变。
- 设置页期间到达的会话更新继续写入现有 Zustand store。
- 返回对话页时不因为重新注册监听而额外执行完整会话快照同步。
- 同一项目、同一 scope 的并发 `git.changes()` 只触发一次 IPC。
- 文件变更摘要和 Review 工具共用同一个 Git 查询入口。
- 保持现有页面行为、数据格式和用户可见交互不变。

## 明确不做

以下内容不属于本次范围，即使实现过程中发现相关优化机会也不顺带处理：

- 不保活对话 DOM，不调整路由层级或设置页布局。
- 不实现消息虚拟列表、分段加载或历史消息缓存。
- 不修改 Markdown、代码高亮、Mermaid 或图片的渲染方式。
- 不重构 `ConversationPane` 的 Zustand selector。
- 不修改 daemon、服务端会话协议或 SSE 消息格式。
- 不改变 Git 命令内容，也不实现长期 Git 状态缓存或文件系统监听。
- 不处理与本问题无关的设置页 IPC 合并。

如果验证后仍存在明显卡顿，应作为后续独立任务重新取证，而不是扩大本次实现。

## 设计一：主窗口会话订阅常驻

### 入口

在根路由组件中增加一个无界面的 `DesktopSessionEventBridge`。它负责调用 `attachDesktopSessionEvents()`，并在自身真正卸载时执行返回的清理函数。

根路由同时承载主窗口和 `/pet` 桌面宠物窗口，因此 bridge 只在当前路径不是 `/pet` 时挂载。宠物窗口不初始化会话事件监听。

### 生命周期

流程如下：

1. 主窗口根路由挂载。
2. bridge 注册 daemon 状态、会话更新和附件上传监听。
3. 对话页与设置页之间切换时，根路由不卸载，bridge 保持挂载。
4. 设置页期间收到的事件照常通过现有 store action 写入状态。
5. 返回对话页时直接使用 store 中的最新状态，不重新注册监听，也不触发重挂恢复同步。
6. 主窗口关闭或根 React 树销毁时，bridge 统一释放监听。

`MainLayout` 中现有的订阅 effect 删除，避免同一职责分散在两个组件。

### 状态所有权

- bridge 只管理监听生命周期，不保存业务数据。
- 会话真相仍放在 `useDesktopSessionStore`。
- `attachDesktopSessionEvents()` 的引用计数和 `resyncActiveSessionSnapshot()` 恢复语义保持不变，以兼容测试或未来其他调用者；本次不重写订阅管理器。

### 错误与边界

- bridge 不吞掉现有订阅错误，也不增加新的重试策略。
- React StrictMode 开发环境下的挂载、清理、再挂载必须仍然只留下一个有效监听集合。
- `/pet` 不得调用 session 相关订阅 API。

## 设计二：项目级 Git 查询协调器

### 公共入口

新增 renderer 内部的 Git 查询协调器，提供类似以下接口：

```ts
queryGitChanges(input, { force?: boolean, maxAgeMs?: number })
```

缓存键由规范化后的 `rootPath` 和 `scope` 组成。不同项目或不同 scope 绝不共享结果。

### 合并规则

每个缓存项包含：

- 当前正在执行的 Promise；
- 最近一次成功结果；
- 成功结果的完成时间。

查询流程：

1. 相同键已有在途 Promise 时，所有调用者复用该 Promise。
2. 没有在途请求且成功结果仍在有效期内时，直接返回成功结果。
3. 默认有效期为 1000ms，只用于吸收同一批组件挂载产生的重复请求。
4. `force: true` 跳过成功结果缓存，但仍复用同一个已经在途的强制请求，避免刷新按钮连点制造并发子进程。
5. 请求成功后更新结果和完成时间。
6. 请求失败后删除在途状态，不缓存错误，下一次调用可以重试。

协调器不持久化数据，不写入 localStorage，页面刷新或应用重启后缓存自然消失。

### 调用方

- `ChangedFilesSummary` 改用共享查询入口。多个历史消息同时挂载时，它们拿到同一份 Promise 和结果。
- `ReviewTool` 改用同一入口。初次打开允许使用短期缓存；用户主动刷新时传 `force: true`。
- 两个调用方继续负责各自的 loading、error 和展示状态，本次不引入新的全局 Git UI store。

### 数据新鲜度

1000ms 有效期只合并瞬时重复请求，不作为业务缓存。超过有效期后，下一个调用会重新读取 Git 状态。Review 主动刷新始终绕过已完成结果，因此不会因为协调器而失去手动刷新能力。

## 测试

### 会话订阅

- 主窗口根路由挂载时注册一次监听。
- 对话路由切换到设置路由时不执行 detach。
- 从设置路由返回对话路由时不重新 attach，也不触发额外 resync。
- 根组件卸载时执行一次 detach。
- StrictMode 式挂载周期结束后只保留一套监听。
- `/pet` 路由不注册会话监听。

### Git 查询协调器

- 相同 rootPath 和 scope 的多个并发调用只调用一次 `window.desktop.git.changes()`。
- 不同 rootPath 分别查询。
- 不同 scope 分别查询。
- 有效期内复用成功结果，过期后重新查询。
- `force: true` 跳过已完成缓存。
- 多个并发强制刷新仍合并为一次请求。
- 失败不缓存，后续调用能够重试。

### 调用方回归

- 文件变更摘要仍显示正确的增删行数。
- Review 工具仍能加载、主动刷新和显示错误。
- 现有 desktop renderer 相关定向测试通过。

## 验收标准

- 对话页进入设置页再返回时，测试证明确实没有发生 session listener 重挂和恢复同步。
- 同一项目长对话中的多个文件变更摘要同时挂载时，测试证明只产生一次 Git IPC。
- Review 主动刷新仍能得到新结果。
- 未修改本设计“明确不做”中列出的模块和行为。

## 实施顺序

1. 先用测试锁定根路由订阅生命周期，再移动订阅入口。
2. 为 Git 查询协调器编写并发、过期、强制刷新和失败重试测试。
3. 实现协调器并接入文件变更摘要。
4. 接入 Review 工具，保留主动刷新语义。
5. 运行与改动范围对应的 renderer 定向测试和类型检查。
