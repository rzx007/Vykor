# 有限客户端 UI 扩展设计

> 状态：设计提案，待评审，尚未实现。本文固定推荐方向和接口边界，不代表现有插件已经支持这些能力。
> 日期：2026-10-28。
> 核对基线：Vykor `1c55cd15`；DeepSeek Harness `ddefc45fbc`。其他任务已有的工作区修改保持原样。

## 1. 目标与已确定需求

用户可以通过扩展定制客户端外观，也可以增加新的功能界面。扩展有明确的接入位置、数据与动作接口；在自己的区域内可以自由组织布局和交互。

已确定的需求：

- 起始页角色支持名称、图片、动画、静态封面，也支持自定义脚本渲染；作者可以接入其他头像库或效果库。
- 起始页角色与独立桌面宠物是两项功能。当前共用 AoraAvatar 只是实现复用，不构成共用配置、资源模型或生命周期的要求。
- 支持主窗口内跨页面常驻的浮动 UI，进入对话、起始页、插件页和设置页都可见。
- 支持会话视图、右侧面板、对应的工具按钮和扩展设置。
- 外观贡献可覆盖配色、现有字体选择与应用内品牌资源。
- 会话轨迹只是用于检验设计的例子，本提案不安排实现轨迹业务功能。

本次“全局”指客户端主窗口。独立桌面窗口、系统级悬浮和修改程序安装图标不在此次范围内。

## 2. 推荐方向与取舍

推荐增加客户端贡献清单，沿用 Native Plugin 的包身份、安装、启用和不可变代码快照。静态外观资源由宿主渲染；起始页代码型视觉扩展和功能界面在隔离 iframe 中运行，通过有限的 Desktop SDK 与宿主通信。

最小方案包括起始页视觉位置与全局浮动位置。起始页位置同时支持资源型和代码型渲染，浮动位置承载跨页面小组件；增加会话读取后，再扩展到会话视图和结果检查。

| 方向 | 优点 | 对本项目的主要代价 | 判断 |
| --- | --- | --- | --- |
| 直接向主界面加载第三方 React 模块 | 与内置组件接入方式接近 | 第三方代码接触宿主组件和状态，升级受内部结构影响 | 不采用 |
| 所有内容继续套进现有会话 Apps | 复用现有完整调用链 | 纯客户端小组件被迫依赖会话、后台与业务操作生命周期 | 保留给现有业务 Apps |
| 客户端贡献与有限 SDK，共用隔离页面基础 | 窗口与会话归属清楚，界面内部自由 | 新增贡献定义、有限桥接和客户端宿主 | 推荐 |

本设计不新增通用依赖注入容器、插件服务树、任意事件总线或另一套 Agent 执行系统。SDK 只是浏览器调用封装，放入现有插件包，不单独新增 npm 包。

### 与 MCP Apps 现行约定的关系

当前插件说明把活页面统一到 MCP Apps，现有 AppBridge 也明确不接收私有协议。新需求需要补充这条产品分类：业务 Apps 继续使用官方协议；客户端贡献使用自己的有限 Desktop 接口。新接口不装到现有 AppBridge 中，不恢复已退役的页面清单和协议。

这是需要在实施时同步修改插件说明的设计决定。两者共用文档隔离和资源校验，不混用执行身份、权限和生命周期。

本次核对的项目依赖是 ext-apps 1.1.2。它已有资源读取和列表变化通知，但没有直接提供本设计所需的客户端会话状态订阅。不能把列表变化通知当作每个 token 的数据推送，也不应把本地配置操作伪装成模型工具执行。

## 3. 借鉴哪些现成机制

| 参考 | 采用的部分 | 不直接复制的部分 |
| --- | --- | --- |
| DeepSeek Harness | 具名界面位置、接口可查询、新增和替换明确区分、注册可清理 | Cordis 服务组合、全应用可替换、主页面中执行第三方组件 |
| VS Code | 清单声明视图和菜单入口，复杂内容使用隔离页面，通过消息调用宿主 | 完整 Extension Host、任意命令注册和条件表达式语言 |
| 当前 Vykor MCP Apps | 离线 HTML、真实 frame 身份校验、主题同步、导航限制和清理经验 | 会话 App 记录、工具 lease、发送模型消息与业务执行回执 |

现有 `PluginAppDocumentStore` 包含会话身份、页面限额与 App 生命周期，不能直接把会话字段改成可选来承载新需求。实施时只提取文档字节、frame 绑定和请求策略这些共用部分；原 App 策略继续由原适配器负责。

## 4. 整体运行流程与负责人

```text
Native Plugin 安装记录及不可变资源
              |
    Server 插件应用服务：校验并提供客户端贡献
              |
       VykorClient.plugins 资源接口
              |
Desktop Main：目录、版本、资源、授权、视图绑定、持久偏好
              |
    主窗口根部的客户端扩展宿主
       /          |           \
外观资源渲染   页面接入位置   全局浮动外框
                  |            |
               隔离 iframe + Desktop SDK
                  |
       明确的数据查询、订阅与界面动作
```

| 状态 | 唯一负责人 |
| --- | --- |
| 插件身份、版本、启用、包权限和资源快照 | 现有插件安装记录与校验模块 |
| 当前连接下可用的客户端贡献 | Server 插件应用服务；Main 缓存读取结果 |
| 挂载身份、资源来源、能力批准和连接代次 | Desktop Main |
| 页面入口、浮窗位置、当前标签与可见性 | 主窗口扩展宿主 |
| 会话、运行、消息与工具事实 | 现有 daemon 与 Client 同步流程 |
| 扩展的筛选、缩放、表单草稿 | 扩展视图自身；需要保留时写入限定的视图状态 |
| 持久扩展偏好、浮窗布局和起始页视觉选择 | Desktop Main 的客户端配置文件；不读写独立宠物偏好 |

扩展不另存一份权威会话历史。Main 通过现有会话订阅服务或 Client Resource 读取获准内容，不允许页面指定任意 daemon 地址、认证凭据或本机路径。

Desktop 通过 Client 获取资源并核对摘要，不把安装记录中的绝对路径交给页面，也不假定包路径可在渲染环境读取。该设计不新增远程连接功能。

## 5. 包与客户端贡献清单

沿用 `.vykor-plugin/plugin.json`，拟新增 `components.desktop` 指向一份客户端贡献文件。一个插件最多声明一份此文件，减少重复定义与顺序问题。Native 根清单仍采用已有格式，客户端贡献文件独立使用版本 1。

纯界面插件无需声明 Node Tool、MCP Server 或 Node 运行引擎。一个包也可以同时携带客户端贡献与现有 Apps，两类声明分别校验。

### 贡献文件中的内容

| 字段 | 内容与约束 |
| --- | --- |
| `schemaVersion` | 客户端贡献格式版本，首版为 1 |
| `views` | 具名功能视图；每项声明标识、标题、入口、展示位置和数据范围 |
| `actions` | 宿主绘制的按钮；声明标识、标题、宿主图标、位置和目标视图 |
| `startVisuals` | 起始页视觉候选项；包含名称、可选封面，及资源型或渲染器型定义 |
| `themes` | 主题名称、浅色和深色变量、现有字体选项 |
| `branding` | 可供用户选择的应用内名称和图片标志 |
| `settings` | 扩展自己的布尔、文本、数字、枚举设置；复杂设置可声明设置视图 |

视图入口是构建好的单文件 HTML，脚本、样式和图片嵌入文件，不引入运行时构建、CDN 或远程脚本。头像库和效果库可作为构建依赖打包到代码型起始页视图中。品牌、主题与资源型起始页形象作为结构化资源读取，不执行脚本。

`startVisuals` 的 `kind` 分为 `asset` 和 `renderer`。前者声明图片或动画及可选封面，后者引用本插件一个展示位置为 `start.visual` 的视图 ID。两类使用同一个选择列表，不要求渲染器再伪装成动画文件。

视图声明的必要信息：

| 信息 | 设计约定 |
| --- | --- |
| 身份 | 插件内唯一的 `id`，完整身份由宿主组合插件 ID 与贡献 ID |
| 位置 | 一个固定位置：起始页视觉、会话标签、工具面板、全局浮动或扩展设置 |
| 数据归属 | `session` 或 `window`；会话标签必须归属 session，起始页视觉采用 window |
| 显示生命周期 | 由位置决定；window 数据范围不代表跨页面常驻 |
| 能力 | 此视图需要的数据能力和允许使用的宿主动作 |
| 视图状态版本 | 保存筛选、草稿等数据时使用；不兼容版本不自动猜测转换 |
| 初始大小 | 浮动视图可以提供建议值，实际范围由宿主窗口决定 |

入口、图片和封面都必须留在插件包内。继续使用现有路径真实位置校验和内容摘要；清单中不保存批准结果、实例 ID 或用户布局。

未知位置、重复 ID、资源缺失、能力未声明和版本不支持都返回明确诊断。其他已有效的插件能力按现有组件降级规则处理。

## 6. 首批接入位置

下列名字是拟采用的公开位置名，尚不是已实现接口。

| 位置 | 内容 | 规则 |
| --- | --- | --- |
| `start.visual` | 起始页视觉内容 | 用户选中一个资源或渲染器；可隐藏，始终有内置默认项 |
| `appearance.theme` | 颜色与现有字体选项 | 用户选中一个主题；个人颜色覆盖优先 |
| `shell.brand` | 应用内名称和标志 | 用户显式选择，不影响程序名称、安装图标和签名 |
| `conversation.view` | 对话并列视图 | 新增标签，不能以相同 ID 替换内置对话 |
| `tools.panel` | 右侧补充视图 | 独立标签，复用现有面板打开和关闭交互 |
| `shell.floating` | 跨页面浮动视图 | 主窗口根部常驻，由用户明确打开或恢复 |
| `conversation.header.actions` | 会话头部按钮 | 原生按钮，指向本插件已声明视图 |
| `composer.actions` | 输入区按钮 | 原生按钮，指向本插件视图；不替换输入框和提交动作 |
| `settings.extension` | 扩展偏好或设置视图 | 位于扩展设置分组，不插入权限审批等核心设置 |

首版不开放已有 cell 的优先级遮蔽。唯一位置由用户选择，列表位置只接受新贡献。菜单过长时由宿主折叠到扩展菜单，不允许扩展自行调整其他按钮。

侧栏独立页面入口、消息动作和专用工具结果呈现保留为按需增加的位置，不作为本轮基础机制的前置条件。

## 7. Desktop SDK：只开放具体用途

SDK 拟通过现有插件包增加浏览器子入口，供作者构建到离线 HTML 中。它不包含 Node 实现、不导出 VykorClient、不保存第二套服务端状态。

| 接口组 | 提供什么 | 限制 |
| --- | --- | --- |
| `host.describe` | 可用位置、方法、参数、SDK 版本和当前批准能力 | 返回说明，不执行操作 |
| `context.read/subscribe` | 主题、减少动态效果、页面类别、允许的项目与会话上下文 | 不包含凭据、系统提示词和任意本机路径 |
| `surface.read/subscribe` | 当前区域尺寸、像素比例、可见性、稳定 seed 与必要的指针信息 | 仅提供该视觉位置所需输入，不暴露宿主 DOM 或键盘内容 |
| `session.readSummary` | 当前绑定会话的运行状态、计数和摘要 | 需要会话摘要读取能力 |
| `session.readMessages` | 分页读取用户可见消息 | 需要正文读取能力；默认 50 条，每次最多 100 条 |
| `session.readTool` | 精确工具记录的获准详情 | 必须属于绑定会话；正文能力覆盖输入和输出 |
| `session.subscribe` | 通知已绑定内容发生变化，附游标 | 不向每个视图再建立独立的 daemon SSE |
| `view.open/close` | 打开自己的声明视图，或关闭自身 | 不能自由传宿主路由或其他插件身份 |
| `navigation.revealMessage` | 定位绑定会话的一条消息 | 校验记录归属，不能指定任意会话 |
| `composer.insert` | 将文本交给宿主预览，由用户选择插入草稿 | 不发送 Prompt，不直接覆盖当前草稿 |
| `state.read/write` | 自己的视图状态与声明设置 | 按插件、视图与作用域隔离，不作为密钥存储 |

拟在根清单的 `permissions.desktop` 中增加有限能力名，沿用安装预览和批准记录。单个视图只能使用自己声明、且安装已批准的能力子集。显示位置不会扩大数据权限。

起始页视觉默认只获得区域输入、主题和自身配置，资源型与代码型都不需要会话读取权限。主题资源与无会话数据的小组件也不申请会话读取权限。扩展不能通过此 SDK 调用任意 Tool、Shell、文件 API 或批准权限。

需要业务工具的功能继续通过现有 Apps 和执行链路完成。客户端视图可以请求用户打开已声明的业务 App 入口；工具执行身份仍由原 App 流程决定，不从 SDK 请求中直接拼装。

### 查询、订阅与切换会话

会话视图在打开时固定原会话，离开后隐藏，返回时复用原实例。全局浮动视图归属窗口，可选择无会话数据，或跟随当前活动会话；在没有活动会话的页面，上下文明确返回空。

Main 为上下文分配代次。切换会话时结束旧数据订阅，发送新的上下文；旧代次的查询结果不能进入新视图。页面不能仅靠提交一个 session ID 获取其他会话。

主题和上下文变化及时通知。消息和工具变化按短时间窗口合并为失效通知，视图按游标补读；首版合并窗口为 200 毫秒，避免每个 token 都复制完整消息树。

首次读取使用现有 snapshot 和 cursor，后续跟随现有 Client 更新。大量正文按页读取，不把完整历史复制到每个浮窗。读取工具详情也按需发起。

## 8. 隔离页面与通信

第三方 HTML 使用 `sandbox="allow-scripts"` 的 iframe，禁止获得宿主同源身份、Electron preload、Node 和任意网络访问。继续使用已核对文档摘要和实际 frame 身份的文档服务。

SDK 与宿主使用独立 MessagePort。宿主核对初始消息来源和一次性绑定后交付通道；不复用现有 AppBridge，不注册另一套全局窗口消息总线。

每条消息只有协议版本、请求标识、方法与有限 JSON 参数。宿主绑定保存窗口、连接、插件版本、贡献 ID、能力和会话上下文；页面传入的身份不具有授权作用。

Main 只接受主窗口 mainFrame 发起的有限 IPC，并以宿主保存的挂载绑定复验请求。实际的会话数据与调用结果再经 Client 和原有服务取得。

SDK 统一处理请求应答、取消、上下文代次和关闭通知。它不实现自动业务重试、自己的运行日志或持久执行状态机。

隔离 iframe 限制 DOM 和能力访问，但不承诺能消除第三方 JavaScript 对渲染性能的全部影响。页面按需启动，隐藏时停止数据推送。现有 Apps 与新增视图共享每个主窗口 8 个页面的容量；文档继续使用已有 16 MiB 上限。新增视图达到限额时返回明确提示，不关闭用户已有页面。

## 9. 全局浮动 UI 的具体行为

浮动宿主挂在主窗口根部，与路由的 Outlet 并列。不能放在仅对话页生效的布局中；同一个根路由也承载宠物窗口，因此必须显式限定主窗口。

浮动外框由宿主提供拖动区、调整大小、收起和关闭。扩展只绘制框内内容。空白覆盖层不接收鼠标，打开浮窗默认不抢焦点。

| 用户动作或状态 | 结果 |
| --- | --- |
| 打开浮动视图 | 创建一个实例；重复打开定位已有实例 |
| 切换页面 | 实例保留，草稿和本地交互状态保持 |
| 收起 | 保留实例与状态，暂停会话数据订阅 |
| 展开 | 取得最新快照后恢复订阅 |
| 关闭 | 结束订阅与通道并移除 iframe，保留明确保存的偏好 |
| 窗口变小 | 把浮窗限制在可见范围内 |
| 应用重启 | 只恢复用户上次允许保持打开的浮窗 |
| 插件停用或卸载 | 移除入口与全部实例，已保存偏好保留 |
| 连接切换 | 原连接的数据访问立即停止，按新连接重新核对贡献目录 |

浮窗在普通页面之上，宿主菜单、权限确认和关键错误提示在浮窗之上。视觉样式、快捷键和减少动态效果遵循现有 Desktop 设计规则。

布局以客户端用户配置保存，键包含插件来源、插件身份和贡献 ID。本机来源键由 Main 按当前运行数据位置生成并持久化，不使用变化的端口或认证 token。切换数据位置不会复用另一份安装的私有状态。窗口实例 ID 只用于运行绑定，不作为跨重启偏好身份。

计时器这类无会话数据的组件可在后台短暂断线时保留本地交互。数据视图明确显示断线，禁止把缓存内容当作新结果。

## 10. 起始页视觉扩展的具体设计

### 与独立桌面宠物分开

起始页角色属于新对话页面的视觉区域。独立桌面宠物属于另一个窗口，拥有自己的选择、动作和窗口生命周期。当前两处都调用 AoraAvatar，并不要求未来继续使用同一个实现。

本方案只修改起始页的扩展接入方式。起始页选择、seed、配置与持久状态独立保存，不读取或修改独立宠物的偏好。也不把起始页代码自动加载到宠物窗口或全局浮窗。

### 资源型和代码型并列支持

| 形式 | 作者提供什么 | 谁负责绘制 |
| --- | --- | --- |
| `asset` | 名称、PNG/WebP 图片或 GIF/动画 WebP，可选静态封面 | 宿主资源适配器 |
| `renderer` | 名称、渲染视图 ID、可选封面和配置；视图包含脚本与所用库 | 隔离页面中的作者逻辑 |
| 内置默认 | 当前 AoraAvatar 及默认参数 | 应用自带适配器，不作为第三方代码执行 |

代码型扩展可以输出 SVG、Canvas 或 WebGL 视觉内容，使用自己选取的头像库或效果库。库、脚本和依赖随插件构建产物交付，不要求作者遵循 Aora 的形状、表情或动画接口。

因此这项能力既能显示一个角色，也能显示抽象动画或其他起始页视觉效果。宿主不规定角色必须有什么部位、表情和动作。

### 资源型导入

1. 用户在设置的起始页视觉选择中导入图片或动画。
2. Main 校验文件类型与解码结果，沿用已有 sharp 生成静态 PNG 封面。
3. 把资源和封面复制到独立的起始页资源目录，以内容摘要命名。
4. 资源保存成功后，登记 asset 候选并更新选择。

文件后续移动不影响已经复制的资源。失败时保留原选择，不留下半完成的当前项。

### 代码型安装与初始化

1. 用户安装包含 renderer 候选的普通客户端扩展包。
2. 安装校验资源、版本与所需能力，并把它登记到同一个起始页选择列表。
3. 起始页显示且用户选中该候选时，在 `start.visual` 区域启动对应的隔离视图。
4. SDK 提供区域尺寸、像素比例、稳定 seed、用户配置、主题和减少动态效果偏好。
5. 作者在自己的文档内初始化头像或效果库，绘制并处理局部交互。

资源型直接导入与代码型插件安装是不同入口，不直接加载用户选择的任意脚本文件。代码型复用普通视图的加载、版本固定和有限 SDK，不新增一种脚本引擎。

### 渲染和交互的归属

| 内容 | 负责人 |
| --- | --- |
| 占位区域、实际大小、裁剪和页面排版 | 起始页宿主 |
| 角色生成、绘制、表情、动画与局部点击悬停反应 | 渲染器作者 |
| 当前主题、区域可见性、减少动态效果通知 | 宿主通过 SDK 提供 |
| 自己的随机种子与用户配置 | 起始页偏好；作者不依赖 Aora 的 name 参数 |
| 动画帧、定时器、监听器和图形资源 | 渲染器创建，离开或替换时清理 |

指针交互默认只覆盖区域内。确需跟随主页面鼠标时，宿主可以提供相对区域归一化的指针坐标；不开放任意页面事件、键盘内容或宿主元素引用。

起始页渲染器只在其区域显示时运行。离开起始页、隐藏该区域、切换候选或停用插件时，结束旧实例并释放 iframe、动画帧、定时器与图形资源。它不会因为数据归属为 window 而变成跨页面常驻视图。

主窗口暂时隐藏时通知 renderer 暂停；资源型改用封面。减少动态效果开启时，renderer 可自行绘制静态效果；未提供该能力时，宿主显示其封面或内置静态默认。静态封面对 renderer 为可选，不能假定 sharp 能把脚本逻辑转成封面。

选择模式为内置默认、选定候选或隐藏。候选选择、seed 和明确保存的配置跨重启保留。运行故障显示封面或内置默认，并保留错误诊断，禁止无限重启。

## 11. 主题、按钮与设置

主题只接受宿主公布的变量名和有效颜色值，以及现有字体选项；不接收任意 CSS 选择器。最终效果按内置基础、用户选中的主题、用户个人覆盖依次计算。停用所选主题后恢复内置基础与个人覆盖。

应用内品牌与起始页视觉都是单选贡献，不采用插件优先级竞争。安装只增加候选项，不自动替换用户的当前选择。

工具栏按钮由宿主渲染，标题、图标和顺序来自清单；动作只定位本插件声明的界面。这样安装后即可发现入口，不必先启动一份脚本注册按钮。

设置分为宿主绘制的简单字段与独立设置视图。字段仅支持已有输入控件可表达的类型，不引入通用 JSON UI 语言。视图自身状态、全局扩展偏好和会话业务记录分别存放。

## 12. 安装、加载、更新与停用

### 新增服务端读取入口

拟在 `VykorClient.plugins` 增加客户端贡献目录和精确资源读取。服务端由现有插件应用服务校验 installed record、当前版本、内容摘要与批准能力后返回；不创建 Agent，不激活插件 Node 代码。

| 拟新增读取入口 | 参数和返回内容 |
| --- | --- |
| `plugins.desktopCatalog()`，对应 `GET /plugins/desktop` | 返回已核对的贡献描述、scope、版本、内容摘要、资源目录、所需能力和诊断 |
| `plugins.desktopResource()`，对应 `GET /plugins/:id/desktop/resources/:resourceId` | 要求 scope 和期望内容摘要；返回精确资源字节、MIME 和 SHA-256 |

已批准能力不由目录字段自行授予。Main 挂载前仍取得安装验证结果，绑定使用已批准的实际子集。资源只按已声明 resourceId 读取，不接受页面提交相对文件路径。

目录返回可公开描述、资源 ID 和摘要，不返回绝对安装路径。资源读取必须带已核对摘要；服务端拒绝已撤销或身份不匹配的资源。Desktop 缓存字节只是副本，不成为安装状态的权威来源。

这些请求属于新的公开通信能力。实施时按仓库既有规则同步更新 Client、Server 与协议版本，不增加旧 daemon 兼容分支；客户端 SDK 自身使用独立的接口版本握手。

客户端偏好保存于 Main 管理的独立 JSON 文件，原子替换后再通知界面；保存失败不先显示成功。每个插件的持久视图状态上限为 256 KiB，超出时返回错误，不静默截断。这里不保存密钥，也不创建数据库迁移。

### 客户端加载

客户端连接就绪后读取贡献目录。元数据注册入口与候选资源，HTML 直到视图首次打开才获取和运行；浮动视图只有用户明确打开或允许恢复时创建。

贡献可见性与安装批准有关，与当前 Prompt 的手动 @插件选择无关。是否允许某次 Agent 使用插件工具，继续由原运行能力范围决定。

### 开发者与 Agent 怎样生成扩展

复用插件页现有快速创建入口，增加浮动小组件、会话只读视图、起始页图片资源和起始页脚本渲染模板。模板携带 SDK 声明、构建方式和位置说明，使用现有校验与安装命令，不增加独立脚手架工具。

插件开发 Skill 说明清单和 SDK，Agent 用普通文件工具生成资源包，再通过现有 PluginInstall 安装归档。SDK 的 `host.describe` 用于页面内诊断与精确能力查询；静态作者文档从同一份接口定义生成，避免两份手抄 API。

安装与显示分别报告。导入成功不能代表浮窗已打开；实际打开失败应返回阶段和诊断。原型验收使用真实宿主，不用独立 HTML 模拟客户端。

### 更新

包安装仍使用现有完整性检查和原子发布。已打开的视图固定原版本；新安装版本不热替换 iframe。用户显式重载时，提示未保存草稿并关闭旧实例，再从新版本创建。

权限增加沿用现有安装预览。新增权限不能在旧视图中立即获得。插件停用、卸载或权限撤回立即终止对应数据与动作访问。

关闭视图和停用贡献不撤销已完成的业务操作。客户端 SDK 首版本身不提供业务副作用重试。

## 14. 独立可交付的实施顺序

### 第一批：资源贡献与全局浮动视图

完成清单、校验、目录与资源读取、Main 绑定、隔离页面和有限 SDK 基础。第一批同时交付起始页资源型与代码型视觉扩展，以及用户可打开、移动、收起的全局浮动视图。

基础 SDK 先提供接口说明、窗口上下文、区域输入、主题、视图打开关闭和自身状态保存，不提供会话正文。参考扩展采用本地计时器或便签；另用一个使用非 Aora 库或效果逻辑的起始页 renderer 验证可替换性，不用真实模型或外部账号。

这批完成后即可独立使用，不依赖会话分析功能。主题与品牌资源按同一贡献读取机制接入。

### 第二批：会话数据与功能视图

接入会话摘要、消息分页、工具详情与更新通知，开放会话标签、工具面板、对应按钮和扩展设置。使用一个只读记录列表验证数据、导航和会话切换，不实现完整轨迹产品。

需要业务工具的现有 Apps 保持可用。客户端扩展 SDK 不增加直接工具执行旁路。

## 15. 验收与失败处理

| 范围 | 必须证明的行为 |
| --- | --- |
| 清单和资源 | 有效资源可读；重复 ID、未知位置、越界路径、错摘要和不支持版本明确失败 |
| 安装权限 | 预览显示真实读取范围；未批准正文权限不能读取消息或工具正文 |
| 页面隔离 | 无 Node、无任意 IPC、无宿主 DOM；伪造插件、窗口、会话或旧绑定不能扩大能力 |
| 生命周期 | 切路由不重建浮窗；收起停止数据订阅；关闭释放 frame、通道和订阅 |
| 会话切换 | 旧响应不进入新会话，分页与游标不串线，无活动会话时返回空上下文 |
| 数据体量 | 长会话按页读取，多个扩展复用上游订阅，不重复拷贝全部历史 |
| 断线和连接切换 | 保留草稿，停止旧连接访问，不把同名插件或会话当作同一身份 |
| 起始页资源型视觉 | 图片和动画真实可读，静态封面可用，选择跨重启保留，移动源文件后正常显示 |
| 起始页代码型视觉 | 非 Aora 实现可运行；尺寸、主题与减少动态效果输入正确；替换和离开后释放图形资源 |
| 功能独立 | 修改起始页选择和配置，不改变独立宠物窗口、偏好、交互或实例 |
| 浮窗交互 | 各主页面常驻，位置可恢复，窗口缩小时可找回，不挡宿主确认框 |
| 更新和停用 | 更新不暗换活动代码；停用立即撤入口和能力；其他插件不受影响 |
| 原 Apps 回归 | 官方 AppBridge、现有工具权限、iframe 来源及草稿关闭规则保持正确 |

实现时运行受影响包类型检查、对应单元测试与真实 Electron 行为测试，覆盖生产 Main、preload、隔离 iframe 和客户端 SDK。无需截图或模型 API 调用。

文档与目录变化运行 `pnpm check-docs` 和 `pnpm check:retired-ui`；基础代码变更按范围运行 `pnpm check:architecture`。不把一次全量测试作为每个小步骤的固定前置。

错误只重试无副作用的读取；关闭与写配置失败要保留原视图或原选择，并显示真实结果。页面异常允许用户关闭或重开，不无限自动重启。

退出本方案可停用全部客户端贡献，保留现有对话与 Apps。资源和客户端偏好独立于会话数据库，无需修改或回滚会话数据。

## 16. 风险、前提与调研范围

最关键的前提是：有限的读取与界面动作足以覆盖主要客户端定制。如果具体扩展必须执行本机任务，应接入原有 Tool 或 Apps 能力；不在 SDK 中补一个任意执行入口。

主要成本是可维护的公开接口，而不是拖动浮窗。需要给每个位置和方法维护参数、数据范围、失败行为及版本说明，并提供可查询的目录。

基础机制、资源导入和独立小组件不要求新账号、API Key、外部服务或额外的宿主依赖。代码型起始页扩展可携带自己选取的浏览器库。sharp 只处理图片和动画的封面；资源协议与隔离能力来自现有 Electron 实现。

现有说明把旧 Native UI 退役。本提案不复用其字段和历史记录；新增客户端贡献需要清楚标注与 MCP Apps 的分工，并持续通过退役检查。

本次没有运行扩展原型、替换客户端页面或执行第三方插件代码。现有工作区包含其他任务修改，本次只新增本设计及其文档入口。
