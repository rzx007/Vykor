# Codex 风格 Markdown 输出与正文排版设计

## 目标

让 VK 的助手回答更接近 Codex 的阅读体验：先把内容写得紧凑、层次清楚，再由桌面端稳定地渲染。实现只修改 VK 自有提示词和界面，不修改任何第三方技能，也不在模型输出完成后重写 Markdown。

## 已确认的原则

- 输出结构和视觉样式必须一起优化；只改 CSS 无法修复冗长、重复链接或不合适的大表格。
- 通用规则进入 VK 系统提示词，不把 AI 新闻专用结构写成全局规则。
- 用户明确要求的格式、项目规则和技能的任务要求仍然优先。
- 规则必须是独立模块；系统提示词只有一个明确调用点，移除或注释该调用即可关闭。
- 桌面端样式只负责展示，不猜测或改写内容含义。

## 方案选择

### 采用：独立输出规范 + 对话正文样式

在 `@vykor/prompts` 中增加一个纯函数，返回通用 Markdown 表达规范。`buildTaggedPromptSegments` 在稳定系统层加入这一段。桌面端继续使用 Streamdown，只覆盖对话正文的宽度、标题、列表、引用块、段落和链接样式。

这种方式与 Codex 的公开实现方向一致：模型提示词约束最终回答的结构，客户端负责解析和显示 Markdown。规则对所有普通回答和技能回答生效，但不包含“新闻必须选 10 条”等领域要求。

### 不采用：只在技能结果后追加规范

影响范围较小，但普通回答仍然松散，并且每次技能调用都重复注入相同文字。它也会让第三方技能内容与 VK 规则在较低层级混合，不利于诊断。

### 不采用：输出后自动整理 Markdown

字符串后处理可能破坏代码块、表格、链接和用户要求的原始格式，也无法可靠判断哪些段落应该合并。

## 模型输出规范

新增 `buildMarkdownPresentationSection()`，输出一段短而稳定的英文系统规则，表达以下行为：

- 先说结论，再补必要解释。
- 简单回答优先使用短段落，不默认添加标题或列表。
- 只有并列事项、步骤、选项和比较适合使用列表或表格。
- 复杂回答最多使用少量主要区块，避免把每个小点拆成标题。
- 列表保持扁平；可以合并的相关信息放在同一项中。
- 表格只用于字段重复且便于横向比较的数据；长叙述改用正文或列表。
- 使用有意义的链接文字，不把很长的 URL 单独放成一段。
- 不为每个条目额外增加引用块；引用块只用于真正需要整体强调的说明。
- 用户指定输出结构时遵循用户要求；技能明确要求交付格式时保留该格式。

这段规则放在稳定层，位于基础行为规则之后、运行模式之前。入口保持单一：

```ts
pushSegment(segments, "stable", "system", buildMarkdownPresentationSection());
```

注释或移除这一行即可完全关闭该规范，不需要修改其他模块。

## 正文排版

桌面端对话正文采用以下调整：

- 消息正文最大宽度从当前约 760px 提升到约 960px；输入框宽度保持不变，避免编辑区过宽。
- 一级标题用于回答主标题，二级和三级标题减少上下留白，避免内容被切成很多大块。
- 列表项覆盖 Streamdown 默认纵向 padding；连续列表保持紧凑但仍可辨认。
- 引用块减少上下 margin 和内部 padding，保留左侧边线和弱化文字色。
- 连续段落间距保持半个标准间距；正文行高维持适合中文阅读的范围。
- 普通网页链接使用主题强调色并保留下划线反馈；长链接允许安全换行。
- 表格继续使用现有紧凑样式，宽度不足时仅表格数据区横向滚动。

这些规则限定在助手消息容器，不改变 Markdown 文件预览器，避免预览文件时偏离原文档版式。

## 运行流程

1. 会话创建系统提示词时，`buildTaggedPromptSegments` 加入 Markdown 表达规范。
2. 模型读取用户要求、项目规则和技能内容后，按规范选择段落、列表或表格。
3. 模型返回原始 Markdown；VK 不做内容后处理。
4. `AssistantMessage` 把 Markdown 交给 Streamdown。
5. 对话专用 CSS 控制正文宽度和各 Markdown 元素间距，最终显示给用户。

## 冲突与边界

- 用户要求“输出完整表格”时，不把表格自动改成列表。
- 技能明确规定交付格式时，保留必要字段；通用规范只减少不必要的包装。
- 代码块、Mermaid、工具轨迹和附件展示不在本次范围内。
- 不新增设置页开关，不改变现有 `outputStyle` 的含义。当前 `outputStyle` 是终端渲染模式，把它改成提示词开关会造成职责混淆。
- 不加入 AI 新闻专用数量、分类或点评口吻，这些仍由技能和用户请求决定。

## 测试

- 提示词单元测试确认默认系统提示词包含 Markdown 表达规范。
- 提示词单元测试确认关闭选项后不包含该规范。
- 提示词分层测试确认该规范进入稳定 `system` 分段，不进入技能或用户规则分段。
- 桌面样式回归测试确认对话正文宽度、列表间距、引用块间距和链接换行规则存在。
- 运行 prompts 包测试、Desktop 相关测试、格式检查和全仓类型检查。

## 验收标准

- 普通简短回答不再自动堆叠标题和列表。
- 新闻或资料汇总优先使用分组短列表，链接以标题承载，不单独铺陈长 URL。
- 必须横向比较的数据仍可使用紧凑表格。
- 同一份结构化 Markdown 在 VK 中不再因窄正文、列表 padding 或引用块 margin 产生明显的纵向膨胀。
- 第三方技能目录没有任何修改。
- 删除单一提示词装配调用后，模型输出规范可以被完整关闭。
