# 子代理结果交付边界规范

> 状态：根据两名子代理的独立审核修订。本文澄清现有机制的职责与数据用途；不要求新增通用投影器或结果交付生命周期。

## 目标与前提

制定规范，允许任务选择交付内容。普通 Agent、Workflow worker 与自动评审都需要把工作成果交给调用者；完整的最终报告可以是合法的交付结果。自动评审的 finding 正文进入父 Task，本身不等于越权或泄漏。

本阶段的父子会话位于同一授权工作范围。子会话拥有独立上下文，减少父代理承受的过程信息；这不构成父代理无权查看子会话内容的保密承诺。现有 JobRead 活动查询、部分结果和诊断入口允许在验证父子归属后读取相应内容。

原设计把“观测记录只含摘要”扩大成“父代理不能收到评审正文”，再为这一限制引入宿主投影回调、持久化策略标识与延迟 Task 结算。本次审核撤回这组新增机制，先准确规定现有数据的职责。

## 三类数据

| 数据 | 含义与存放位置 | 可见规则 |
| --- | --- | --- |
| 子代理工作记录 | Child Session 的任务输入、模型消息、工具调用与运行记录 | 独立保存；不自动拼接到父模型上下文或统计记录；授权诊断与活动查询沿用现有接口 |
| 任务交付结果 | AgentChildResult、父 Task 的最终输出以及现有结果通知 | 可以包含详细结论、相对文件位置、证据与未完成部分；由任务明确要求交付什么，不默认压成计数 |
| 运行与质量摘要 | 父 Run 的 autoReview metadata、session.auto_review.updated、Execution Observation | 仅保留状态、数量、严重级别、耗时、引用等有界字段；不复制报告或原始输入正文 |

父 Task 与 `agent.child.closed` 属于现有结果交付渠道，不是统计摘要渠道。它们可以包含同一份最终结果。框架不得为了交付结果，另行复制全部输入 patch、子会话历史或工具日志到父侧。

“不自动复制工作记录”是传输规则，不是内容脱敏保证：模型最终报告可能引用输入中的代码，字段名叫 `summary` 或通过 JSON 校验均不证明内容已脱敏。

## 模块职责

- **Core：**维护共享设置和通用运行类型，不判断代码风险、不解析评审正文，也不决定所有任务能交付哪些内容。
- **Agent Runtime：**负责子代理创建、能力限制、预算、中止、结果返回和关闭错误传播；普通委派继续沿用现有生命周期。它不依赖 Server 的评审解析器。
- **Server 自动评审：**选择内置 reviewer、提供任务要求与输出结构，校验最终报告，并维护权威的评审质量状态。是否需要摘要或详细报告，由任务契约说明。
- **Server 会话投影与恢复：**持久化和恢复运行事实、Task 结果及失败信息；不能依据事件名称或模型文本推断“评审通过”。
- **Protocol 与观测读取方：**定义并校验共享的评审状态结构；默认观测输出保持有界，不承担报告全文分发。

首版复用 `expectedResult`、现有结果 schema、`AgentChildResult` 和 Task/Child Session 引用。只有出现这些接口无法表达的具体需求，才增加宿主内部接口；不预设投影器注册中心、策略版本库或 `full/summary/private` 配置矩阵。

## 自动评审的当前契约

reviewer 继续提交现有有界 JSON：`verdict`、`summary`、`findings`；finding 包含严重级别、标题、相对文件位置和证据。`parseAutoReviewResult` 校验格式、长度、枚举及文件范围，Server 据此生成评审状态与计数。

Task 的输出是模型提交的最终结果，可能是有效报告，也可能是不合法响应；保存它不表示系统已采信。父代理和用户可以通过现有授权 Task/Child Session 入口读取报告正文，应用判断是否通过时读取父 Run 的 `autoReview.status`。

自动评审输入的 Git 归因、敏感路径检查和执行权限继续由既有入口执行。严格只读由工具、插件、MCP 与 hook 的执行约束保证；结果可见范围不改变执行权限。

## 完成、质量与关闭的区别

| 事实 | 实际含义 |
| --- | --- |
| Child Run completed | 模型运行正常结束；不代表评审通过 |
| 父 Task completed | 按现有委派生命周期取得执行结果；不替代业务质量判定或资源释放确认 |
| 模型报告中的 verdict: pass | 模型提出的结论，必须经过应用验证 |
| 父 Run autoReview.status: passed | 服务确认执行成功、输出合法、覆盖完整且必要收尾成功后的质量结论 |

保留现有 `run.completed/failed/interrupted` 结算 Task 的时机，不为输出正文增加“等待关闭才交付”的分支。`child.closed` 事件与关闭调用的成功返回不可混为一谈：当前关闭实现会收集清理异常、发布事件，再向调用方抛错。自动评审服务必须接收该错误，不能把原始报告里的 `pass` 升格为 `passed`。

因此，Child Run 已完成但后续关闭失败时，运行完成事实可以保留，评审质量状态应为失败。UI、CLI 与父代理用于判断评审是否通过的依据均为 `autoReview.status`；不新增第二套 Task 状态机。

## 正常执行、失败补偿与恢复

正常结算、投影失败补偿、`child.closed` 重放均保留既有执行状态和允许交付的最终结果、`failureKind`、`partialResult`。晚到事件或重复重放不得把明确失败的评审质量状态改成通过。

自动评审重启恢复沿用现有规则：`captured → unavailable`，`pending → failed`，原因均为 `daemon_restarted`；不能仅凭持久结果中的 `verdict: pass` 恢复为 `passed`。普通 Agent 与 Workflow 的部分结果恢复继续保持可用。

现有投影失败记录会保存原事件与错误信息，JobRead 还可读取 `latestAssistantText`。这些属于同一授权范围内的诊断或交付数据，不是仅修改终态序列化就能隐藏的内容。本文不宣称父子会话之间已有保密隔离。

## 验收标准

1. **交付有用：**自动评审的有效 finding 能通过现有 Task/Child Session 入口获取；普通 Agent 和 Workflow 的最终结果与部分成果保持可用。
2. **摘要有界：**父 Run autoReview、自动评审状态事件和 Execution Observation 不携带报告全文或输入 patch；不把完整子会话记录自动拼入父上下文。
3. **状态真实：**格式错误、模型失败、超时、部分覆盖、投影或必要关闭失败均不能得到权威的 passed。Task 完成与评审通过分别验证。
4. **恢复一致：**正常结算、失败补偿、重放及 daemon 重启遵守相同结果与质量语义，既有部分成果不被通用错误覆盖。
5. **测试不过度承诺：**测试分别放置“只在输入/工具记录出现的标记”和“合法最终 finding 标记”，验证前者没有被框架额外复制、后者仍能正常交付；不把模型主动引用输入误判为框架自动拼接。

## 何时需要更强的限制

若之后明确引入不同授权主体，或要求某任务的报告正文只对指定读者可见，再设计受信任的内容访问契约。届时需要一起覆盖 Task 输出、事件、错误、partialResult、活动查询、恢复记录及导出；不能仅过滤 child.closed，也不能从可编辑角色名或 prompt 推断权限。

这属于新的访问控制需求，不以当前自动评审功能为由预先实现。当前变更不迁移或删除历史记录。

## 审核处理记录

- 采纳“默认禁止 finding 正文缺少产品依据”：父侧恢复为可交付最终报告，观测摘要保持有界。
- 采纳“正常终态过滤不足以覆盖补偿、恢复与活动查询”：撤回全局保密承诺，列明现有数据范围及更强限制需要覆盖的渠道。
- 采纳“关闭失败与原始 pass 可能并存”：区分运行完成事实、模型提议与服务质量状态，以 autoReview.status 作为唯一质量依据。
- 精简设计：移除通用投影回调、持久化契约标识和新增 Task 结算分支；保留现有可用接口与恢复路径。
