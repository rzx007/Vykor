# 子代理结果交付边界设计

> 状态：待用户审阅；本设计只规定结果如何跨会话交付，不改变子代理调度、评审触发或普通委派的默认行为。

## 问题与目标

Vkyor 已将子代理工作记录保存在独立 Child Session，但子代理的 `run.completed/failed` 和 `child.closed` 会分别把完整输出写入父 Session Task 与 `agent.child.closed` 事件。自动评审的最终 JSON 可能含 finding 正文，故“父 Run metadata 只存摘要”不足以保证父会话也只存摘要。重启恢复还会重放 `child.closed`，单改导出层或某个投影分支无法建立稳定边界。

目标是让每次受信任的委派显式决定“交给父会话什么”，同时保留子会话的完整诊断记录。普通 Agent/Workflow 子代理仍返回现有的完整最终结果；首个使用新边界的是系统自动评审。

## 方案选择

- **采用：父侧交付结果契约。** Child 原始结果与 Parent 可见结果是两份不同数据。宿主在受信任的启动入口指定结果投影器；框架在发布父侧终态事件之前调用一次，并把投影后的结果作为父 Task、父事件与恢复重放的唯一输入。普通子代理不指定投影器时行为不变。
- 不采用“导出时逐处脱敏”：已经落库的父 Task、事件及恢复记录仍含正文。
- 不采用“所有子代理只能返回计数”：探索、实现和验证任务需要给父代理交付完整结论；这是任务契约，不是运行时统一阈值。
- 不新增第二套 Job、Agent 或评审生命周期，也不增加用户可配置的模式矩阵。

## 运行流程与职责

1. **Server 选择交付契约。** 自动评审启动系统 Child 时，提供一个受信任的纯投影器。它根据严格解析后的 reviewer 结果生成有界的父侧交付：状态、结论、finding 数、最高严重级别与 Child Session/Task 引用。原始 patch、finding `evidence`、未验证的自由文本和绝对路径不进入父侧交付。解析失败时只交付失败状态与固定错误码，不转发模型原文。普通子代理省略投影器，沿用完整结果。
2. **Agent Runtime 执行与关闭。** Child 在自己的 Session 中接收输入、运行、保存完整最终输出。系统 Child 结束后，Runtime 把原始结果交给 Server 的投影器，在 `child.closed` 发布前得到父侧结果；原始结果仍作为受信任调用的返回值供自动评审状态机解析。投影失败时发布固定、无原文的失败结果，并让调用方得知失败，绝不伪报通过。
3. **Server 只投影父侧结果。** 对采用该契约的 Child，子会话的 `run.completed/failed` 只结算子会话，不再提前用原始输出完成父 Task；父 Task 等到带有父侧结果的 `child.closed` 再进入终态。父侧 `agent.child.closed` 事件同样只包含父侧结果。普通 Child 保留原来的尽早完成父 Task 的行为。
4. **恢复沿用同一事实。** 交付契约的标识由受信任宿主写入 durable `child.created`/Task metadata；不能由模型 prompt、可编辑 role 名或用户传入的 metadata 决定。重启恢复和事件重放读取同一标识及已投影的 `child.closed` 结果，不重新解析原始模型正文，也不走另一套脱敏规则。若 Child 在 `child.closed` 前失联，按现有恢复语义结算为未完成/失败，不复制其原始输出到父侧。

## 数据边界

| 位置 | 普通 Child | 自动评审系统 Child |
| --- | --- | --- |
| Child Session 的输入、消息、Run | 现有完整记录 | 保留完整记录，按现有授权诊断入口读取 |
| 父 Session Task 的终态输出与错误 | 现有完整结果 | 仅父侧交付结果；不含原始 patch、finding evidence 或自由文本 |
| 父 Session `agent.child.closed` | 现有完整结果 | 仅父侧交付结果 |
| 父 Run `autoReview` metadata/事件 | 不适用 | 继续保留现有有界结构化状态 |
| 默认会话导出 | 现有规则 | 不绕过上述边界；Child 导出维持现有脱敏规则 |

“父侧只见摘要”不等于用户永远看不到详情：有权访问 Child Session 的诊断入口可查看完整评审结果。后续若某种任务需要向父代理交付详细 findings，应由该任务定义可验证的父侧结果契约，而不是放宽所有 Child 的持久化边界。

## 兼容性与失败语义

- 未指定父侧投影器的 Agent 与 Workflow、其 `JobRead/JobWait`、部分结果和 `failureKind` 均保持现状。
- 自动评审的父 Task 不能因为 Child Run 完成就提前显示完成；在父侧结果交付或明确失败后才进入终态。投影器错误、关闭失败或恢复不完整不能产生 `passed`。
- 投影器必须有界、确定性、无工具调用；不得依赖模型再生成一份摘要。模型输出中的自由文本不能因为字段名叫 `summary` 就被视为已脱敏。
- 这项变更只影响新产生的自动评审记录；既有父 Task/事件中已存的正文不会自动迁移或删除，须单独决定历史数据处理策略。

## 验收

1. 以含 `SECRET_FINDING` 与 `SECRET_PATCH` 的真实 Child 结果运行自动评审：Child Session 保留完整信息；父 Task、父 `agent.child.closed`、父 Run metadata/事件与默认导出均不含标记，状态和数量仍正确。
2. 覆盖成功、解析失败、超时、取消、关闭失败；所有非完整结局保留真实状态，不伪报通过。
3. 在 `run.completed/failed → child.closed` 的正常顺序、投影重试、daemon 重启后的结算中重复上述断言。
4. 普通 Agent Child 与 Workflow worker 的完整最终结果、部分结果和 `JobRead/JobWait` 回归测试保持通过。

## 范围外

本设计不把所有子代理改成摘要模式，不重做自动评审的 Git 归因和风险策略，不改变子会话的授权读取权限，也不自动清理历史记录。
