# Desktop 和 CLI 共用独立 daemon

日期 2026-11-06。本文描述目标和迁移验收条件。现行行为见 [系统常驻流程](../../daemon-system-service.md)。

## 目标

Desktop 和 CLI 按同一登记文件连接兼容的本机后台。正常桌面主进程通过 `VykorClient` 发 HTTP 请求和接收 SSE 事件。独立后台执行任务并持久化会话，继续由会话库的所有权记录保证同一个库同时只有一个执行者。

保留用户已有的常驻开关、会话和后台任务、桌面环境终端、浏览器操作及其权限、备份恢复后的数据目录切换。使用同一份现有服务端实现。桌面发行包保留无窗口后台入口。已有远程连接和显式 `vk serve --store-path` 沿用当前语义。

## 启动和连接

1. 先读登记文件并探活，验证协议、鉴权和需要的能力。对活着但暂时不可达的进程，返回可重试状态并保留登记文件。只在进程已退出后清理旧记录。
2. 找不到可用后台时，开启常驻就交给现有系统服务。关闭常驻则按需启动无窗口后台，沿用桌面 `--daemon-service` 和 CLI `serve --register` 两个现成入口。两者共享后台配置和能力。按需拉起复用 SDK 启动锁。可自主启动的后台入口还需取得登记路径对应的独占权，取得后才打开数据，退出后才释放。两把锁分属调用方和后台，子进程不获取调用方持有的锁。服务端的会话库所有权继续保护同一个库。
3. 启动方等待服务写入实际地址、进程 ID、token 和数据库路径。业务 client 使用地址和 token。探活、进程身份和启动等待优先复用 `@rzx/client/service`。操作系统启动项和有损操作的决策留在调用它的本机启动层。
4. Desktop 和 CLI 都按协议与实际能力判断是否复用后台。本机已登记的后台显式启用同一套执行能力。启动归属仅用于显示和选择启停命令。CLI 启动的后台复用当前的工作区默认分配，桌面创建会话时仍显式传入系统文档路径。旧版本不满足能力时给出清晰状态，通过现有安全重启流程替换。旧后台无法确认安全收尾时，要求用户先停止旧后台。

`daemon.autoStart` 控制系统登录时启动及异常恢复。按需启动的独立进程可以在桌面退出后继续已有任务，与当前 CLI 按需启动的行为对齐。显式停止和禁用系统服务沿用原有入口。Desktop 退出时关闭自己的订阅和浏览器连接。

## 浏览器

Electron 持有真实标签页、窗口归属和开发诊断状态。服务端沿用 `BrowserHost` 接口，由一个代理把请求转给 Electron。已启动的后台也能在窗口打开后接入浏览器。

- 桌面主进程用登记 token 与本机 daemon 建立一条经过鉴权的 SSE 连接。浏览器事件放在独立的私有流，由桌面用 HTTP POST 回传审批请求和操作结果。复用现有 HTTP/SSE 传输与浏览器操作类型。每次审批由对应 POST 响应直接返回。截图通过结果入口回传，单独限制解码前后大小。
- 路由只在受管理的本机监听器开放，强制登记 token，并拒绝带 Origin 或浏览器 Fetch Metadata 的请求。信任边界是有权读取登记 token 的本机用户。随机连接 ID 用于隔离连接世代。请求同时绑定会话和连接，旧连接不能回包。
- Electron 只服务持有有效窗口会话令牌的标签页。排队、审批返回和执行前都验证窗口、会话和页面是否仍匹配。普通站点审批和开发检查审批继续调用当前工具尝试的权限回调。截图回到 daemon 原有的存储入口。
- 桌面独立处理审批返回、取消和操作请求，避免操作等待审批时阻塞消息流。操作沿用工具尝试的取消信号和截止时间。连接关闭、后台停机或安全收尾时取消挂起请求并关闭 SSE。已派发操作结果丢失时记录为执行结果未知。重连只接收新操作。
- 验收覆盖无 token、带 Origin、旧连接回包、窗口会话变化、审批期间断线及后台退出。无窗口时其它工具照常运行。

## 数据目录和安全停机

登记路径固定在启动环境确定的基础数据目录。有效数据目录可由已恢复的数据位置覆盖。已有 Electron `runtime-data-location.json` 第一次迁移时导入到基础目录下的 daemon 状态文件，保留其指定的数据库路径。CLI 从桌面默认安装目录读取旧配置。桌面若使用自定义安装配置且发现后台打开了另一份库，会提示先停掉后台，再从桌面启动。Desktop 和本地已登记的 CLI 后台读取同一份选择。显式指定的 CLI 数据目录或数据库仍按原规则处理。

切换继续限于按需后台。桌面调用带目标位置的本机维护入口。后台校验目录和数据库，并持有启动协调锁直至切换结束。检查常驻开关和系统服务状态后，复用安全重启的准入检查。仍有运行、后台任务或终端时直接拒绝。获得准入后写入切换 ID，向桌面确认接收，再由原进程关闭旧应用和 HTTP 监听。此后打开目标库并重新监听。切换期间保持同一进程和登记独占权，调用方等待该实例更新登记。目标就绪后原子写入目录选择和切换结果，再原子发布新的地址与 token，随后开放任务和渠道。目标初始化可以运行数据库恢复。若打开目标失败，在原进程重新打开旧库并保留原选项。若恢复也失败，记录单独错误并退出，释放登记独占权。提交目录选择后，发布登记失败则退出并保留已验证的新位置。崩溃发生在提交之前时，下次报告该切换中断，并从旧位置启动。并发切换在同一进程内拒绝。

## 顺序与验收

1. 接通私有浏览器通道。验证普通与开发审批、断线后不重放、旧连接回包隔离，以及现有标签页操作仍可用。
2. 统一无窗口入口的数据位置和安全停机。验证默认位置、已有自定义位置、活跃任务拒绝切换、新位置启动失败后的恢复。
3. 切换桌面按需启动，保留系统服务入口。每次登记都原子发布，进程退出时只清理仍属于自己的登记。验证 Desktop 先开、CLI 先开、常驻先开及并发启动时复用同一实例。两端同时连接仍使用同一会话和事件流。
4. 删除桌面主进程的内置启动路径，更新 Desktop、CLI、客户端服务管理、浏览器和系统常驻文档。

测试用临时目录和隔离的进程，覆盖进程不可达、断线和恢复。使用 `pnpm check:retired-ui` 与 `pnpm check-docs` 验证路径、旧引用与文档。
