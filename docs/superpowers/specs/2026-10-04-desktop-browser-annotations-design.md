# Desktop 浏览器批注体验改进设计

> 状态：设计已实现。当前浏览器能力见 [Desktop 浏览器能力](../../browser-capabilities.md)，验证记录见实施计划。

实施任务与本次审核修订见 [浏览器批注实施计划](../plans/2026-10-04-desktop-browser-annotations.md)。

## 1. 目标和范围

让用户在内嵌浏览器里清楚地完成“找到元素、选中元素、写意见、回看意见”，并让 Agent 收到对应页面的批注。

本期改善已有功能，不建设新的浏览器框架。支持主文档中的普通 HTML、React、Vue 页面；批注不依赖网页使用哪种框架。批注保存在当前标签页的主进程内存中，不增加数据库、云同步或跨会话恢复。

用户流程：

1. 点击浏览器工具栏的批注按钮，进入选择模式。
2. 鼠标悬停时显示目标边框和简短名称，滚轮继续滚动网页。
3. 点击目标后锁定边框，在目标旁显示意见输入框。
4. 保存后显示编号标记，可以继续选择其他元素。
5. 点击编号或批注列表项，回看意见并定位目标；支持删除批注。
6. 结束选择后恢复普通网页操作，保留已保存的编号；可以单独隐藏批注显示。

本期不提供 React 性能分析、组件树、源码跳转、任意脚本执行、跨框架内部状态读取、多人协作、图片涂画或批注导出。iframe 内部和 Shadow DOM 内部节点不在本期选择范围；可以选择其外层元素，并明确提示范围。

## 2. 已有实现和问题

现有入口：

- `apps/desktop/src/renderer/src/components/desktop/tools/browser-tool.tsx`：浏览器导航、webview 绑定，以及批注模式、透明点击遮罩、输入框。
- `apps/desktop/src/main/features/browser/browser-agent-service.ts`：核对窗口和标签页，用 `document.elementFromPoint()` 取得目标文字，在内存中保存 `{ target, comment }`。
- `apps/desktop/src/main/features/browser/ipc.ts`：核对调用窗口，转交固定浏览器请求。IPC 是主界面与主进程之间的通信。
- `apps/desktop/src/shared/ipc-channels.ts`、`desktop-api-contract.ts` 和 `apps/desktop/src/preload/desktop-api.ts`：定义请求类型并向主界面提供接口。
- `packages/server/src/application/browser-tools/browser-host.ts`、`browser-tool.ts`：定义页面观察结果，将批注作为 Browser 工具结果交给 Agent。

目前选择前没有高亮预览；选择后只有文字，输入框固定在左上角；保存后只有内部计数，没有页面标记和回看入口。目标没有定位信息，批注按 WebContents ID 保存，没有与页面地址建立明确的生命周期关系。

现有页面权限、标签页绑定、普通 Browser 动作和 Developer mode 检查继续作为基础，不在本期重构。

## 3. React Scan 的取舍

参考 [React Scan 的高亮和选择器实现](https://github.com/aidenybai/react-scan/blob/main/packages/scan/src/web/views/inspector/overlay/index.tsx)：悬停边框、目标标签、点击锁定、视口位置跟随。它的选择器依赖 React 内部组件树，且使用性能面板的内部状态；[公开 API](https://github.com/aidenybai/react-scan#api-reference)以性能扫描为主。

本期参考交互思路，自行实现必要的 DOM 命中和显示，不安装 React Scan，不复制它的性能面板。现有页面已经可以使用固定脚本读取元素，增加框架专属依赖不能解决通用网页批注问题。

后续取舍：仅引入框架无关的 `@medv/finder` 4.0.2 生成 CSS 选择器，保留现有选择、高亮和清理逻辑。不引入 `pick-dom-element`，其选框位置更新与点击传播不满足已验证的交互边界。finder 在构建阶段通过共享 Vite 插件打包为自包含 IIFE（无需外部模块加载的脚本），仅在进入选择时注入，并保留其 MIT 许可声明；运行时不下载脚本。

选择方案时考虑了三种方式：

| 方式 | 结果 | 决定 |
| --- | --- | --- |
| 接入 React Scan 整包 | 带入性能分析和 React 组件依赖，仍需自行实现意见保存与回看 | 不采用 |
| 继续在主界面遮罩上处理鼠标，再跨进程查询每次悬停 | 能复用点击代码，但滚动转发、延迟和网页坐标同步会增加复杂度 | 不采用 |
| 在网页内运行固定选择脚本，主界面只处理批注表单和列表 | 元素命中与绘制在同一坐标空间，网页保留原生滚动 | 采用 |

只显示一个悬停框和至多 20 个批注标记，普通 DOM 和 CSS 足够；不使用 Canvas、Worker 或动画库。

| 位置 | 负责什么 | 接收和返回什么 |

| `apps/desktop/src/main/features/browser/browser-annotation-controller.ts`（新增） | 保存批注、管理选择身份、校验脚本结果、调用固定脚本、生成界面快照 | 由 Browser 服务提供已核对的 guest 和页面版本；不自己查找任意 WebContents |
| `browser-agent-service.ts`（修改） | 继续管理窗口、标签页、页面导航和 Agent 站点权限；把已核对的请求交给批注控制器 | 页面身份和生命周期来自这里；批注控制器不复制导航监听 |

| `apps/desktop/src/renderer/src/components/desktop/tools/browser-annotation-panel.tsx`（新增） | 显示输入框、批注列表、错误和保存反馈 | 只消费 hook 返回的数据和回调；不直接调用 Electron |
| `browser-tool.tsx`（修改） | 保留导航、webview 绑定和页面容器，接入批注 hook 与面板 | 提供容器位置和标签页信息，不再持有批注存储逻辑 |
| 现有 IPC、preload 和 Server Browser 文件（修改） | IPC 核对调用方并转交；preload 提供窄接口；Server 输出有限批注 | 不增加第二份批注存储，也不开放新 Browser 动作 |

批注控制器是 Browser 功能内部的具体模块，不定义通用 repository、事件总线、插件接口或多个可替换实现。主进程内存中的记录是唯一保存来源；网页只持有显示所需的目标引用，主界面持有快照和未保存草稿。

## 5. 最小数据和接口

### 5.1 批注记录

保存后的记录包含：

- `id`：主进程生成的批注身份；编号只是展示顺序，不作为身份。
- `pageUrl`：保存时的完整主文档地址，区分路径、查询参数和片段。
- `target`：有限的可读元素说明，例如 `button: 提交`。
- `selector`：固定脚本生成的 CSS 定位信息；不是 Renderer 自行提供的字符串。
- `locatorKind`：`unique-id`、`semantic` 或 `path`，区分唯一 ID、基于稳定属性/类名的选择器，以及只在原文档引用有效时使用的结构路径。
- `tagName`、`role`、`name`：用于重载后核对元素是否仍是原目标。
- `comment`：用户意见，去掉两端空白后最多 2,000 个字符。

不保存整个 DOM、HTML、输入值、计算样式、截图、React 组件实例或框架内部数据。

目标矩形属于当前界面快照，不属于保存记录。快照中的目标状态为：

- `visible`：找到并核对目标，矩形与视口相交，可以显示标记。
- `offscreen`：找到目标，但当前不在视口内；列表可以请求滚动定位。
- `missing`：目标消失、定位不唯一、特征不匹配、暂时无法取得位置，或结构路径的原元素引用失效；列表仍保留意见，页面不显示旧位置的标记。

### 5.2 页面和选择身份

Browser 服务维护单调递增的 `pageRevision`，表示当前标签页页面版本。主文档导航开始、同文档地址变化、guest 更换时使旧版本失效；它独立于 Developer mode 的诊断状态，不能靠调用方传入的 URL 决定身份。

进入选择模式后的候选元素由页内脚本持有引用；用户锁定目标后，主进程生成 `selectionId`，关联当前 `pageRevision` 和经过校验的目标信息。保存请求只提交这个选择身份和意见。它不是普通 Browser 的 `elementId`，不授予 Agent 点击或输入权限。

### 5.3 Desktop 固定接口

沿用 `window.desktop.browser`，只增加实际需要的方法：

| 方法 | 输入 | 结果 |
| --- | --- | --- |
| `readAnnotations` | `tabId` | 当前页面版本、显示模式、锁定目标、被点击的批注 ID、批注记录及目标矩形 |
| `setAnnotationMode` | `tabId`、`pageRevision`、`mode: off / pick / review` | 更新后的快照；进入 `pick` 时清除旧锁定目标 |
| `addAnnotation` | `tabId`、`pageRevision`、`selectionId`、`comment` | 保存后的快照；成功后清除选择并继续 `pick` |
| `focusAnnotation` | `tabId`、`pageRevision`、`annotationId` | 尝试滚动到匹配目标，返回新的位置和目标状态 |
| `removeAnnotation` | `tabId`、`pageRevision`、`annotationId` | 删除后的快照 |

首次打开界面先读取快照取得页面版本，再进入选择。所有写请求均要求当前页面版本；旧请求失败后，界面读取新快照，不自动在新页面重试保存或定位。

快照携带 `interactionVersion` 和页内 `eventSequence`。前者由主进程在开启、暂停或结束交互时递增，用于拒绝旧脚本结果；后者只在锁定元素、点击编号或页内 Escape 等用户操作时递增。hook 按“页面版本、交互版本、事件序号”处理一次用户操作，不能因为同一个快照被反复读取而重新打开已关闭的意见框。

用上述接口替换仅返回文字的 `inspectAt`；现有 `addAnnotation` 同步调整参数。IPC 类型、preload、Desktop API 契约和调用方一次性更新，不同时保留新旧两套选择流程。

记录提交是保存成功的判据。提交后页面标记同步失败时，仍返回已保存记录的快照，暂将其位置标记为 `missing` 并通过列表说明位置不可用；不能把这次保存说成失败，诱导用户重复提交。

### 5.4 Agent 结果

`BrowserObservation.annotations` 的每条数据包含 `{ target, comment, selector }`。这是一处小的输出类型调整，Server Browser 工具沿用现有输出通路；不把 Desktop 批注类型或 Electron 引入 Server。

只返回当前主文档地址的已保存批注，继续遵守普通 Browser 的站点授权和观察范围。草稿、悬停数据、显示模式和矩形不进入模型上下文。`selector` 只是说明如何定位目标，不是新的工具执行参数；Agent 仍须通过普通 Browser 的观察和元素 ID 进行操作。

## 6. 页面内选择层

### 6.1 安装和通信

在已经核对的 guest 主文档内运行应用打包的固定脚本。使用 Electron 现有 `executeJavaScriptInIsolatedWorld()`：脚本拥有独立的 JavaScript 全局变量，但仍与网页共享 DOM。使用应用内集中定义的专用 world ID，不使用网页主世界或 Electron preload 使用的世界。

保持现有 `will-attach-webview` 策略：不增加 guest preload，不启用 Node，不关闭沙箱或网页安全检查。隔离执行环境不等于 DOM 可信；返回字段仍由主进程检查类型、长度和范围。

脚本只支持安装、设置显示模式、读取有限快照、同步保存标记、定位匹配元素和销毁这些固定操作。参数作为序列化数据传入，不能用意见、选择器或网页文字拼出可执行语句。

选择层节点放在独立 Shadow Root 中，使页面 CSS 不影响它，也使现有主文档文本提取和可操作元素查询不会把编号按钮当成网页内容。Shadow Root 用于显示隔离，不作为权限边界。

主界面不增加网页消息桥。批注显示期间每 100 ms 串行读取一次快照，最多一个读取请求在途；隐藏批注、切换到非活动标签页或卸载组件时停止读取。鼠标悬停及边框移动完全由页内脚本处理，不经过这个周期。

页内调用最多等待 2 秒；超时结束本次交互，保留保存记录并提示重新开启。超时不代表底层脚本已取消，迟到结果仍须按交互版本丢弃和清理。

固定命令都携带交互版本，旧安装不得覆盖新版本；清理只处理对应的旧选择层，不能删除已经重新开启的选择层。批注读取不进入 Agent 的长操作队列；主进程对批注写入只允许一个未完成操作，冲突时返回占用错误，结束或暂停立即使该操作失效。

### 6.2 输入和绘制

- 选择模式在主文档尽早捕获 `pointerdown`、`mousedown`、`pointerup`、`mouseup` 和 `click`，取消默认动作并停止后续传播；只拦截 click 会让按下鼠标时的网页处理器先执行。锁定目标不得触发目标自身的网页处理器或默认导航。这是需要真实 Electron 验证的交互要求，不是对任意网页脚本的安全隔离保证；网页更早安装的全局捕获处理器仍可能先运行。
- 不捕获或阻止主文档的滚轮、触摸板滚动、原生滚动条操作。选择层的边框和标签不接受鼠标事件；已保存的编号可以接收点击。
- iframe 等独立嵌入区域在选择模式下覆盖局部命中层，点击只选择外层元素，不让选择手势进入子页面。该区域的内部滚动和节点选择不在本期范围，退出选择后恢复原操作；不遍历子框架或增加跨域访问。
- 页面滚动（包含内层滚动容器）、窗口变化和元素尺寸变化时，合并到下一次 `requestAnimationFrame` 更新位置。每次快照读取也重算有限的目标矩形，以覆盖网页布局变化。
- 已锁定目标期间保留边框，不让鼠标经过其他元素替换草稿目标；重新选择由用户显式触发。
- 锁定使用当前实际 DOM 元素，避免在鼠标移动途中只凭旧坐标选择。选择器优先使用经筛选的唯一 ID，否则通过 finder 组合白名单属性、有限类名和元素层级；不在悬停时运行选择器搜索。
- 原元素引用仍有效时直接使用它。原引用失效后，只有 `unique-id` 和 `semantic` 可以尝试重定位，且必须唯一匹配，标签、角色和非空名称特征一致。`path` 即使重新查到相同文字也返回 `missing`，避免列表重排后指向另一个同名按钮。
- 标记先按当前文档中的元素引用定位。引用失效或文档重载后才按保存的选择器重新核对，不每次遍历整个 DOM。

主进程每条记录最多保留 512 个字符的选择器、200 个字符的目标说明和 180 个字符的名称。超过选择器深度 12 或无法生成唯一定位信息的元素，本期提示选择一个更明确的外层目标，不保存无法可靠回看的记录。

### 6.3 坐标和缩放

元素矩形使用页面视口的 CSS 像素，即 `getBoundingClientRect()` 的坐标；页内边框和编号使用同一空间，不保存滚动后的绝对像素位置。

主界面意见框以实际 webview 内容区为边界。快照附带页面视口宽高，按“主界面容器尺寸 / 页面视口尺寸”换算位置；不得再乘 `devicePixelRatio`。意见框优先显示在目标旁，空间不足时翻到另一侧，最终限制在内容区内。

目标离开视口时隐藏其页内标记；未保存意见框收至内容区底部并显示“目标已滚出视野”，草稿继续保留。回看列表中的 `offscreen` 目标时，通过固定定位方法调用目标的 `scrollIntoView()`，再读取实际位置。

## 7. 主界面状态和反馈

hook 只维护一个明确的界面阶段：正常浏览、正在选择、填写新批注、查看已保存批注。保存中作为操作状态处理，不另建状态机框架。主进程快照中的 `off / pick / review` 分别表示隐藏选择层、允许选择、只显示保存标记；界面阶段由快照和当前草稿推导。

- 工具栏显示可见的批注数量；数量按钮打开列表，列表按创建顺序显示编号和意见摘要。
- 锁定后输入框获得焦点，目标名称和边框同时存在。输入框使用应用现有颜色、按钮、焦点样式和克制的浮层阴影。
- 保存中禁用重复提交；主进程成功返回后才显示编号、清空草稿和更新计数。
- 保存失败保留草稿并在输入框内显示具体原因，提供重试或重新选择；不只在页面角落显示原始异常。
- 查看保存批注时可以删除；删除成功后再移除编号和列表项。本期不提供意见编辑。
- 输入框支持 `Ctrl/Cmd + Enter` 保存；普通 Enter 保持换行。Escape 取消当前输入或查看，返回选择；选择状态下再次 Escape 结束选择并进入 `review`。
- 编号在主界面列表里有等价的可聚焦按钮，不要求键盘用户操作跨执行环境的页内标记。
- 选择模式保留网页原有的 Tab 焦点移动；聚焦网页元素时同步高亮，Enter 捕获并锁定该元素。本期键盘选择覆盖网页原有可聚焦元素，不声称能键盘遍历所有静态节点。
- 切换标签页、暂时隐藏面板、保存失败或目标失效时保留草稿文字。暂停结束旧选择身份；恢复后先显示“草稿已保留，请重新选择目标”，重新选择前禁用保存，不猜测旧目标。
- 页面地址或文档版本改变时同样保留当前已挂载组件的草稿文字，但解除其目标关联并提示重新选择。明确取消或标签页真正关闭才丢弃草稿；不增加主进程草稿存储或跨组件恢复。
- 窗口、模式和页面版本变化时取消旧读取的界面影响。Renderer 的请求序号只控制界面响应；是否允许写入始终由主进程当前身份决定。

编号和文字说明共同表达状态，不只靠颜色。减少动态效果时取消边框过渡；不添加脉冲、发光或持续播放动画。

## 8. 生命周期和失败处理

每个标签页只保存当前地址的一组批注，不建立多页面缓存或历史索引。

| 情况 | 保存记录 | 选择层和界面 |
| --- | --- | --- |
| 切换标签页或暂时隐藏 Browser 面板 | 保留 | 停止读取和页内选择监听，旧选择身份失效；hook 保留草稿文字，恢复时读取记录并要求重新选择 |
| 普通滚动、窗口变化、同地址 DOM 更新 | 保留 | 跟随目标位置；目标替换后核对定位，不能核对则标记 `missing` |
| 主文档开始导航或刷新 | 暂时保留，停止对外投影 | 页面版本立即失效，销毁旧选择层，解除草稿目标关联；旧异步结果不得恢复旧界面 |
| 导航完成且完整地址未变 | 保留 | 用户重新显示批注时安装选择层；唯一 ID 和语义属性/类名目标按特征核对，结构路径目标只在列表保留文字 |
| 导航完成且完整地址改变 | 清空 | 以新页面版本开始；同站换路径、查询参数或片段变化也按换页处理 |
| guest 更换、标签页关闭或 Desktop 退出 | 清空 | 取消读取、移除监听和选择层、释放目标引用；恢复进程不重建旧批注 |

导航期间不自动重试保存。只有在主文档就绪后才允许重新进入选择；界面提示“页面已变化，草稿已保留，请重新选择目标”，不自动把草稿关联到新页面。取消导航也使旧选择失效；主文档仍可用且地址未变时保留保存记录，但重新选择后才能保存草稿。

`setActiveTab` 由 Browser 服务主动暂停上一个标签页的选择层，不能依赖切页后已经停止读取的 hook 来清理。只是隐藏面板时，hook 在可见状态变化时请求 `off`；页面销毁时由主进程清理兜底。`UtilityPanel` 目前传给 Browser 的 `active` 只表示选中标签页，不含面板的 `open`；新增独立的 `visible = open && active` 给批注 hook，不能把普通 Browser 的活动标签页语义改成面板可见性。

导航监听只处理主框架。同文档地址变化按 `did-navigate-in-page` 的 `isMainFrame` 和新地址处理，不等待不会发生的整页 `dom-ready`；子框架导航不改变主页面版本或清空记录。换主题导致 React ref 暂时解绑、随后绑定同一 guest 时只暂停选择，不清空保存记录；只有真实 guest 更换或销毁才释放原记录。

DOM 元素消失、网页移除选择层或脚本安装失败不能影响正常浏览。安装失败时退出选择并提示重新开启；重新开启进行一次幂等安装。停止、切换模式和导航清理均应可重复调用。主进程在脚本调用前后核对 guest、活动标签页、页面版本和本次交互版本；停止之后迟到的安装结果必须清理，不能重新挂回监听。

## 9. 限制和信任边界

- IPC 调用方必须是拥有该标签页的 Desktop 主窗口。用户界面操作只作用于当前活动标签页；请求携带的 guest ID、URL、选择器和矩形不能替代主进程核对。
- 网页只提供候选目标信息，不能直接新增或删除批注、发送 IPC、请求站点授权。固定脚本不读取密码和其他敏感输入值，不读取框架内部状态。
- 每页最多 20 条批注，达到上限时明确要求先删除记录，不静默淘汰旧意见。
- 空意见拒绝保存；超过 2,000 个字符在输入端限制，主进程仍独立校验并拒绝，不静默截断。主进程对所有页面返回数据和数值矩形独立限制。
- 同一 `selectionId` 只能成功保存一次，防止双击提交、重试或迟到请求产生重复记录。
- 保存前再次核对锁定元素仍连接到当前文档且特征匹配；同地址内元素已经消失时拒绝保存并保留草稿，不用原来的文字说明猜测目标。
- 定位不接受 Renderer 或 Agent 的任意选择器；只使用主进程已经保存、当前页面仍匹配的记录。
- 网页文本和批注引用仍作为不可信工具数据进入 Agent 结果，不能改变现有授权或扩展 Developer mode。

## 10. 实施顺序和验收

按下面三个可验证的部分推进，不先做通用基础设施，也不顺带重构整个 Browser 服务。

### 第一步：数据、身份和生命周期

完整实现前先执行实施计划中的 Electron 可行性任务，验证固定脚本、真实 webview 的输入拦截、原生滚动和浮层显示。未验证通过时不能宣称页内选择方案已成立，也不能直接绕到大规模输入转发框架。

新增 Desktop 批注类型及具体控制器，接入 Browser 服务现有标签页与导航事件；完成页面版本、选择身份、数量限制、删除和当前页面投影。同步增加 Server 观察结果中的 `selector` 字段。

重点验证：不同窗口/标签页不能互相操作，旧页面或旧选择不能保存，同一选择只保存一次；同地址刷新保留记录，地址改变和 guest 销毁清理记录，子框架导航及同 guest 重绑不误清理；Agent 结果只含当前页面的已保存记录。

### 第二步：页内选择和最小快照接口

新增固定脚本，完成高亮、锁定、编号和清理；接入 IPC、preload 和 Desktop API，替换旧文字选择接口。先在真实 Electron guest 中验证选择和清理，再接入主界面。

重点验证：选择点击不会提交表单或打开链接；滚轮及内层滚动容器仍原生工作；脚本多次安装、退出再进入、导航中断后没有重复监听；非 React 页面、iframe 外层和失效目标有明确结果。

### 第三步：输入框、列表和反馈

提取 hook 与批注面板，将 `browser-tool.tsx` 变回导航和组合入口，接入目标旁输入、保存反馈、回看、删除、键盘操作及有限快照读取。

重点验证：保存失败、暂停或页面变化后保留草稿且不能用旧目标提交；快速切页/关闭面板后迟到响应不重新打开输入框；同一页内事件只消费一次；窄面板、深浅主题、页面缩放和高 DPI 下位置正确；隐藏时停止读取，保存后编号与列表一致。

### 检查范围

- 控制器、Browser 服务与界面 hook 使用现有 Vitest；只新增能揭示身份、生命周期或异步错误的行为测试。
- 页内脚本的真实点击取消、原生滚动、执行环境隔离和坐标换算必须在 Electron 里检查，模拟 DOM 测试不能代替这些验证。
- 完成实现后运行 Desktop 的 node/web 类型检查、涉及的 Browser 和批注测试，以及 Server Browser 工具相关测试。不重复运行无关的整仓测试。
- 真实页面至少覆盖普通 HTML 和 React、内层滚动、同地址刷新、同文档换地址、目标删除，以及页面缩放 80% / 125% 和窄面板。
- 文档和当前能力说明以实现状态为准；本方案通过文档检查不代表功能已经实现或 Electron 验收通过。

## 11. 完成标准

用户能在点击前看清目标、点击后看清已选位置、保存后看到编号、通过列表回到匹配元素。正常浏览和滚动继续工作；页面变化不会把旧批注当作新页面意见交给 Agent。

代码中只有一份主进程保存记录，没有新的数据库或框架专属依赖；导航与权限仍由 Browser 服务管理，DOM 操作留在固定页内脚本，主界面只处理用户交互和显示。
