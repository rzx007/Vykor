# Agent 回复风格

## 目标与范围

按用户已确认的调研方案，提供协作、直接、讲解三种可独立选择的回复风格。进度通知继续由 `workStyle` 控制。覆盖桌面设置、配置读写和导入导出、会话覆盖、程序接口、子 Agent 继承、模型请求刷新和上下文统计。

## 配置与优先规则

`ReplyStyle` 为 `collaborative | direct | explanatory`，默认 `collaborative`，纯类型和校验函数归 agent-contracts。全局配置保存 `replyStyle`；会话 runtime 可指定具体风格或 `inherit` 以恢复跟随默认；程序接口可指定具体风格。请求配置保存解析后的值。

会话显式覆盖优先于全局配置，子 Agent 显式值优先于父 Agent 当前值。未设置时继承；一份请求只注入一套风格。旧配置缺少字段时使用协作。无效值在配置写入或会话修改前拒绝，失败不增加配置版本。

显式完整 `systemPrompt` 继续完全覆盖默认提示词，不暗中附加风格。普通自定义指令、SOUL.md、USER.md 和项目规则仍参与默认组装。说明用户当前要求与项目规则优先于默认表达偏好。

## 提示词

`packages/prompts/src/reply-styles.ts` 持有共享沟通规则与三档差异。共享规则覆盖结论、关键发现与影响、证据、不确定性、纠正和交付；各档分别控制协作程度、铺垫和解释深度。更新时机只由进度通知规则负责，风格不降低任务完成、验证和权限要求。

从固定任务规则中移走可变语气要求，排版规则只管 Markdown 结构。Fast mode 说明执行速度偏好，不再覆盖回复风格或鼓励省略必要调查。

## 界面

一般设置新增“回复风格”下拉，三档附简短说明。原“工作风格”改称“进度通知”，保留原配置值以兼容已有设置。复用现有 Select、设置行、错误展示和保存回退行为，不新增第三方组件，不搭建预览或截图。

## 验证与边界

以真实配置读写、会话持久记录、请求配置快照和模拟模型接收的最终请求验证传递、优先级、热更新、单次注入和完整提示词覆盖。实际模型风格效果另用可重复的场景清单评估，不用字符串断言冒充模型行为验证。

不修改用户已有的 composer 附件改动，不创建提交或推送。完成前运行受影响测试、类型检查、`pnpm check:retired-ui` 与 `pnpm check-docs`。
