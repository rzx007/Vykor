# 轻量便签二期：本地 Markdown 文件

日期：2026-10-05

状态：已按确认范围实现，相关测试及独立审查通过。

## 已确认定位

便签用于碎片化记忆：打开即写、自动保存、随用随走。正文以独立的本地 `.md` 文件保存，界面仍是普通文本输入框，不要求标题、格式或每次选择路径。

本轮不包含 AI、附件管理、富文本、分类、项目关联、多端同步或系统快捷设置。此前较大的二期方案已撤回。

## 保存和找回

- 全局便签列表、新建、编辑、正文搜索和删除确认。
- 从首个非空行派生标题，Markdown 文件只包含正文，没有隐藏头部。
- 固定保存到数据库同级 `notes/` 目录，默认位于用户数据目录的 `data/session-runtime/notes/`。
- 使用稳定 ID 作为文件名，改正文不会重命名文件。页面提供“打开便签文件夹”。
- 输入后约 300 ms 自动保存；失败保留本地恢复稿并支持重试。
- 应用内部只记录 ID、时间、修订号、内容摘要和删除标记。正文以文件为准，不在数据库重复保存新正文。
- 文件先写入临时文件并完成同步，再替换原文件；失败不把原文件清空。
- 整组数据库操作回滚时，文件创建、修改和删除也按相反顺序撤销；已提交后通知失败不撤销保存。
- 外部编辑改变文件后，旧修订请求拒绝覆盖。重新聚焦页面时刷新已保存内容，保留当前未保存编辑。

## 旧数据和备份

- 原 SQLite `note` 记录首次使用时复制到 Markdown，原数据库内容不删除。
- 同名文件已存在时保留现有文件，不用旧库正文覆盖它。
- 删除标记防止已删除文件从旧记录再次导入。
- 原有未保存恢复稿继续恢复，已退役小窗口的恢复稿在确认转入主恢复缓存后清理旧键。
- 新备份使用版本 3，同时保存数据库索引和 Markdown 目录；旧版本 1／2 备份继续支持。
- 所有版本恢复目标便签目录已含文件时均拒绝覆盖。旧版本的迁移和正文导出仅在暂存副本上进行，不改写备份原件。
