# 便签统一桌面与文件夹分类

日期：2026-10-27

状态：2026-10-29 已实现并完成 review 后的五项优化，146 项定向测试和相关类型检查通过；交互样式按协作约定由用户查看。

## 目标

将现有“桌面／收纳”两种展示模式合并为一个统一桌面。用户不再切换模式，而是直接拖拽便签完成整理：

- 将一张便签拖到另一张便签上，自动创建文件夹。
- 将便签拖到已有文件夹上，文件夹先原位展开，再把便签放到夹内位置。
- 将夹内便签向外拖出，文件夹先收起，再把便签放回桌面网格。
- 桌面与文件夹内部都使用自动网格排序，不保存自由坐标。

改造必须保留现有 Markdown 正文、自动保存、冲突处理、恢复稿、纸色、置顶、搜索、删除确认和详情编辑能力。

## 产品规则

### 统一桌面

顶层网格同时展示未分类便签和文件夹。删除现有“桌面／收纳”切换及单一总收纳夹。

文件夹只有一层，不允许嵌套。桌面和文件夹内部均可拖拽排序，窗口尺寸改变后按当前顺序重新流式排布。

### 创建与命名

把便签 A 拖到便签 B 上，稳定悬停达到合并阈值后进入“合成文件夹”预览；仅当指针仍位于 B 的有效命中区域内并松手时创建文件夹，不显示二次确认框。未达到阈值、松手时已离开 B、按下 `Escape` 或拖拽被系统取消时均不得创建文件夹。新文件夹包含 A 和 B，并占据 B 原先的桌面顺序位置；A 原位置被移除。文件夹默认采用目标便签 B 的派生标题，创建过程不弹出输入框。创建完成后提供轻量重命名入口，用户也可稍后从文件夹的更多菜单重命名。

同一张便签最多属于一个文件夹。文件夹 ID 独立于名称，重命名不会改变归属关系。

### 放入与取出

将桌面便签连续悬停在已有文件夹上达到 400 ms 后，文件夹原位展开。拖拽项继续跟随指针，夹内网格展示预期插入位置；松手才确认放入。

从文件夹内部拿起便签并越过展开层边缘达到 24 CSS px 后，文件夹先收起，随后显示桌面网格落点；用户在桌面松手后确认取出。

文件夹只剩一张便签时自动解散。剩余便签占据原文件夹在桌面中的位置；本次拖出的便签放到用户选择的桌面位置。空文件夹不能存在。

删除文件夹等同于解散：从 `desktop` 删除该文件夹项，并在该项原索引处按 `folderItems[folder-id]` 的既有顺序连续插入文件夹内全部便签；随后删除对应的文件夹元数据和 `folderItems` 条目，不删除任何 Markdown 正文。删除单张便签继续使用现有确认流程。

### 搜索与排序

搜索同时覆盖：

- 桌面便签正文；
- 文件夹内便签正文；
- 文件夹名称。

搜索结果保留原归属信息。夹内便签结果显示所在文件夹，用户可从结果打开便签；匹配文件夹名称时显示该文件夹。

手动网格顺序不再被更新时间自动覆盖。置顶便签进入桌面置顶区，置顶区内部仍可手动排序；普通便签和文件夹按持久化的桌面顺序排列。文件夹内部按各自的手动顺序排列。

## 交互状态与阈值

页面只建立一个拖拽上下文，使顶层桌面与原位展开的文件夹属于同一次拖拽会话。

- 指针移动达到 6 CSS px 后才开始拖拽，避免打开便签时误触。
- 在另一张便签上连续稳定悬停达到 250 ms 后进入“合成文件夹”状态。
- 在文件夹上连续悬停达到 400 ms 后自动展开。
- 夹内便签越过展开层边缘达到 24 CSS px 后自动收起文件夹。
- 拖过便签但没有满足合并悬停时，按普通网格排序处理。
- 松手前只更新内存预览；松手后才提交组织变化。
- `Escape` 取消拖拽并恢复拖拽前布局。

距离按指针从起点到当前位置的欧氏距离计算，达到或超过阈值即触发。悬停计时仅在指针连续位于同一目标的有效命中区域时累计；离开目标、切换目标、取消拖拽或开始滚动时立即清零。触控和鼠标使用相同业务阈值；键盘操作不使用悬停与距离阈值。

拖拽期间使用稳定的浮动纸片预览，避免文件夹通过 Portal 展开或网格重排时纸片跳动。目标便签用文件夹轮廓表达可合并，文件夹封面用轻微状态变化表达可放入，网格用真实空位表达落点；不使用发光或大幅缩放。

网格重排沿用现有 `SPRING_LAYOUT`。文件夹开合与共享元素变化控制在 150–200 ms。启用系统“减少动态效果”后只取消位移补间，开合直接切换；6 CSS px、250 ms、400 ms 和 24 CSS px 的业务阈值保持不变，避免该模式更容易误触。界面仍保留明确的落点与结果反馈。

## 技术方案

### 三方库与动画分工

采用 `@dnd-kit/core`、`@dnd-kit/sortable` 和 `@dnd-kit/utilities`：

- dnd-kit 负责鼠标、触控和键盘输入，碰撞检测，二维网格排序，跨桌面与文件夹容器移动，以及拖拽浮层。
- 现有 `motion/react` 负责文件夹开合、共享元素衔接和非拖拽项的布局补间。
- 不让 dnd-kit 与 Motion 同时控制拖拽项本体的 `transform`；拖拽项由浮层控制，其他项目由 Motion 补间。

项目锁文件已有兼容 React 19 的 dnd-kit 版本，但桌面包需要显式声明直接依赖，不能依赖其他包的传递依赖。

不采用原生 Pointer Events 自研，因为碰撞、自动滚动、触控、键盘和取消恢复会产生不必要的维护成本。也不采用 Pragmatic drag and drop，因为当前场景更依赖现成的二维 sortable、多容器和键盘能力。

### 前端模块边界

- `NoteBoard`：统一桌面入口，渲染顶层便签和文件夹，持有唯一的拖拽上下文。
- `NoteFolder`：渲染文件夹封面与原位展开内容，只负责展示、焦点和开合动画。
- 组织控制器：读取组织快照，处理排序、合并、移入、移出、重命名、解散、乐观更新与失败回滚。
- 拖拽状态机：保存当前拖拽项、来源容器、悬停目标、自动开合计时器和拖拽前快照；不保存持久数据。

现有便签编辑控制器继续负责正文草稿、自动保存和冲突恢复。组织控制器不改写正文，也不参与正文修订号竞争。

## 文件存储

### 目录与格式

文件夹、便签归属和顺序不保存在 SQLite，而是保存在便签目录下的 `organization.json`：

```text
notes/
├── <note-id>.md
├── <note-id>.md
└── organization.json
```

建议格式：

```json
{
  "version": 1,
  "folders": {
    "<folder-id>": {
      "name": "周会要点",
      "createdAt": 1793086679000,
      "updatedAt": 1793086679000
    }
  },
  "desktop": [
    { "type": "note", "id": "<note-id>" },
    { "type": "folder", "id": "<folder-id>" }
  ],
  "folderItems": {
    "<folder-id>": ["<note-id>", "<note-id>"]
  }
}
```

`version` 用于后续结构迁移。`desktop` 是顶层项目的唯一顺序来源，`folderItems` 是各文件夹内便签的唯一顺序来源。同一便签不得同时出现在多个位置。

置顶状态目前保存在本机展示偏好中。渲染时先从 `desktop` 取出置顶便签组成置顶区，再按 `desktop` 中的相对顺序展示其余项目。置顶或取消置顶时同步调整组织顺序，避免刷新后顺序含糊。

### 原子写入与串行化

组织文件沿用 Markdown 文件的安全写入策略：

1. 在 `notes/` 中创建随机命名的临时文件；
2. 以 UTF-8 写入完整 JSON；
3. 对文件执行 `fsync`；
4. 关闭句柄后通过同目录 `rename` 原子替换；
5. 无论成功或失败都清理残留临时文件。

组织写入通过单一队列串行执行。每次写入基于队列中最新快照，避免快速连续拖拽出现后一次覆盖前一次。只有拖拽松手、重命名、解散、置顶变化或外部文件自愈确实改变结构时才写文件。

每次读取成功后记录 `organization.json` 的内容哈希和文件元数据，成功原子替换后立即用新内容更新这组基线，确保队列中的后续写入不会把应用自身的前一次保存误判为外部修改。执行替换前，在组织仓库的同一进程写锁内重新读取并比较基线；若磁盘内容已变化，则本次写入不得覆盖文件，也不得自动合并，须取消尚未持久化的乐观布局、重新读取并对账磁盘版本，并向用户提示“组织文件已被外部修改，请重新操作”。文件不存在与新建文件也作为可比较的基线状态处理。

任意外部程序不遵守应用写锁时，标准文件 API 无法提供跨进程的原子比较后替换，哈希检查与 `rename` 之间仍存在无法完全消除的极短竞态。每次替换前把刚读取并通过校验的磁盘版本原子保存为单一轮换文件 `organization.previous.json`，只能恢复到校验时版本，不能保证保留该竞态窗口内外部程序刚写入的新版本。若替换后文件监视器发现非本进程写入或下一次读取发现基线异常，组织界面停止继续写入，并提供当前文件与 `organization.previous.json` 的恢复入口。验收不得宣称支持多个外部写入者并发编辑或完全保护该竞态窗口；支持范围是应用单写者、对常规外部修改的冲突检测，以及校验时版本的恢复保护。

### 对账与损坏恢复

读取 `organization.json` 时必须做结构验证和对账：

- 清除不存在的文件夹引用；
- 清除指向已删除 Markdown 的便签引用；
- 同一便签重复出现时只保留第一次合法位置；
- 文件夹少于两张便签时自动解散，并把剩余便签放回该文件夹原桌面位置；
- 扫描到未被组织文件引用的新 Markdown 时，将其追加到桌面末尾；
- 没有 `organization.json` 时，根据现有 Markdown 创建默认无文件夹桌面；
- JSON 语法错误或当前版本结构验证失败且无法修复时，将原文件复制为不覆盖既有文件的带时间戳损坏副本，再根据 Markdown 重建无文件夹桌面并返回可见警告；只有新文件原子写入成功后才替换原文件。
- 若 `version` 高于当前支持版本，则不得改名、覆盖、自愈或重建原文件；组织界面进入只读状态并提示用户升级应用或恢复兼容版本。

复制或备份整个 `notes/` 目录即可同时带走正文和分类。现有只枚举 `.md` 的正文读取逻辑必须继续忽略 `organization.json`；备份和恢复流程则需要显式包含并校验该文件。

## 保存失败与并发行为

松手后界面先乐观显示新布局，再将完整组织快照写入服务端。写入成功后清除拖拽前快照。写入失败时：

- 恢复拖拽前布局和文件夹开合状态；
- 保留所有 Markdown 正文；
- 显示“整理未保存，已恢复原位置”及具体错误；
- 提供重试入口，但不得重复应用同一次移动。

正文编辑与组织保存是两条独立队列。编辑器已打开的便签不可拖动，避免同一点击既编辑又整理；其他便签仍可整理。组织文件被外部编辑时，下一次读取先验证并对账，不静默接受不合法的多归属或嵌套结构。

## 可访问性

- 指针和触控使用相同的业务结果。
- 键盘通过空格拿起，方向键移动，空格放下，`Escape` 取消。
- 文件夹、便签和可放置位置都有清晰的可访问名称。
- 实时播报“已创建文件夹周会要点”“已放入产品想法，第 2 位”“已移回桌面，第 4 位”等结果。
- 拖拽失败、取消和自动解散也要播报。
- 文件夹关闭后恢复到打开前或拖拽开始前的合理焦点。

## 测试与验收

### 纯模型与存储

- 两张便签合成文件夹，名称取目标便签标题。
- 桌面排序、夹内排序、跨容器移动结果稳定。
- 文件夹剩一张时自动解散，删除文件夹不删除便签。
- 不允许多归属、文件夹嵌套、空文件夹或单便签文件夹。
- `organization.json` 原子写入失败时保留旧文件。
- 快速连续保存按顺序落盘，不丢失前一次操作。
- 缺失文件、新 Markdown、重复引用和损坏 JSON 能按规则对账或恢复。
- 备份与恢复包含组织文件，旧备份没有组织文件时仍可打开。

### 组件与控制器

- 页面不再出现桌面／收纳切换和总收纳夹。
- 指针移动未超过阈值时仍按点击打开便签。
- 便签悬停合并、文件夹悬停展开、越界收起均使用正确阈值。
- 拖拽取消恢复原顺序，保存失败回滚并提示。
- 搜索可发现夹内便签和文件夹名，并显示归属。
- 置顶区与手动顺序不受正文更新时间影响。
- 原位展开和关闭后焦点正确恢复。
- 减少动态效果模式下没有位移动画，但拖拽距离和悬停时间阈值保持不变，操作仍完整。

### 人工交互验收

- 拖拽过程中纸片始终跟随指针，不因 Portal、滚动或网格变化跳动。
- 文件夹开合与网格回位连续、克制，没有发光、大幅缩放或不必要阴影。
- 鼠标、触控板、触摸和键盘均能完成合成、放入、取出、排序与取消。
- 重启应用后文件夹、归属和顺序不变。
- 在文件系统中新增、删除或编辑 Markdown 后，重新聚焦便签页能正确对账。

## 非目标

本轮不实现：

- 多级文件夹或文件夹嵌套；
- 自由画布坐标、便签重叠或任意旋转；
- 标签体系、智能分类或 AI 自动归档；
- 跨设备同步或多人并发编辑组织文件；
- 拖动文件夹合并、夹内子文件夹或空文件夹占位。
