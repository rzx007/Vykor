# 桌面端 MCP 管理入口与真实配置收敛设计

**日期：** 2026-09-23  
**状态：** 设计方案已获用户口头通过，待审阅书面规格

## 目标与现状

主页面“插件 → MCP”是桌面端原定的 MCP 管理入口。它已有列表、搜索、筛选、添加、编辑、详情、删除、导出和启停界面，但目前只操作按项目区分的浏览器 `localStorage`，不会影响 Vykor 实际连接的服务器。设置页后来加入的“MCP 服务”使用真实全局配置与 OAuth 状态，造成两个入口展示不同数据。

本次将主页面接入真实管理能力，移除设置页入口。MCP 配置以全局 `settings.mcpServers` 为准，与 `vk mcp` 命令共用。切换项目不改变主页面 MCP 列表。旧主页面中的数据只是静态演示数据，不读取、不迁移，也不作为实际配置。

## 用户可见行为

### 唯一入口与列表

- “插件 → MCP”展示全局 MCP 服务；设置页不再有“MCP 服务”导航或管理页面。
- 保留现有单栏布局、搜索、全部/已启用/已停用筛选、添加、详情、编辑、移除和 JSON 导出。列表继续使用轻量图标、细分隔线和克制的文字层级，不增加一组大型状态卡片。
- 每行展示名称、经过脱敏的地址或启动命令、传输类型、一个最值得关注的状态，以及真实启停开关。停用项降低视觉权重，但仍可搜索、查看和编辑。
- 列表状态优先级：停用、需要重新授权或未登录、连接失败、已连接、尚无活动 Runtime。认证状态与运行状态不合并成一个底层字段；列表仅选一个摘要，详情分别列出两者。
- 空列表提示“还没有 MCP”，并提供添加入口。刷新重新读取真实配置、认证及 Runtime 快照。

### 详情与认证

- 详情展示传输方式、地址或命令、启用状态、认证方式、认证状态、Runtime 状态、已配置 scopes 和适用操作。
- 仅 Streamable HTTP 且配置为 OAuth 的服务显示“浏览器授权”“重新授权”或“退出登录”。公开 HTTP 服务显示“无需认证”，不提供授权按钮。Bearer/自定义认证也不显示 OAuth 操作。
- 授权仍调用现有 Desktop OAuth 服务；成功后刷新完整快照。若凭据保存成功而活动 Runtime 重连失败，明确显示“授权已保存，重连失败”，不把它误报成未登录。
- 详情默认不展开完整配置 JSON；需要查看时才展开，并提示其中可能含有环境变量值或请求头。OAuth access/refresh token 不进入普通配置、详情或导出文件。

### 添加、编辑、删除和导出

- 保留表单与 JSON 两种编辑方式。表单以真实 `McpServerConfig` 为准：stdio 的 `command/args/env/cwd`，HTTP 的 `url/headers/oauth.scopes`。现有演示字段 `env_vars`、`bearer_token_env_var`、`http_headers`、`env_http_headers` 不直接写入真实配置；有等价含义的字段在表单中映射到真实字段，没有等价能力的字段不继续伪装成可生效选项。保存操作改为异步，保存期间保持编辑器打开且禁用重复提交，失败时保留用户输入。
- 已有服务的名称作为稳定标识，编辑时不可改名；表单和 JSON 模式均校验此规则。需要新名称时添加新服务并移除旧服务。JSON 批量添加继续允许，但同名项报错，不覆盖现有服务。
- 现有真实配置里的 SSE 服务可以查看并通过 JSON 编辑；OAuth 按钮仍只适用于 Streamable HTTP。JSON 解析器接受真实配置支持的 SSE 类型，表单不必为 SSE 新增一套专门字段。最终保存前按真实配置结构校验 `oauth`、`headers` 及各传输类型字段，不能只沿用演示版解析器。
- 删除服务先确认，清理该名称对应的 OAuth 凭据后移除配置；凭据清理失败时保留配置并报错。若凭据已清理而配置写入失败，提示“服务配置仍在，但已退出登录”，并刷新快照。删除与退出登录的结果分别反馈。导出只包含实际全局 `mcpServers`，不混入其他全局设置或旧 `localStorage` 数据。
- 修改 HTTP 地址或认证配置后，不沿用与旧服务身份不匹配的 OAuth 凭据；界面要求重新授权。保存后刷新真实快照。

### 真实启停与生效

- `McpServerConfig` 增加可选 `enabled` 字段；缺省视为 `true`，`false` 表示停用。CLI `list/get/status --json` 与桌面快照均反映真实状态。
- 停用的服务器不在新 Session 建立 MCP 连接，不向新 Session 注册其工具。启用后，新 Session 按现有连接流程使用它。
- 对已有 Session，启停操作由 daemon 发起按服务名和配置来源的重新核对：每个受影响的 Session 对照自己已连接的旧配置与当前有效配置，停用时撤下工具并断开连接，启用时按最新配置连接并发布工具。每个活动 Session 的 Runtime 句柄即使该服务原来不存在或已停用，也须能参与这次核对。同步须覆盖现有 stdio、HTTP 和 SSE 配置；OAuth 仍仅适用于 Streamable HTTP。现有按 HTTP URL 指纹匹配的 OAuth 同步路径不能单独完成此事。Runtime 保留会话内连接状态管理职责，不成为配置的写入者。
- 新增、配置变更或删除同样触发重新核对：先撤下旧连接和工具，再根据新的有效配置决定是否连接、发布工具。会话的 MCP 工具注册表和每次运行读取的能力视图须一起更新，不能只改变底层网络连接。核对按服务名串行并用代次避免慢连接覆盖后来发生的停用、删除或改址。
- 全局配置操作只同步实际使用该全局来源的 Session。项目配置若声明了 `mcpServers`，当前合并规则会整体覆盖全局列表；这类 Session 不参与全局配置的同步，即使服务名与 URL 恰好相同。来源在 Session 建立时记录，并在重新核对时按最新有效配置确认，不靠 HTTP 指纹推断来源。
- 没有活动 Runtime 时，配置操作仍成功；详情显示“当前无活动会话”，不称为连接失败。
- 如果配置写入成功而活动 Runtime 同步失败，操作返回可识别的“已保存、同步失败”结果，页面刷新真实配置并提示重试或在新会话中生效。不能回滚用户已保存的配置来掩盖同步问题。

## 组件与数据流

```text
插件 → MCP（现有主页面布局与编辑器）
  ↓ Desktop preload / IPC
Desktop MCP 服务（快照与操作入口）
  ↓
MCP 配置应用服务 → 全局 settings.mcpServers
  ├─ OAuth 应用服务 → 独立凭据存储
  └─ Runtime 协调器 → daemon → 活动 Session 的 MCP 连接和工具
```

Desktop MCP 快照在现有 `DesktopMcpServer` 的基础上增加 `enabled` 和安全的配置摘要，供同一个管理器渲染。编辑时再通过 `getConfig(name)` 读取单项完整配置；导出时通过 `exportConfig()` 读取全局 MCP 配置。配置中的敏感值不放进列表快照、摘要和错误文案。渲染层不再自行把浏览器存储与真实快照拼接。

Desktop IPC 增加 `getConfig / exportConfig / add / update / remove / setEnabled`，保留 `snapshot / login / logout`。配置应用服务校验名称与真实配置字段，只修改全局 `mcpServers` 中的目标项并保留其他设置。所有生产环境的全局 settings 写路径要共用跨进程读改写入口：取得写锁后读取最新文件、修改并原子保存，再释放锁；Desktop 编辑还要在锁内比较打开编辑器时的目标配置。这样 CLI、桌面和其他设置写入不会互相覆盖；目标项已被 CLI 或另一窗口修改时拒绝覆盖并保留编辑内容。配置写入、凭据清理和 Runtime 同步的结果要区分，便于界面准确反馈。

现有 `McpManager` 保留页面布局和弹窗结构，改用 Desktop MCP API；去掉 `projectPath`、`localStorage` 读写及“仅本机配置、尚未连接”的固定文案。`McpSettings` 迁移完 OAuth 操作后删除；设置导航、内容分支及失效的测试同步清理。无需新增只有一个消费者的前端全局 Store。

## 边界与错误处理

- 全局配置是管理对象；项目配置或插件附带的 MCP 不由此页面编辑。Runtime 状态只聚合来源确认为全局配置的活动连接；项目覆盖或插件贡献即使同名同 URL，也不计入该全局服务的状态。无法确认来源时显示“状态不可用”，不猜测为已连接。
- 服务配置的 URL、命令或认证信息无效时，保存前给出字段错误。OAuth 登录失败只影响认证反馈；读取快照失败给出可重试状态，不能呈现为“空列表”。
- 用户编辑期间如果目标配置已被其他入口修改，保存应报告冲突并保留编辑内容，避免无提示覆盖。删除和启停也要以最新配置为准。
- 停用不删除配置或 OAuth 凭据；重新启用时沿用仍有效的凭据。删除服务才清理该服务凭据。
- 任何错误文案、列表摘要和 Runtime 失败信息都不得包含 token、Authorization Header 或完整敏感配置。

## 验收标准

1. CLI 添加的 beUI 与 Linear 在主页面出现；桌面添加的服务可由 `vk mcp list/get` 看到，切换项目不改变列表。
2. beUI 显示“无需认证”，没有授权操作；声明 OAuth 的 Linear 可在详情中完成授权、重新授权和退出登录。
3. 启停、编辑、删除真实影响新 Session；对已有 Session，停用和删除后对应工具不可再用，启用和有效配置修改可重新连接。stdio、HTTP 与 SSE 都覆盖。
4. 无 daemon、认证失败、连接失败、配置已保存但同步失败各有正确且可区分的反馈。
5. 设置页不再出现 MCP 管理入口；主页面不再读写旧演示数据。
6. 验证范围包括配置类型及持久化、应用服务和 IPC、Runtime 同步、主页面交互，以及 CLI/桌面的交叉可见性；现有 OAuth 回归测试继续通过。

## 非目标

- 不引入项目级 MCP 管理或迁移旧主页面演示数据。
- 不改变 OAuth 协议、凭据存储方式或新增授权方式。
- 不重做插件页的视觉体系，也不新增独立的 MCP 路由或前端状态框架。
