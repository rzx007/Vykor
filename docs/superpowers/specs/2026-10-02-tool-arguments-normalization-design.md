# 工具 arguments 包装统一处理 Spec

> 状态：已完成子代理审核与修订，可实施；本轮只处理已确认的参数包装问题。

## 1. 目标与证据

会话 `848b94a1-9d17-4480-a675-2df1f45422b3` 在 2026-10-02 00:30:53 的 Shell 调用（part seq 49）发送了 `{"arguments":{"arguments":{"command":"…"}}}`。JSON 合法，但现有归一化只接受一层且要求内层立即通过校验，因此返回 `invalid_input/not_started`、缺少 `command`，没有启动命令。同会话的一层包装可执行。

目标是在所有模型工具共用的执行前入口识别明确的多层包装，不在 Shell、Write、Edit 或提供商适配器里分别修补。不承诺模型永不写错；有歧义或不合法的参数继续拒绝执行。

## 2. 范围与非目标

- 扩展 `packages/core/src/engine/tool-input-schema.ts` 中现有 `normalizeToolInput(schema, input): unknown`；返回类型不变，无新增依赖或配置。
- `query-tool-preparation.ts` 继续负责校验、失败调用去重及准备权限检查；修正这些步骤的顺序。
- 不解析字符串形式的嵌套 JSON，不支持 `argument`、`params` 等猜测包装名，不推断缺少的命令、路径或内容，不合并包装内外字段。
- 不增加一套 JSON Schema 校验器；沿用现有工具校验能力。组合 schema 和 `$ref` 的包装自动处理暂不支持。
- 不改变 API 工具 JSON 解析失败的诊断、两轮纠正上限、网络重试、权限规则、工具实际实现或 Desktop 展示协议。
- 不构建 Desktop、不重启服务、不重跑原会话命令，不修改其他会话的工作区改动。

## 3. 归一化规则

1. 无 schema、非对象输入或没有明确顶层 `properties` 时，保持现有行为。数组不是对象参数。
2. 先对原输入应用现有字段别名规则，正式字段优先；严格 schema 下移除已复制的别名。若原输入已通过校验，直接采用它，不再拆包装。
3. schema 声明了顶层 `arguments`，或顶层含 `anyOf`、`oneOf`、`allOf`、`$ref` 时，不自动拆包装。保留业务参数，不遍历 schema 推断含义。
4. 只遍历自身可枚举字段恰好为 `arguments` 且该字段值为非数组对象的包装；每一层都遵守这条规则，最多拆 8 层。循环引用也必须有限返回。
5. 每拆一层，先应用同一套字段别名规则，再按工具 schema 校验。遇到第一份合法候选即返回；不继续拆合法业务输入。候选的命令字符串、路径和内容不改写。
6. 包装旁有其他字段时停止遍历，不丢弃字段。找不到合法候选、超出上限、候选为数组/字符串或存在循环时，返回原输入的别名归一化结果，由执行前校验拒绝不合法调用。不得把未通过校验的半拆结果作为可执行参数。
7. 不修改原始输入对象或任何内层对象，不新增敏感参数日志。已发出的原始调用事件/持久记录不改写；后续权限检查与工具执行使用同一份有效参数。现有准备阶段会替换 `toolUse.input`，内存历史共享这个调用对象；继续沿用，不新增历史副本或持久字段。

## 4. 执行顺序与防重复执行

运行入口为 `QueryEngine` 的工具执行流程：先检查 JSON 解析标记及工具是否存在，再归一化并校验参数，再查询失败调用记忆，最后进入权限检查、hook 和工具执行。

`ToolFailureMemory` 已按工具名称和输入保存失败记录；查询与写入都必须使用归一化参数。此前已记录失败、工具名称与全部有效参数相同且没有新证据时，只改变包装层数不能绕过保护。查询失败记忆只在校验成功后进行；重复不合法参数仍返回 `invalid_input/not_started`，不进入权限或执行。不增加同一批次尚未失败调用的去重逻辑。

保留现有只读/可安全重试工具规则，以及通过新证据解除失败保护的行为。本次不扩大可自动重试的工具集合。

## 5. 验收用例

| 输入/条件 | 预期 |
|---|---|
| 直接合法参数，以及原输入不合法、拆一层后合法的包装 | 保留直接参数，包装归一化后成功 |
| 两层及 8 层 Shell 包装 | 得到原始 `command`，校验通过 |
| 原输入不合法的 9 层 Shell 包装、循环引用 | `normalizeToolInput` 有限返回；不能得到合法候选，Shell 校验拒绝 |
| 多层 Write，叶子为 `path`/`contents` | 复用别名规则，得到 `file_path`/`content` |
| 候选缺少 command、command 为数字、arguments 为数组或 JSON 字符串 | 拒绝，不猜测或转换类型 |
| 外层或中间层含额外字段 | 不丢字段，不跨过该层继续拆 |
| 工具正式参数含 arguments；组合 schema；原输入已合法 | 不拆业务输入 |
| 权限拒绝归一化后的命令 | 权限看到实际 command，工具执行次数为 0 |
| 非法包装 | 权限检查次数与工具执行次数均为 0 |
| 已记录失败、没有新证据、同一有效参数只改变包装层数 | 失败记忆命中，实际执行次数仍为 1 |

测试采用非破坏性命令和内存工具，不执行用户会话中的删除或截图命令；不得只检查源码字符串。

8 层上限只限制包装自动处理；原输入本来合法时按第 3 节第 2 条保留。循环对象不是模型 JSON 协议可产生的数据，循环验收仅约束归一化函数，不扩展失败签名序列化器的范围。

对于没有必填字段且允许额外字段的 schema，包装对象本身可能合法。新规则有意保留它，而不是沿用旧规则继续拆一层，避免改变合法业务输入。
