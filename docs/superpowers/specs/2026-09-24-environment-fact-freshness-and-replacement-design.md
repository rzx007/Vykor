# 环境事实时效与旧值替换设计

> 状态：设计待审。适用于当前项目的 `local_rules/projects/<项目>-<hash>/facts.json`，不是项目长期语义记忆 `/memory`。

## 目标与现状

环境事实会随服务器、路径和版本变化。系统应让用户看出一条事实有多旧，并能依据明确指令取代旧值，同时不误删另一台服务器的信息。

当前实现从有 ID 和时间的用户消息中抽取事实，按 `type:value` 去重，写入 `facts.json`；提示词从此文件生成，不读取 `rules.md` 缓存。提示词已显示最近一次用户消息的观察日期和使用前核验提醒，但这个日期**不是**工具核验时间。会话每次成功收尾都会重新扫描历史消息，因此只删除旧事实，下轮会把它重新写入。

## 选择及其边界

采用“软提醒 + 精确选中旧键 + 留存取代状态”。不按固定天数自动删除，也不因为新旧值同为 IP 或文本相似就认定属于同一服务。

其他两种做法不采用：按时间自动过期会让仍有效但长期未提及的地址消失；按类型或近似度自动替换会混淆多台真实服务器。将来若项目配置已有稳定服务 ID，可以在单独阶段加入基于该 ID 的自动更新；首版不假定这个标识存在。

## 数据含义

每条事实保留现有的 `key`、`type`、`value`、`confidence` 和消息来源。`observedAt` 表示最近一次从用户消息看到该值，不能改称“已核验”。以后只有确实读取配置、执行探测并保存可回查证据时，才允许记录 `verifiedAt` 和验证来源；本阶段不伪造这两个字段，也不新增定时核验任务。

在同一个 `facts.json` 中给被取代的旧记录保存状态 `superseded`、新记录键、操作时间和操作 ID。新记录保存明确替换操作的来源：操作 ID、时间，以及有则保存当前会话 ID。来源校验接受“已有的用户消息 ID + 时间”或“显式替换操作 ID + 时间”两种真实来源，不能把一个没有落入会话历史的斜杠命令伪装成用户消息 ID。旧记录与新记录共同保存旧键、新键和时间，便于解释“谁取代了谁”。文件是单一权威状态，`rules.md` 仍只是可重建的展示缓存。

## 用户入口与执行流程

提供 `/facts list` 和 `/facts replace <旧键> => <新值>`，展示完整键、值、观察日期、状态和来源；对应 daemon 接口按当前项目 cwd 隔离，与 `/memory` 区分。替换操作接收**准确旧键**和同类型的新值，例如 `ssh_host:ops@10.1.2.3` → `ops@10.1.2.4`。用户明确指定旧键就是授权替换，不再为同一决定重复弹确认框。使用 `=>` 分隔，让值中含空格的类型也能表达。

操作依次执行：确认项目作用域；取得项目写入锁；读取并校验事实文件；确认旧键存在且有效；校验新值符合该事实类型且未命中明显凭据检测；确认目标新键没有冲突；将旧记录标为取代并加入新记录；一次性原子写入 `facts.json`；再更新 `rules.md` 并让后续提示词读取新状态。用户可以通过列表查看取代关系。找不到旧键、文件损坏、新值无效或目标键冲突时，返回明确错误，保持文件不变。相同操作重复提交应返回已有结果，不生成第二次替换。

替换只作用于**选中的键**。例如 `ssh_host:ops@10.1.2.3` 与 `ip_address:10.1.2.3` 是两条记录；系统若发现旧地址仍出现在其他有效记录，应在结果中列出那些准确键，提醒用户分别判断，不能静默把它们也改成新地址。后续可减少同一条消息中 SSH 主机与裸 IP 的重复抽取，但不把这个优化当成自动判定两个独立消息属于同一服务的证据。

## 读取和再次抽取

提示词只注入有效、来源合格、未命中凭据检查的事实；列表仍可显示被取代的旧记录。每次从历史消息重新抽取时，若键已被取代，跳过它，不覆盖取代状态。即使旧消息再次进入扫描、进程重启或新会话开始，旧键也不得复活。若未来要重新启用旧地址，必须有新的明确操作，而不能靠重复扫描旧对话。

观察日期继续作为软提醒，不能仅因超过某个天数改变有效状态。执行任务时，如事实关系到连接、部署或数据写入，Agent 仍应核对当前配置或实际环境；提示文字不等于已经完成核验。

## 验收

1. 一条有效旧记录被精确指定后，新值出现在下一轮提示词，旧值不出现；重启和重新扫描旧消息后仍如此。
2. 同类型但未选中的其他服务器保持不变；如果旧地址还出现在其他有效键中，结果明确列出这些键。
3. 旧键不存在、文件损坏、类型不符、凭据风险或目标键冲突时不修改 `facts.json`。
4. 重复提交同一替换不产生重复记录；`rules.md` 更新失败不使提示词读回旧值，并向调用方报告缓存更新问题。
5. 列表能解释观察来源与替换操作来源；手动替换不会被显示为工具核验。

## 本阶段不做

不做固定 TTL、后台巡检、推断服务身份、跨项目替换、自动读取工具输出晋升为事实，也不改 `/memory` 的语义记忆机制。这些只有在真实使用案例证明需要时再独立设计。
