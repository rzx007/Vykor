# Agent 日常续做与交付闭环

状态：实现与提交前复核完成，两个边界问题已修复并回归；提交和推送结果以 Git 记录及最终回复为准。

## A 本轮范围

用户要求落实架构评审“最值得关注的四点”中的前三点。
第四点的参数入口、查询搬运和存储绑定简化由另一对话处理。
本轮在隔离工作树实施，先提交并推送功能分支 `codex/agent-daily-continuity`。
用户随后明确要求合并 main 后推送，整合时保留主分支已有简化和测试改动。
不实现跨进程执行恢复、持久审批、新调度器或新数据库表。

## B 可信只读与失败语义

Node 只为实际创建的内置 Read、Glob、Grep 及 ToolResult 登记只读身份。
Core 使用定义身份和原执行函数核验捕获后的绑定。
Server 还要求来源是 builtin，不能凭工具名或 readOnlyHint 放行。
同名覆盖、换掉执行函数和外部工具继续采用原有保守分类。
daemon 的附件 Read 包装先核验基础定义，再为宿主实际创建的包装登记身份。

发布包把 Core 实现打入 Runtime，不能用外部 Core 副本的私有表核验这些工具。
Server 的登记与识别函数统一从同一 Runtime 包导入。
实际 dist 回归同时检查捕获身份、宿主包装和伪装拒绝，不引入全局状态。

读取已发生但文件不存在或读取失败，返回 completed 与 isError。
参数错误、访问策略拒绝和执行前取消仍保留 not_started。
只读失败不会制造未知写入，也不解除真实未知写入的阻断。

```flow
Node 实际内置工具 -> Core 身份登记: 保存定义身份与执行函数
Core 身份登记 -> Server 操作分类: 校验最终绑定及 builtin 来源
Server 操作分类 -> S1 操作记录: 只读或默认保守分类
S1 操作记录 -> 模型: 返回真实完成情况与错误
```

## C 未知操作的人工核对入口

增加宿主 HTTP 与客户端入口，沿用现有 daemon 认证。
模型工具列表不增加核对工具。
入口列出同根会话树的未知操作，也包含原 Run 已结束的 dispatching。
列表返回身份、状态和版本，不复制正文。
按操作 ID 查看时再返回有界的输入和结果预览。

dispatching 不能直接人工解除。
列表、详情和拒绝响应提供恢复提示：先排查存储失败并等待实际调用结束。
确认旧 daemon 停止后重启，经过既有启动恢复再核对。

人工提交 operationId、expectedRevision、outcome 与非空 evidence。
applied 若要转为 confirmed，还必须提供经核对的 completed 结果。
没有可确认结果时只记录核对证据，保持 unknown。
not_applied 可以解除该操作的未知状态，但不会自动执行它。
unknown 只追加证据，继续阻断。

核对必须检查 owner、服务就绪、会话归属及原 Run 已终止。
跨根会话、活跃 Run、旧版本和缺少证据都拒绝。

Run 超时或取消不等于实际调用结束。宿主在本进程跟踪实际调用的 Promise；结束前只允许追加 unknown 证据，拒绝 applied 和 not_applied。
实际调用结束后清理跟踪，不新增持久恢复机制。同一 activeAttempt 的合法迟到完成可以修正先前 not_applied 的结论，保留人工核对历史；旧 Attempt 不得覆盖新 Attempt。

活跃父会话仍可核对已归档子会话的历史操作，不能因归档让父树永久无法处理。
复用现有 reconcile，保留操作和 Attempt 的核对历史。
原始未知回执不被普通模型文本替换。

入口是 HTTP 和客户端方法，本轮没有新增桌面核对按钮。
旧自定义宿主可以不提供新服务，此时新路由返回 404，其他路由保持可用。

## D 日常重开续做

复用 SQLite 历史、现有压缩摘要、Goal 与结果补读。
重开后先加载历史，再接受新输入；不重发原始任务。
测试检查目标、最新约束、已确认结果和产物引用能进入下一轮上下文。
测试同时检查未知写入重开后仍阻断危险操作，可信读取仍能核查现状。

现有原文摘录需要保留工具结果的 executionState 和 isError。
摘录同时保留已有的完整结果引用；没有文本正文时也能携带引用。
这些字段表示历史执行状态，不是新权限或当前外部状态。

压缩提示要求区分已确认、仅计划、尚未执行和结果未知。
继续执行前仍须检查可能变化的文件与外部事实。
模型仍可能误判，验收只证明已覆盖场景的行为。

## E 结构化交付的真实消费场景

现有自动代码评审改为消费系统子 Agent 的结构化交付回执。
宿主为本次系统子 Agent 显式提供 outputContract。
合同不放进可序列化的 SpawnInput，也不从父 Agent 自动继承。
系统子 Agent 仍没有普通工具权限，仅有内部 SubmitResult。

合同数据沿用评审的 version、verdict、summary 与 findings。
schema 检查格式，宿主核验器继续检查引用文件、长度及结论的一致性。
完整评审使用 done，未完成的评审使用 partial。
核验通过表示报告符合约束；合法的 fail 或 partial 也可以通过核验。

消费者要求真实回执和通过的宿主核验，不能从普通输出文字推断通过。
原有风险分级、用户抢占、超时和截断处理规则保持生效。

## F 状态组合规则

| 状态 | 含义和控制者 |
|---|---|
| Run.completed | Kernel 确认本轮正常结束 |
| delivery.status | 本次交付报告的进展 |
| validation | 数据格式符合合同 |
| verification | 宿主对报告的约束检查通过 |
| Goal 状态 | Goal 服务根据显式 GoalUpdate、预算和等待规则决定 |

done 不自动完成 Goal，waiting 不自动暂停 Goal。
GoalUpdate 不得用交付格式通过代替完成检查。
若同一轮报告 partial、blocked 或 waiting，却显式要求完成 Goal，宿主暂停并说明矛盾。
其他情况继续由显式 GoalUpdate 控制，不根据文字猜测状态。
自动评审只消费评审报告，不改变被评审父任务的 Goal。
Run 终态没有真实交付事件时，会清空调用方 metadata.delivery 中的同名声明。

## H 两处局部整理

结构化评审的 data 已是对象，直接使用共同校验器，不再转成文本后重新解析。
原文本入口解析一次后复用同一校验器。
字节数、路径、条数、结论和交付状态限制，以及宿主核验与接收端复核继续保留。

实际调用登记只读取当前派发是否匹配，不复制完整输入或结果。
查询放在现有操作仓库，owner 和实际调用存活保护继续由原服务负责。
不新增查询服务或通用校验框架。
