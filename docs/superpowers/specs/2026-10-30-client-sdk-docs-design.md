# Vykor Client SDK 文档站设计

> 状态：已实现并通过最终复验与独立复审；本轮未提交代码或部署。具体验证结果见[实现计划](../plans/2026-10-30-client-sdk-docs.md)。

## 目标与入口

在 `apps/client-docs` 增加私有工作区包 `@vykor/client-docs`。它面向安装 `@rzx/client` 的开发者，提供中文指南、可检查的 TypeScript 示例和从公开声明生成的 API 参考。默认连接已有 daemon，本机服务管理作为可选章节。

## 职责与内容

- Starlight 管页面布局、导航、目录、主题和构建后的 Pagefind 搜索；站点输出为静态文件，不需要常驻服务。
- TypeDoc 只读取 SDK 构建得到的 `dist/index.d.ts` 与 `dist/service.d.ts`；教程说明运行流程，API 参考说明参数、类型与返回结果。
- 可运行示例放 `examples/`，站点直接展示同一份源码；示例必须通过针对 SDK 发布声明的 TypeScript 检查，不在构建时连接 daemon。
- 指南覆盖安装连接、Session/Input/Run 概念、任务提交与权限、快照和事件恢复、文件、附件和 Jobs、结构化交付、错误与兼容性、可选本机服务。
- 公开站只覆盖两个公开入口。内部应用接口、凭据和仓库维护流程不进入站点。
- 保留现有仓库文档的维护用途，增加新站入口，避免内部相对源码链接进入公开页面。

## 构建与部署

站点具有独立开发、类型检查、示例检查、构建和构建产物检查命令。文档构建工具的 Node 要求与 SDK 的运行时要求分别声明。

仓库已有 GitHub Pages 官网。沿用同一发布流程，把 SDK 文档放在官网的 `client-sdk/` 子路径；根路径和自定义部署路径都须正确生成导航、API 链接与搜索资源。仅准备 workflow，不在本轮触发远端发布。

## 验收

1. SDK 和站点可从干净依赖安装构建；TypeDoc 参考覆盖主入口与 Node service 入口。
2. 示例通过类型检查，Markdown/MDX 页面和站点配置通过 Astro 检查。
3. 构建产物包含指南、参考页与搜索索引，站内链接在根路径和子路径部署时有效。
4. 新目录有 README，仓库文档与发布流程入口同步；现有官网保留。
5. 运行文档检查与 retired-ui 检查，并对最终改动做独立 review。
