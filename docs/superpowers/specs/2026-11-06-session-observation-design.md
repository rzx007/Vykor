# Vykor 跨会话进度观察设计

2026-11-06。经两位子代理独立评审后修订。

## 用户入口

用户在 Desktop 打开目标会话，通过「更多 → 复制 → 复制会话 ID」取得 ID。回到当前会话，把下面两行作为一条排队消息发出。TUI、CLI 和 HTTP Client SDK（`@rzx/client`）的普通提示入口也接受相同文本。

```text
observe-session <目标会话 ID>
等这一轮测试结束，再核对当前项目的调用。
```

后台服务仅在普通客户端提交新消息时解释首行指令。首个输入项须为文本，指令须占完整第一行，支持 CRLF。保留提交的原文。重试使用相同的输入 ID 时，正文和授权意图都必须一致。格式错误、将消息插入正在运行的轮次、自身作为目标，均返回明确错误。排队消息带授权时继续按队列运行，「立即发送」会给出提示。现有「历史对话」引用仍用于阅读历史内容。

## 授权与目标

- 来源和目标须是同一后台服务上仍可用的持久根会话。根会话没有父会话。子 Agent、分叉、临时会话和渠道绑定会话超出首版范围。渠道归属查实际渠道绑定记录。
- 普通提示的 HTTP 入口解析指令，通过宿主专用接纳参数传入目标 ID。新排队 Run 与输入一起写入时保存授权。`Run` 指一次输入触发的一轮执行。原始运行以外的编辑、重放、旧输入恢复和自动续跑沿用各自的入口。通用元数据保留字段阻止外部写入同名授权。
- 接纳时优先选目标正在执行的 Run，其次选最早排队的 Run，再选最近创建的已结束 Run。此时没有任何 Run，则固定为 `idle`。授权保存目标会话 ID、选中 Run ID 或空值，以及当前事件序号。查询时用创建事件检查目标会话或选中的 Run 有没有在授权后用同一个 ID 重新创建。此前已有的会话仍可观察。
- 当前 Run 启动时按需注入 `SessionObserve`，沿用 Goal 工具已有的运行内注入机制。显式首行指令授权这项宿主只读操作，工具仍须通过当前运行的允许和拒绝规则。同名自定义工具在观察运行中让位给内置观察工具。工具从宿主上下文核对调用者会话、运行及原始输入，并在每次返回前重读当前授权和目标。运行外的后续轮次只能通过新指令授权。

具有后台服务访问权的普通客户端可以提交首行指令。该入口沿用后台服务现有的客户端信任边界，工具执行仍须核对本轮授权。

## 返回值与等待

工具参数只有 `timeoutMs`。默认立即返回，可等待 0 至 30 秒，并给工具自身截止时间留出收尾时间。返回目标会话 ID、固定的运行 ID、状态、更新时间、待处理类别和是否超时。运行状态沿用 `pending`、`running`、`completed`、`failed`、`interrupted`。返回类别可以包含 `approval` 和 `question`。类别来自与所选 Run 直接关联、确实需要人处理的请求。父会话收到的子任务审批继续由其原有入口处理。状态结果只包含这些字段。

后台服务从 SQLite 记录读取快照。先记事件序号，再读快照。需要等待时，从该序号订阅现有事件流。收到目标状态、审批或删除事件时重读快照。目标运行结束或出现人工待办时返回。到截止时再读一次，仍在运行或排队时返回 `timedOut: true`。超时和取消只结束观察。事件流异常会返回可重试的错误，并释放订阅。

## 验收

- 真实普通提示入口建立授权，真实 daemon 在这轮向模型提供 `SessionObserve`。
- 伪造保留字段、非普通入口、会话重建、插入式发送、旧输入恢复与重放均无法借用授权。
- 目标开启下一轮时，返回值仍指向接纳时选中的 Run。固定为空的观察返回 `idle`。
- 运行结束、真实审批或提问、超时、取消和订阅建立前的变化均有定向测试。
