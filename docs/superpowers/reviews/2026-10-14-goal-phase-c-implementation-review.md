## 1. 实际流程与责任

- 创建在同一事务保存 Goal、用户输入、版本与准备批次，提交后走原队列。准备最多 2 次实际模型尝试、4 次 builtin 只读调查、每次输出 1024 Token；重试与压缩也计入。禁用副作用工具、子任务、hooks、自动审核及后置记忆维护。
- 准备建议成功后保存并交付整批工具结果，正常结束 Run，不调用模型收尾。宿主核对 completed、版本、批次、来源、预算和用户工作，再冻结正式条件并保存唯一 initial。被预算或用户工作挡住时保留 ready，普通明确继续无需再准备；重新整理是显式新批次。
- 版本文件只存取定义；GoalRead 只读当次绑定快照。refine/pivot 先停旧版本工作，再保存用户变更与新版本；理由、来源、替换关系均可追溯。状态、验收、预算与总量不改写冻结定义。
- 证据读取器只核对已有 Run/消息/Part，文件摘要由原工具在同次读写中生成。Core 只提升捕获的可信 builtin 回执，插件自报字段不能入库为宿主证据。完成检查先核对完整集合和客观证据，用户只验收明确指定的主观项。
- 进展计算是纯函数，使用已核实要求转换、交付物变化与外部终态；已见状态往返、日志和 blockerKey 更换不归零。三轮无可信推进暂停；连续真实阻塞且没有可执行路线时 blocked。宿主等待与验收等待不累计轮。

仅新增四份生产文件与一张版本表。Desktop 复用原 Banner、Composer、动作、GET 与 B 的 revision/usage.seq 合并，不新增页面或预览。

## 2. 集中审核与修订

一名只读审核者 `goal_c_implementation_review` 集中核对当前实现与必要源码，不继承整段聊天，不跑测试或再拆代理。

| 审核问题 | 修订 |
| --- | --- |
| P1：缺文件或删除回执可冒充已交付 | missing 不支持 artifact_review 完成；删除仍可提供进展事实，同轮被覆盖的旧证据不能支持完成 |
| P2：受阻目标的说明被协议当作问答 | 普通 resume 可独立提交变化说明；只有当前问答/confirm 强制问题与版本身份 |
| P2：次数耗尽挡住主观验收 | confirm 不检查或增加自动次数，只对指定项验收；准备也不消耗自动执行次数 |
| P2：澄清/重新整理丢失替换授权 | 按当前版本的原变更请求读取授权，后续准备批次保留该来源 |
| P2：普通用户工作使 ready 卡在 active | 保存 ready 后暂停并清 currentRun，用户工作结束后明确继续冻结 |
| P2：正文相同的新附件/输入被吞掉 | 带新附件或非原正文输入时不走 noChange，保存来源并重新准备 |

同一审核者定点复核六处修订及必要连接，确认原触发条件均已处理，没有剩余实质缺口；没有再次全文重审、运行测试或修改文件。主代理统一检查下列结果后标记 C 交付。
