# S1 B 实现与验收记录

> 状态：实现与独立 review 已完成，2026-10-28。未迁移用户实际数据库；提交和合并状态以 Git 记录为准。

按用户选择的 [B 方案](../specs/2026-10-28-s1-simplification-design.md)，移除整个 S1 操作控制层，保留普通权限、真实调用收尾和独立长结果补读。实施过程见[实施计划](../plans/2026-10-28-s1-remove-control.md)。

## 实现结果

正常执行路径为：检查普通权限及当前归属 → 执行工具 → 保存完整返回正文 → 截断展示并交给模型。执行前不创建持久操作记录，也不再查询历史 unknown 是否阻止新调用。

| 内容 | 结果 |
| --- | --- |
| Operation/Attempt Gate、票据、授权状态、结果复用和通用防重放 | 已删除 |
| 整树/同会话封锁、保存失败封锁集合、只读例外、人工核对、迟到审计 | 已删除 |
| 普通权限、审批、沙箱、当前 owner/Run/输入/工作目录/最终工具绑定检查 | 保留；模型、手动、嵌套和 child 路径共用 |
| 实际调用登记、超时/取消、结束等待和资源释放 | 保留；超时不代表实际调用结束 |
| 完整结果保存及 list/read/search | 独立 `tool_result` 表，宿主生成 UUID 引用，按会话与当前工具来源授权 |
| 旧记录和引用 | 不导入、不映射、不双读；迁移删除三张旧 S1 表，保留其他数据 |
| 客户端契约 | 协议递增到 7，移除旧 review API/类型和阻断设置入口 |

关键实现入口：[Core 工具执行](../../../packages/core/src/engine/tools/checked-tool-execution.ts)、[宿主派发检查](../../../packages/server/src/application/session/execution/tool-dispatch-check.ts)、[结果存储](../../../packages/services/src/tool-results/tool-result-repository.ts)。

## 合并前的补充检查

集成基线更新为 `d2279368`（子代理预算反馈与结果交付），S1 实现提交为 `0dcf01d4`。两处文档冲突合并保留协议 7、正常权限与真实收尾说明，以及主分支新增的预算反馈说明。

扩大 Core 回归时，发现部分旧测试仍把工具已返回的错误认作未知，或信任已调用工具自报的 `not_started`。测试改为分别验证普通返回错误为 `completed + isError`、外层转发已执行时不能证明未执行，并保留正文、权限拒绝及实际目标零调用断言。

补充发现并修复一个 P2 问题：同一批次搜索加载 MCP 工具后，外层转发失败可能仍写入当前 Run 的重复失败记录，使下一次合法调用被挡住。现在只根据宿主在当前批次记录的未加载目标证据跳过该失败记录；实际 MCP 转发工具也将不可见目标交给宿主拒绝，确保真实路径产生该证据。可见的非 MCP 来源、缺少注册表或受检调用入口仍被拒绝，不存在的目标及实际未知调用仍按原有重复失败规则处理。

真实转发集成回归先观察到 2 项失败，再验证允许、权限拒绝、同名非 MCP 来源及不存在目标共 5 项通过。独立 reviewer 复核全部补丁，并独立验证 6 条内存边界，结论为 APPROVED，没有未解决的重要发现。
