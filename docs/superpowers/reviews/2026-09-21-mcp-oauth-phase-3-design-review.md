## 2026-09-28 范围收缩复审

用户要求防止过度设计、控制范围、职责清晰，并暂缓 OS Keyring + file fallback。两位子代理分别审核范围复杂度和存储并发依赖；主线程修订设计后同步计划，再交原审查者复审。

| 发现 | 修订结果 |
|---|---|
| 暂缓的存储项目仍占一整批交付 | 删除 Keyring、AES-GCM、后端选择、专用状态、原生打包及平台验收；不预留接口 |
| 删除存储批次会连带删除退出保护 | 单独保留最小明文 v2：现有 servers + logoutEpochs；不保留 backend 包装 |
| 旧进程可能绕过退出计数 | 保留版本升级，使旧 reader 拒绝 v2；同配置目录客户端一起更新 |
| epoch 占位值与消费者分批可能形成虚假保护 | 计划任务 3、5 联合验收；CAS 未命中不写入、不迁移 |
| Desktop 本地回退增加一条授权路径 | 只接入现有 daemon 主路径；CLI 离线流程仍保留 |
| 原有验收、阶段边界和任务引用未同步 | 计划收缩至 9 个任务、两个批次，更新第一阶段后续边界 |

保留刷新分类、资源绑定、取消提交边界、退出计数、请求幂等、实例识别与有界内存状态；这些处理已有并发和失败场景，不建设通用任务或事件框架。agent-runtime 不接管授权策略和凭据管理。

两位子代理复审均未报告剩余阻断项。非阻断建议已采纳：不原地修改 current；交接按交付提交而非强制每任务一提交；删除本轮 Keyring 验收歧义。文档链接/路径检查和 diff 空白检查均通过；本轮未改业务代码，未运行业务测试。

下方保留历史审核记录，其中主密钥、加密与 unavailable 等结论已随 Keyring 暂缓，不是当前实施要求；当前范围以最新设计与计划为准。

用户随后补充 Desktop MCP 已迁至“主页 → 插件 → MCP tab”。主线程核对 `plugin-page.tsx` 的挂载及 `mcp-manager.tsx` 的登录/退出处理后，更新设计入口、计划任务 8 的组件和测试路径；不恢复旧设置页，也不扩大到插件导航重构。此项为路径勘误，未重新启动子代理审核。

## 第一轮发现及修订

| 问题 | 修订 |
|---|---|
| metadata 精确匹配被 URL 归一化/父路径包含混淆 | 单独保存 expectedResource 字符串；另做 endpoint origin/路径段包含检查 |
| 取消排在等待浏览器的整个登录之后会被阻塞 | 队列外先 abort，锁内提交前再校验 |
| 跨进程 logout 后迟到登录可复活记录 | v2 保存 logoutEpochs，空删除同样递增，提交持锁比较 |
| requestId 恢复未区分 daemon 重启 | 创建和恢复绑定 oauthInstanceId，新实例拒绝旧请求 |
| 缓存满额可能提前淘汰未过期幂等结果 | 先查幂等记录，未过期容量满时拒绝新建 |
| “从未用过 Keyring”无法从空文件证明 | 仅当前无密文且 Keyring 明确 missing 时允许创建主密钥 |
| Desktop 连接服务可能接管/关闭 daemon | 接管在操作创建前完成，创建后固定拥有者，main 持有敏感数据 |
| 存储锁定没有准确状态 | 新增 authStatus unavailable，逐服务报告错误 |
| 登录等待期间修改配置可能提交过时候选 | 提交锁内复核授权配置快照 |
| 所有失败回调都不消费会使合法拒绝悬挂 | 无效输入不消费；有效 access_denied 消费并结束 |
| CAS miss 的现有 update 仍会写文件与增 revision | 明确 no-op 写入语义和实际落盘版本的使用快照 |

## 第二轮结论

- 协议/并发审查者确认 resource、取消、配置复核、CAS 与 callback 消费问题关闭。
- 存储/接口审查者确认跨进程 epoch、实例恢复、缓存限额、主密钥创建、Desktop 寿命和存储状态问题关闭。
- 非阻断建议“创建请求示例补 oauthInstanceId”已同步写入设计。

主线程随后进行计划覆盖检查，明确认证快照查询路由和授权 URL 就绪的安全事件，避免客户端收到 pending 后无法取得 URL；这些是已有状态/事件职责的具体接线。
