# Goal 收缩实施与集中审查

2026-10-15。依据：[收缩规格](../specs/2026-10-14-goal-reliability-and-budget-design.md)和[精简计划](../plans/2026-10-15-goal-simplification.md)。

## 实现结果

- 创建目标直接进入正常执行，普通回合无需 GoalUpdate 即可续跑。
- GoalRead 只读当前目标；GoalUpdate 只接收状态、问题或具体任务等待。请求先保存到当前 Run，正常终态再次核对身份、版本、状态及限制后才生效，保留最终回复。
- 删除准备批次、冻结条件、来源引用、每轮评估、证据裁决和进展评分；保留用户优先、真实任务等待、请求/派发去重与原用量账本。
- 编辑保留保存、取消和草稿恢复，移除分类/原因/替换项；旧问题、批准关联与任务观察失效，暂停或受阻的目标不会因编辑自动恢复。
- 0007 只丢弃旧 Goal 自有数据，重建最小五表、删除评估表；不转换或接管旧目标，保留会话、输入、Run、消息和工具历史。

## 审查修订

一名独立子代理集中审核实际调用链、状态竞争、等待、预算和迁移范围，发现“waiting_user + approval 在批准后缺少继续入口”。已在目标栏补“批准后继续”，沿用现有 resume；服务端仍要求同会话且 approved，pending/denied 不得恢复。

主代理同时发现通用执行限制会误拦当前 completed 根 Run 的既有维护工作，已只对仍绑定当前 active Goal/版本的根 Run 放行原维护及后续 child/run/tool 检查；结算后旧 Run 被拒绝，GoalUpdate 仍只接受 running。未增加维护队列或新控制器。

子代理定点复核以上两处，确认闭合，无新增必须修问题。计划已要求的“暂停保存失败仍尝试中断”也已修复，两条中断入口有针对性回归。
