# 长结果补读与结构化交付验收

> 状态：已实施并完成本轮限定范围验证；独立审查和合并验证发现的问题已修复，源代码通过 `main` 交付。

依据：[实施计划](../plans/2026-10-26-result-reading-and-structured-delivery.md)和[原方案](../specs/2026-10-26-agent-core-capability-completion-design.md#h1-p1-的明确范围)。基线为 `b38f4735`，分支为 `codex/result-reading-and-structured-delivery`。主工作区的其他改动未纳入本轮。

## 已接入的行为

长工具结果在模型截断前保留引用。内置 `ToolResult` 可列举、分页和字面检索，历史压缩或新 Run 后仍能找回当前有权读取的结果。默认 Node SDK 使用有容量上限的内存存储；daemon 直接读取 S1 保存的操作结果，真实 SQLite 关闭重开后仍可读取超过 300 KB 的结果尾部。没有新增数据库表或第二份结果正文。

Server 每次读取检查当前 owner、精确会话、运行状态、取消信号、工作目录、输入归属、权限版本以及实际工具来源。结果存储在本轮最终工具集合确定后绑定，单次提交缩小工具范围时，历史结果访问同步缩小；手动工具入口采用相同规则。父子和兄弟会话不能互读；未知、未开始或缺少完成事实的结果不生成完整引用。查询工具自身的输出不递归成为新引用，同名替代工具不能取得内置查询工具的只读承诺。相同 builtin 来源内部的可信宿主替换属于同一来源授权范围，历史读取不比较进程内函数版本。

宿主通过 `outputContract` 配置数据格式和可选核验器，模型单独调用 `SubmitResult`。结构或宿主核验失败发生在 S1 实际派发之前，不形成假工具尝试或未知写入；模型可按原有有界纠错机制修改提交。合同存在却没有有效提交时明确失败。成功结果通过 `AgentRunResult.delivery`、`AgentChildResult.delivery`、完成事件和已有 Run metadata 返回，纯文本输出保留。默认子 Agent 不继承根输出合同，显式子合同已通过真实 Kernel 验证。

公开 Prompt/Client 输入增加 `outputSchema`，准入前固定并校验，参与同一 ID 的内容比较。请求不能用 `steer` 或活跃子会话补充输入改变合同；重放保留原合同。Client 在发送前检查 `features.structuredDelivery >= 1`，旧服务不能静默忽略这项要求。HTTP 不传函数，未配置可信业务核验时回执保持 `not_requested`。

## 合并前复审

本轮由安全、架构和四角度反向测试分别复审。安全与架构没有新的阻塞项；反向测试复现两个 P2，均已修复并再次复核，没有保留未解决的问题。

1. 运行取消时，已撤销的归档能力会抛错，原先阻断了同批已结算工具的结束事件。现在取消后不再申请新引用，仍按真实执行状态交付已结算结果；活跃运行的正文保存失败和 S1 持久化失败仍明确抛出。四个取消回归先失败后通过，并保留容量失败检查。
2. 结构化业务数据中的 `path` 与允许的额外字段 `file_path` 被误认作工具参数别名。现在只对工具顶层参数推断别名，嵌套对象/数组项仍执行类型、必填字段和额外字段检查。实际 Kernel 提交回归先失败后通过，原顶层别名冲突检查保留。

合并前新运行的证据：运行时完整测试 787 项通过、9 项按原配置跳过，Kernel 边界 8 项通过；修复后 Core 完整测试 485 项通过，工具参数定向 68 项和 Kernel 交付 23 项通过。最终源码的 SDK 构建与独立打包消费检查退出 0。额外真实两轮撤权探针 2 项通过，被移除或禁止的工具不在最终工具集合中，旧引用列举和直接读取都被拒绝。

与主分支 `8855f31c` 的回归测试合并后，实际 daemon 子运行还暴露了一处启动顺序问题：结果存储绑定先于子运行记录持久化。现已改为等待可靠 `run.started` 投影完成后绑定，再确认启动和执行模型；结果服务的 owner、会话、运行和权限检查没有放宽。新增异步投影/绑定用例先失败后通过，Kernel 定向 27 项通过，真实子 Agent 附件用例继续验证会话隔离。原测试中的 S1 原始结果断言与假模型 JSON 读取也按新增引用信息同步，未删除原生写入、未知结果或权限隔离检查。

## 实施边界

- 本轮不实现 S2 执行检查点、原执行位置续跑或 Workflow 恢复；S2 撤回文档保留。
- 单 Agent 持久审批仍需重建待执行操作和重新授权，本轮不作为小改纳入。
- SDK 内存历史有容量上限，驱逐或 Agent 关闭后不承诺保留；daemon 随会话删除和权限撤销失效。
- 分页偏移使用 UTF-16 位置，读取最多 16000 字符；内置工具实际 JSON 响应最多 12000 字符。宿主自定义更小的内联预算仍生效，可能继续截断查询响应。
- Schema 使用现有校验器的明确子集，不支持的关键字在配置时拒绝；不提供完整 JSON Schema 或模型原生输出约束。
- `done` 是 Agent 报告的进展；只有可信核验器通过才标记 `verification: passed`。Run 正常结束不会自动完成 Goal。
- 验证平台为 Windows。未在 Linux/macOS 执行本轮测试，未调用在线模型或外部业务系统。
