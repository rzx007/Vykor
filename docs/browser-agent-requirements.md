# Vykor Agent 浏览器操作与可重跑流程需求

> 状态：提案，暂缓实施。

## 1. 用户目标

用户在项目聊天中交办网页任务，Agent 在 Vykor 桌面浏览器里观察当前页面、选择下一步、执行动作，再依据页面变化继续。任务完成时，用户能看到实际核验了什么、核验结果，以及可用的截图。若页面与预期不符，用户能看到卡在哪一步和当时的页面状态。

走通的操作可以从聊天保存成项目流程。用户能在同一项目的其他聊天里换参数重跑。首次执行和每次重跑都归属各自发起的聊天，在对应聊天的工作流面板查看。保存流程使用新的步骤与参数格式，旧单表单格式及原单参数调用的兼容与迁移已从需求中移除。

适用场景是桌面内嵌浏览器里的网页任务，包括操作本地开发页、逐步填写表单、筛选列表、打开详情和检查更新是否生效。流程可以在目标标签页内随页面跳转继续，包括单页应用只改变路径或内容的情况。观察、执行和截图都以桌面当前项目聊天授权的页面为准。

## 3. Agent 如何执行网页任务

### 3.1 观察与定位

- Agent 从聊天打开指定页面，或继续操作已授权的目标标签页。观察结果包括实际地址、标题、页面可见文字、可用控件，以及当前加载或跳转状态。
- 控件以角色和可访问名称描述，例如「输入框 · 搜索工单」「按钮 · 应用筛选」。还要提供与动作有关的状态，包括是否可用、是否选中、可选择的选项，以及有助于区分同名目标的区域名称。敏感字段沿用现有遮蔽规则。
- 能把观察和查找限定在明确区域，例如「工单结果」列表中的「详情」链接。按区域查找时，应先在当前页面完成匹配，再限制返回给模型的内容量。返回截断时要注明，避免把未返回的目标误判为不存在。
- 即时操作可以引用本次观察的临时控件 ID。页面导航、控件变化或 ID 失效后，重新观察再行动。动作前核对标签页、页面和目标身份。经过审批或等待后，也要重新核对目标。
- 可重跑的定位方式使用角色与精确名称，必要时再加命名区域或稳定的测试标识。目标不存在、禁用或匹配到多项时，返回明确原因。多个同名目标由区域或其他稳定信息消歧，列表顺序不作为默认选择依据。

### 3.2 网页操作

| 动作 | 可观察结果与约束 |
| --- | --- |
| 打开页面、点击链接或按钮 | 返回实际到达的地址和页面状态。页面重载、路由变化后，用新观察继续定位。地址偏离预期时说明实际落点。 |
| 填写输入 | 可依次填写多个字段，每次设置指定字段的值。空字符串表示清空，缺少值则让用户补齐。页面框架能收到正常的输入和变更事件。 |
| 选择下拉项 | 原生下拉框按选项名称设置并读取当前选中值。有可识别角色的网页下拉菜单沿用「打开菜单、等选项出现、点击选项、核对选中结果」。重名、禁用或缺少选项时返回原因。 |
| 切换复选状态 | 以用户指定的目标状态为准。控件已处于目标状态时直接报告，无需再点击。 |
| 按键与滚动 | 在明确目标或可确认的焦点上执行常用网页按键，如 Enter、Tab、Escape 和方向键。支持滚动后重新观察。可能提交的按键沿用提交动作的确认规则。 |

一次动作返回的是执行结果，例如「已填写」「目标已失效」「操作发出，结果未知」。任务完成由后续核验决定。Agent 只在当前任务授权的范围内根据新观察调整下一步。

### 3.3 等待与验收条件

| 等待条件 | 示例 |
| --- | --- |
| 控件存在、可见、隐藏或可用 | 等待「结果列表」出现，等待加载提示隐藏，等待「保存」按钮可用。 |
| 区域内文字或控件值符合预期 | 在「工单详情」区域核对标题与状态，确认下拉框选中「已完成」。 |
| 到达预期地址 | 点击结果链接后，等待目标页面地址及该页面的详情控件。流程可使用参数或本次观察到的目标链接确定详情地址。 |
| 成功或失败提示 | 成功条件匹配时返回匹配证据。明确错误提示出现时报告失败，保留提示与当前页面。 |

等待页面就绪可以判断当前状态，例如按钮已经可用。验证刚执行的动作时，要在动作发出前提交核验条件并记录前态。若动作前已满足主条件，要观察到它先失效再满足，才可以通过。预期有具体新值时，从一开始就把它写进条件。前态未知或只看到旧结果时，报告未验证。页面重绘和动作返回本身不能作为通过证据。

可组合多个明确条件，例如「`Maple` 结果出现」且「状态是已完成」。验证本次动作时，指定一项业务结果作为主条件。加载结束等附加条件可用于确认页面就绪，其变化不能单独证明本次结果更新。列表或详情取值应尽量限定区域。等待在条件满足时立即结束，使用现有默认等待时长，并允许按步骤设置合理时限。等待受当前执行的总时限和取消信号约束。超时要返回未满足的条件和实际观察，区分「仍看到旧值」「页面仍在加载」「目标消失」等情况。

### 3.4 异常与用户介入

- 旧目标失效、页面重绘或路由变化后，首跑的 Agent 可重新观察并在同一授权范围内继续。已经发出的提交、点击或按键若结果未知，应先观察结果和页面状态。任何再次提交都应基于用户的新指令和已确认的页面状态。
- 出现登录、审批、站点访问限制或页面要求用户介入时，聊天指出需要用户处理的位置。用户处理后，重新核对当前标签页、地址和条件，再决定继续还是结束。
- 用户切换目标页面或标签页、关闭页面、撤销权限，或者桌面断开后台时，停止发出后续动作。对于已发出且未收到结果的动作，保留结果未知的记录。重连后可以观察现状，工作流不会补发上次的动作。
- 用户取消时，停止等待和还未发出的动作。记录已完成的步骤以及最后一个动作的状态，保留后续排查所需的证据。

## 4. 从首跑生成预览和保存流程

### 4.1 首跑的依据

Agent 从一次已核验成功的操作中选出一段连续的浏览器调用，命名流程并标出参数。后台在同一项目聊天的实际工具记录中提取步骤顺序、操作目标、执行结果与验收条件。预览的可执行内容由实际调用生成，允许为输入和核验目标提取参数。模型提供的自然语言总结用于说明。

归档首跑时，使用原来的操作结果和截图附件，生成一条工作流运行记录。同一次首跑反复打开或调整预览时，沿用这条记录。首跑和后续重跑各有各的运行标识。没有完成核验的操作仍可在聊天里检查进度和原因，确认可重跑的预览需要有一次已通过的操作作为依据。

### 4.2 流程保存内容

| 内容 | 要求 |
| --- | --- |
| 身份与入口 | 流程名称、项目归属、稳定的流程标识、进入页面的方式，以及首跑证据引用。 |
| 参数 | 为可替换的输入定义名称和用途，支持文本、选项和复选状态。用户在每次重跑时提供实际值。步骤可多次使用同一个参数，例如用关键词定位结果，再用它核对详情。 |
| 有序步骤 | 每一步记录实际要执行的动作、页面或区域、稳定的目标定位方式、固定值或参数，以及必要的等待条件。支持多次填写、连续点击、选择、按键和跳转后继续。 |
| 验收条件 | 保留关键步骤和最终结果的核验条件。需要证明本次动作生效时，保存动作与对应条件的关系。 |

操作步骤只保存可复用的定位规则、固定值和参数引用。临时控件 ID 只属于当次观察，截图和实际输入产生的可见结果只属于当次运行。密码、验证码等敏感字段由用户在授权的页面里处理，入口、参数和流程记录按现有权限和遮蔽规则呈现。

### 4.3 聊天交互

1. Agent 在首跑通过后给出结构化预览。复用现有流程卡片，显示名称、「已验证 · 未保存」、参数含义、动作与目标、验收条件，以及首跑记录入口。步骤可折叠，工具详情默认收起。
2. 用户调整名称或参数说明时，可继续引用原首跑。若改动会改变实际操作、目标或通过条件，则根据新要求执行并核验，再更新预览。
3. 点击「准备保存」把引用该预览的确认请求填入当前聊天草稿。后台从实际收到的用户消息核对确认及项目归属，并从已有预览记录读取原内容保存。保存成功后展示「已保存」和重跑入口。预览不可用或保存失败时，提示用户如何重新生成或保存。

## 5. 重跑与工作流记录

- 用户可从同一项目的聊天按名称选择保存的流程，也可以从已有的流程结果使用「重跑」。同名时列出可区分的信息供选择。先检查参数名称、类型和必填值，再操作页面。
- 每次重跑建立独立工作流记录。按保存的顺序打开页面、定位、执行和核验。每个目标都在当次运行的当前页面重新定位。页面跳转后核对实际落点并重新观察，再执行下一步。
- 重跑通过条件来自保存的流程和此次参数。遇到目标歧义、页面偏离或等待超时，在对应步骤停止。权限审批由当前工具调用等待，批准后复核页面再继续。遇到登录或页面要求人工操作时，本次重跑停在该步，用户处理后可发起新运行。后续步骤的状态可见，用户能辨认哪些已经执行。
- 工作流沿用当前聊天授权和已确认的站点访问范围。对新站点、可能提交或修改数据的动作，按现有权限机制决定是否需要确认。保存流程和重复运行都不会扩大网页权限。
- 持久记录包括运行类型、来源流程或首跑标识、各步骤状态、卡住的步骤、当前地址、匹配证据和截图引用。工作流面板能从运行概览查看结果，需要排查时可展开步骤详情。

| 用户看到的状态 | 判定与展示 |
| --- | --- |
| 通过 | 必需的验收条件均有匹配证据，显示核验结果和可用截图。 |
| 失败 | 页面明确反馈本次操作失败，或核验已确认结果与预期冲突，显示实际值、预期值和步骤。 |
| 未验证 | 等待超时、识别不唯一、浏览器断连或操作结果未知。显示已经执行到哪里、待验证条件和最后可确认的页面状态。 |
| 需要用户处理 | 审批由现有权限界面显示。页面要求人工操作时，结果说明原因、当前步骤与可采取的操作。 |
| 已取消 | 记录取消位置、已执行的步骤和未确认的动作结果。 |

一次重跑在同一标签页按顺序发出动作。流程停止后的新尝试应由用户发起，并从明确的页面状态开始。出现断连、超时或截图失败时，系统保留原运行记录和最后确认的观察，避免重复发出可能改变数据的动作。

## 6. 截图与模型能力

- 工具根据模型能力提供观察。纯文本模型通过文字、控件和结构化条件操作及核验。支持图片的模型可在需要判断外观、布局或画面时请求截图。仅有文字证据时，报告文字或控件核验的实际范围。
- 每次可核验的运行都可以保存截图证据，无论该模型能否接收图片。截图在最终核验所对应的页面内容绘制之后捕获，并关联当次运行。在截图前后确认仍是同一标签页和页面，工作流面板通过已有图片查看器打开。
- 截图失败、页面在截图时切换或附件保存失败，均记录证据未保存。已经通过的文字或控件核验仍有效，捕获失败不会触发再次执行网页动作。
- 截图按现有页面权限、会话归属和附件访问规则处理，延续现有大小限制。首跑和重跑分别打开时，图片应实际对应各自输入产生的页面内容。

## 7. 复用入口与数据归属

| 现有入口 | 负责什么 |
| --- | --- |
| [`Browser` 工具](../packages/server/src/application/browser-tools/browser-tool.ts)与[桌面浏览器服务](../apps/desktop/src/main/features/browser/browser-agent-service.ts) | 接受受控动作，在桌面当前浏览器观察、定位、执行和等待。通过现有后台与桌面连接传输请求，沿用浏览器作用域、上层超时与取消。 |
| [会话记录](../packages/services/src/conversations/conversation-repository.ts) | 按项目聊天及运行找到实际浏览器调用，提供首跑证据。 |
| 拟接入 `BrowserVerification` | 生成预览、保存项目内的流程定义和参数、读取已保存流程并发起重跑。重跑动作继续走 `Browser`。 |
| [`WorkflowHost`](../packages/agent-runtime/src/node/workflow/workflow-host.ts) | 持久化首跑和每次重跑的结果、步骤进度和截图引用。 |
| 聊天预览与[工作流结果](../apps/desktop/src/renderer/src/components/desktop/tools/workflows/workflow-output.tsx) | 复用 Vykor 的聊天草稿、流程卡片、工作流面板和图片查看器，呈现预览、保存入口和各次运行的证据。 |

页面文字、控件标签和工具返回中的网页内容均按不可信数据处理。用户授权、工具边界和保存确认来自 Vykor 自己的会话与权限状态。保存流程使用可验证的有类型动作及条件，由同一桌面执行入口落地。

## 8. 验收标准

### 8.1 真实桌面操作

使用本地开发的工单页面。搜索和筛选实际发出 HTTP 请求，列表延迟更新，从结果链接跳转到真实详情地址。两组工单用不同名称和状态，详情页显示可核对的值。

| 操作 | 验收证据 |
| --- | --- |
| 在 Vykor 桌面聊天让 Agent 搜索 `Cedar`，选择「进行中」，提交筛选，打开匹配项并核对详情。 | Agent 从新观察定位搜索框、状态选项和提交按钮，等待正确结果出现，再依据实际列表打开详情。核对详情标题与状态。 |
| 从聊天查看预览并确认保存。 | 预览与实际走通的步骤一致，可替换关键词和状态。确认后在当前项目可找到流程。首跑归档时，服务端收到的筛选提交次数仍为一次。 |
| 在同一项目用 `Maple` 和「已完成」重跑。 | 重新定位各步控件，等待列表更新，再打开 `Maple` 详情。服务端收到新参数，重跑也只提交一次。 |
| 从对应聊天的工作流面板分别打开首跑和重跑。 | 两条独立运行记录，截图各自对应 `Cedar · 进行中` 和 `Maple · 已完成`。结果中能看到各自的关键步骤、匹配条件和详情地址。 |

纯文本模型应能走完基于文字和控件的任务，面板仍可打开其运行截图。支持图片的模型补测一次基于画面的观察，确认画面与实际浏览页面一致。

### 8.2 回归检查

| 场景 | 通过条件 |
| --- | --- |
| 默认等待与延迟更新 | 省略等待时长，条件延迟出现后成功匹配。显式较短等待超时后报告未验证。 |
| 旧结果与错误提示 | 提交前就有的成功文字或结果行不会让本次核验通过。真实错误提示使流程停在正确步骤。 |
| 控件替换、重名或移位 | 新页面按定位规则找到正确目标。无法唯一匹配时停在该步，相关动作未发出。 |
| 原生和自定义下拉菜单、按键提交 | 可观察真实选中值。按键提交经过现有审批并只发出一次，等待条件对应当次操作。 |
| 跳转、切换标签页或跨站 | 预期跳转完成后按新观察继续。切走标签页、到达未授权站点或偏离预期时，按现有权限和页面范围停止后续动作。 |
| 取消、断连或操作结果未知 | 工作流保留已执行步骤和最后状态。重连不会补发已提交的动作。 |
| 参数缺失、跨项目调用或预览被替换 | 在发出网页动作前给出明确提示。用户确认的流程内容和所属项目可核实。 |
| 截图时序与截图失败 | 两张截图各自包含核验通过后呈现的页面。模拟截图失败后仍保留核验结果，服务端只收到一次提交。 |

自动回归复用[现有 Electron 浏览器测试入口](../apps/desktop/tests/browser-annotations-electron/main.ts)。交付时运行完整 Electron 浏览器套件，以及受影响的桌面和服务端测试。桌面实测记录保留模型类型、两组参数、首跑与重跑的运行标识、截图和实际判定结果。
