# Desktop Agent 消息渲染设计

> 状态：当前 Desktop 消息与文件变更渲染说明，最近核对：2026-10-02。

## 目标

桌面端的 Agent 回复需要同时承载 Markdown 正文、推理过程、工具执行、文件引用和本轮文件变更。正文优先保证阅读连续性，运行细节默认保持克制，但在需要排查时仍可展开查看。

## 显示结构

一条 Assistant 消息按以下顺序渲染：

1. 连续的文本 part 合并后交给 `Streamdown` 渲染。正在生成的最后一条消息使用 streaming 模式，历史消息使用 static 模式。
2. reasoning part 显示为可展开的“思考过程”，默认收起。
3. 同一个 `toolUseId` 的 tool 和 tool_result 合并为一条工具活动，避免输入和结果各占一个卡片。
4. error part 使用明确但不过度抢眼的错误提示。
5. 回合结束且发生文件写入时，在消息末尾展示“已编辑 N 个文件”。

用户消息继续使用靠右的轻量气泡；Assistant 正文不套大卡片，保持完整可读宽度。用户 text part 带有 `metadata.items` 时，按原顺序把 Skill item 渲染为行内名称，并保留相邻正文；绝对 `SKILL.md` 路径和 Skill 正文不进入消息展示。

## 工具参数、结果与状态

- 参数生成阶段只显示一行“工具名 · 生成参数 · N 字符”和状态图标，不可展开，不重复渲染空的参数/结果框；图标保留无障碍状态名称，并尊重减少动态效果设置。
- 活动行显示文件路径或命令摘要。仅含 `arguments` 的包装对象可逐层展开用于摘要；同时存在其他业务字段时不替换原对象。这只影响展示，不改执行参数。
- 正式工具活动展开后分别显示原始“参数”和“结果”，不能用结果覆盖参数。未记录参数、实际空对象和参数解析失败分别说明；解析失败的空对象占位不冒充有效参数。
- `toolCallStatus` 统一合并调用和结果状态，包括独立的 `tool_result`。失败、中断、等待和运行中明确标记，已结束的调用不继续显示运行效果。
- 分组使用“文件编辑 N 次”“命令调用 N 次”等中性标题；调用次数不表示成功编辑了 N 个文件，失败另行标记。
- 分类互斥，命令类优先；`BackgroundShellCreate` 只计为命令调用，不能因名称包含 `Create` 再计为文件编辑或吞掉查看次数。

## 文件引用

Markdown 链接和行内代码中的文件路径都可以成为文件入口。识别规则保持保守：必须带目录分隔符或常见文件扩展名，并排除 URL、命令参数和纯版本号。

点击文件入口后的流程：

1. 消息组件将路径和可用行号交给会话页的文件打开回调。
2. 主布局展开右侧工具面板并生成一次性文件打开请求。
3. `UtilityPanel` 激活文件工具。
4. `FilesTool` 在当前项目文件列表就绪后，复用现有 `workspace.readFile` 流程打开文件标签。

相对路径以当前项目目录为根；绝对路径只有位于当前项目目录内时才会转换为相对路径并打开。消息组件传递可用行号，具体定位由文件工具消费请求。

## 文件变更摘要

当前会话协议还没有独立的 file-change 事件，因此第一版只从结构化工具调用中提取，不解析普通回复文字：

- 根据写入类工具名称判断是否属于文件变更。
- 从 `input.path`、`filePath`、`file_path`、`target` 等结构化字段提取路径。
- 对 `apply_patch` 一类输入解析补丁头和增删行数。
- 只汇总已完成且成功的文件操作；失败或中断不能进入成功变更摘要。独立结果和内嵌结果使用同一状态判断。
- 工具仍在 pending/running 时不展示摘要；回合结束后再展示，避免列表跳动。

摘要默认展示前三个文件，可展开其余文件。文件行可点击并打开右侧文件工具。后续协议若增加结构化 file-change part，应直接替换提取器的数据来源，UI 组件无需改动。

## 组件边界

- `apps/desktop/src/renderer/src/components/desktop/conversation-page/`：会话布局、输入框、消息分组和文件打开请求转发。
- 该目录下的 `message/message-render-model.ts`：合并文本、配对工具、统一工具状态、提取文件引用与成功文件变更，保持为可测试的纯函数。
- `message/assistant-message.tsx`：Streamdown、自定义文件节点、工具活动、错误和变更摘要。
- `layout/main-layout/utility-panel/` 与 `tools/files-tool.tsx`（均位于 `components/desktop/`）：传递并消费一次性文件打开请求。

## 验收标准

- 标题、列表、引用、链接、行内代码、代码块和表格具有一致的 Markdown 排版。
- 流式内容不会反复重建整条历史消息。
- 文件路径表现为紧凑的文件入口，点击会展开右侧面板并打开文件。
- 工具输入和结果不会重复显示成两张卡片。
- Write/Edit 和 Shell 的原始参数在展开后可见；解析失败与未记录参数可区分。
- 失败调用有明确标记，不被统计为成功文件变更；独立结果能正确结束运行状态。
- 只有回合结束并检测到文件写入时才显示文件变更摘要。
- 明暗主题下正文、代码块、工具活动和变更摘要均有清楚层级。
