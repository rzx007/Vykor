# 输入框能力需求补全文档

> 状态：当前。`@/+` 插件入口默认开启；插件本轮的真实 Electron 手动验收尚未执行，检查步骤见[插件能力运行设计](./plugin-capability-invocation-design.md#15-发布检查与手动验收)。

## 1. 背景

当前输入框支持文本、Skill、斜杠命令、插件、历史对话、计划模式、目标与附件。本页维护跨客户端和服务端的输入约束；具体文件、状态归属和新增代码位置见[Composer README](../apps/desktop/src/renderer/src/components/desktop/conversation-page/composer/README.md)。

## 2. 目标

输入框需要成为统一的“请求编排入口”：用户可以输入文本、引用上下文、选择命令或 Skill，并能看到能力执行和系统状态的完整反馈。

目标包括：

- `@` 和 `+` 打开同一个上下文面板。
- `/` 打开命令面板。
- `$` 打开 Skill 面板。
- 已有拖拽、粘贴和附件上传能力保持不变。
- 能力选择、执行、失败、取消和历史恢复形成闭环。
- 自动压缩、手动 `/compact`、模型切换等系统状态使用统一 metadata presentation 展示。

## 3. Codex 对齐规则

### 3.1 `@` 与 `+`

`@` 和 `+` 是同一个“添加上下文”面板的两种入口：

- 键入 `@`：从光标位置唤起面板。
- 点击 `+`：直接唤起同一个面板。
- 两者使用同一份数据源、搜索、键盘导航和选择逻辑。
- 选择结果成为当前 composer document 的上下文项。

面板分类包括：

- 文件和文件夹
- 计划模式
- 插件
- 目标
- 历史对话

历史对话作为只读参考，不切换当前会话。独立应用、文件和聊天搜索尚无面板入口；站点不在当前范围内。

`+` 不是“多能力添加器”，也不是新的输入语法。

### 3.2 `/`

- `/` 可在输入中间通过空格边界触发。
- 首字符 `/` 时显示完整命令菜单，包括审查、压缩、计划等操作。
- 中间位置 `/` 只显示允许内联使用的项目，不显示仅支持空输入执行的命令。
- 选择命令后，按命令类型执行或插入文本。
- 中文输入法组合态下，回车不能误提交或误关闭面板；组合态结束后回车正常确认。

### 3.3 `$`

- `$` 用于唤起 Skill 面板。
- 支持首字符和正文中间触发。
- 选择 Skill 后插入结构化 Skill mention；item 携带当前 catalog 的绝对 `SKILL.md` 路径，供 daemon 执行前重新校验。
- 路径不在消息列表或胶囊中展示，也不构成任意文件读取授权；服务端通过当前 cwd Skill registry 解析并校验真实能力。

## 4. 现有能力盘点

| 能力 | 当前状态 | 处理要求 |
| --- | --- | --- |
| 普通文本 | 已有 | 保持 |
| `/` 命令 | 已有 | 保持首字符/中间位置与输入法组合态边界 |
| `$` Skill | 已有 | 保持结构化引用和服务端校验 |
| `@` 上下文 | 已有 | 与 `+` 共用 Context Picker |
| `+` 上下文与插件 | 已有 | 文件项复用附件链路，插件项保存能力引用 |
| 拖拽附件 | 已有 | 不改变行为 |
| 粘贴附件 | 已有 | 不改变行为 |
| 计划模式与目标 | 已有 | 分别更新会话工作模式或进入独立目标输入流程 |
| 自动压缩 | 已有 | 展示“正在压缩上下文/已压缩上下文” |
| `/compact` | 已有 | 与自动压缩使用相同状态展示 |

## 5. Context Picker 需求

### 5.1 入口

- `@`：根据光标位置插入触发 token。
- `+`：不改写正文，直接打开面板。
- 面板打开时，输入框保持焦点。
- 点击外部、Esc 或发送消息时关闭面板。

### 5.2 搜索和导航

- 支持按名称、描述和分类搜索。
- 支持上下方向键、Enter、Tab、Esc。
- 鼠标悬停更新高亮项。
- 空结果显示明确提示。
- 面板内容较多时可滚动，且不影响消息列表滚动。

### 5.3 选择结果

上下文项必须包含：

- `type`
- 稳定 `id`
- 展示名称
- 可选描述
- 来源和版本信息
- 是否需要上传、授权或确认

选择后：

- 文件/文件夹进入附件或文件上下文链路。
- 计划模式更新当前会话工作模式，保持授权档位不变。
- 插件和对话进入各自的结构化输入项；目标打开独立输入模式。
- 不能只插入不可解析的纯文本名称。

## 6. 附件行为约束

以下行为必须保持不变：

- 拖拽文件到输入框后上传。
- 从剪贴板粘贴图片或文件后上传。
- 显示上传进度。
- 支持取消、重试和移除。
- 不支持的文件类型给出原因。
- 页面刷新或发送失败后，不能静默丢失附件状态。

`+` 和 `@` 只是增加附件/上下文的入口，不替换现有附件处理器。

## 7. 计划模式和目标

### 7.1 计划模式

计划模式使用独立的 `workMode: execute | plan`，通过 `@/+`、`/plan` 和输入区标记共用会话更新动作。授权档位 `approvalMode` 独立保存，进入和退出计划不会改写它，也不修改新聊天默认授权。

### 7.2 目标

目标入口进入独立输入模式，提交后由会话级 Banner 展示状态和操作。正文、用量、暂停、续跑与等待由服务端持久保存；Composer 不维护第二套目标状态机。完整行为以[会话目标设计](./session-goals-design.md)为准。

## 8. 执行闭环

能力从选择到执行必须经过以下状态：

```text
未选择 → 已选择 → 等待执行 → 执行中 → 成功
                                  ↘ 失败
                                  ↘ 取消
```

要求：

- 客户端发送结构化能力引用。
- 服务端校验能力存在、版本、权限和参数。
- 执行中可见状态。
- 失败原因可读，并支持重试或移除。
- 取消后停止接纳新操作；已发出的操作查询原回执，不能把取消当作回滚成功或自动重放的依据。
- 页面刷新后从服务端状态恢复。

## 9. 消息和 metadata 展示

系统过程消息采用 presentation metadata，不让展示文本进入模型上下文。

统一支持：

```ts
metadata: {
  presentation: {
    kind: "context_compaction" | "model_switch" | "capability_status",
    phase?: "started" | "completed" | "failed" | "cancelled",
  }
}
```

压缩状态文案：

- `正在压缩上下文`
- `已压缩上下文`
- `上下文压缩失败`

这些 presentation-only 消息不能进入 Agent transcript。

## 10. 数据协议（不做旧数据兼容）

- 插件与历史对话使用稳定 ID，不依赖展示名称恢复；Skill 携带目录中的绝对路径，由服务端重新校验。
- 本功能直接采用新协议，不提供旧 composer 数据迁移或双读逻辑。
- 客户端和服务端同时升级；协议不匹配返回明确错误。
- 已删除或失效能力可以保留历史展示，但不能再次执行。
- 未注册的 presentation 类型返回明确错误，不静默降级。
- 不修改已有附件、Skill、命令的存储格式。

## 11. 验收标准

### 交互

- 输入 `@` 和点击 `+` 打开同一个面板。
- `@` 选择文件后复用附件上传。
- 拖拽和粘贴附件行为与改动前一致。
- `/` 首字符显示完整命令，中间位置按规则过滤。
- `$` 可以选择 Skill。
- 中文输入法下回车行为正确。

### 数据

- 发送请求包含结构化上下文项。
- 插件和历史对话引用使用稳定 ID；Skill 路径必须属于当前服务端目录。
- 历史消息重新加载后可以还原上下文展示。
- presentation-only 消息不会进入模型上下文。

### 状态

- 能力执行成功、失败、取消均有反馈。
- 自动压缩和 `/compact` 都显示开始和完成状态。
- 压缩失败时显示失败状态，且不吞掉原始错误。

### 测试

- Context Picker 单元测试。
- `@` 与 `+` 入口一致性测试。
- 拖拽/粘贴附件回归测试。
- `/`、`$` 和中文输入法交互测试。
- 能力执行状态测试。
- 历史恢复和 metadata 降级测试。
- 自动压缩和手动压缩展示测试。

## 12. 实施顺序

1. 统一 `@` / `+` 的 Context Picker 外壳和数据协议。
2. 接入文件和文件夹，并复用附件上传链路。
3. 接入现有计划模式。
4. 维护插件和对话数据源；没有稳定实现的应用入口继续隐藏。
5. 完成能力执行状态和错误闭环。
6. 完成历史恢复和全量回归测试，不增加旧协议兼容层。

## 13. 非目标

- 不把 `+` 设计成新的能力语法。
- 不重写拖拽和粘贴附件系统。
- Skill 路径只用于结构化输入及服务端复核，不在消息标签展示，不授予任意文件读取权限。
- 不将命令、Skill、上下文和附件强行合并成同一种执行语义。

## 14. 插件能力交付契约

`@` 与 `+` 共用插件目录，插入包含稳定 `pluginId` 的原子引用。目录只包含名称、版本、来源、说明和能力类别；历史按名称恢复，不显示路径、凭证或内部配置。输入按 queue 创建新 Run；同插件的 `@`、Skill、Agent 引用可合并，不同插件会在准入阶段拒绝并保留草稿。

Desktop 启动按[协议契约](./protocol-contract.md#当前版本)精确匹配，并要求 `pluginCapabilities: 1`，不支持时明确要求同时升级 daemon。`VITE_PLUGIN_MENTIONS_ENABLED=false` 只关闭入口，用于普通输入、Skill、Goal 和附件等回归检查。

准入失败和运行失败均可关闭提示；运行错误关闭只改变界面，失败状态仍保存在 Run 中，刷新或重开历史后恢复。插件准备状态携带 sessionId、runId、pluginId，实际调用沿用 Tool 和 Child 消息。
