# Vykor Desktop 设计基线

Vykor Desktop 的界面应当安静、可靠、精确。它是一款需要长时间停留的开发工具，不是营销页面，也不是由一组仪表盘卡片拼起来的后台系统。

这份基线参考 Codex 等现代桌面开发工具的结构与密度，但不照搬具体页面。新增页面和改造旧页面时，应优先保持 Vykor 自己的任务流一致。

## 1. 页面结构

- 应用外壳负责侧栏、工作区边界和全局导航；页面内容不要再套一层“大卡片”。
- 设置、插件、任务管理等阅读型页面使用居中的可读内容列，推荐最大宽度 `56rem` 左右。
- 页面标题与正文靠留白建立层级。页面标题默认约 `20px / 600`，区块标题约 `15px / 600`，说明文字约 `12–13px`。
- 同一页面只保留一个主标题。不要用多个大标题重复描述相同的信息。

## 2. 表面、边框与阴影

- 默认表面是工作区背景。只有真正独立、可以被整体操作或移动的对象才使用卡片。
- 列表优先使用行间距和细分隔线，不要把列表再装进带圆角和阴影的大容器。
- 边框用于表达输入范围、窗口边界、可点击区域或状态边界；没有这些含义时就不要加。
- 不在同一个层级同时叠加背景色、边框、大圆角和阴影。
- 页面内部通常不使用阴影。应用外壳、浮层和菜单可以保留克制的阴影来表达层级。

## 3. 控件

- 主要操作才使用实心按钮。刷新、重新加载、更多操作等低风险动作优先使用 ghost 按钮或图标按钮。
- 搜索框、文本输入框保留清晰边界，因为边界表达了输入范围；不要额外添加外层卡片。
- 筛选使用线型标签或轻量分段控件。避免在页面中重复出现厚重的胶囊背景。
- 开关只用于立即生效的二元状态；破坏性操作必须经过确认。

## 4. 状态反馈

- 成功信息使用紧凑的内联状态或 toast，不占据整行形成新的视觉区块。
- 警告和错误可以使用 Alert，因为它们需要打断注意力；同类信息应合并，避免连续堆叠多个边框框体。
- 加载骨架应模拟最终内容的形状和密度，不显示一个巨大的空白卡片。
- 空状态保持紧凑，说明下一步能做什么；不要用大面积边框把“没有内容”放大成页面主体。

## 5. 列表与详情

- 列表行默认高度控制在 `56–72px`，主要信息一行、次要信息一至两行。
- 图标是识别线索，不是装饰海报。常规插件或工具图标建议为 `36–40px`。
- 状态徽标只表达异常、待处理或重要状态。来源、范围等普通元数据优先使用次要文字。
- 详情弹窗内部使用标题、间距和对齐建立分组；不要为每个小分组再创建灰色圆角卡片。

## 6. 颜色、字体与动效

- 统一使用现有语义颜色变量，如 `background`、`foreground`、`muted`、`border` 和 `destructive`，不要在业务页面写固定颜色。
- 正文和控件使用应用默认 UI 字体。展示字体只用于确有品牌表达需求的场景。
- 动效服务于状态变化，常规时长控制在 `150–200ms`。尊重系统的减少动态效果设置。
- hover 只做轻微背景或文字变化；不要使用缩放、发光或大幅位移制造反馈。

## 7. 提交前检查

- 是否存在可以直接删除的外层 Card、Alert 或边框？
- 是否有超过一个页面级大标题？
- 信息层级能否只靠标题、间距和字体粗细读懂？
- 成功状态是否比错误状态更抢眼？如果是，应降低成功状态的视觉重量。
- 空状态是否占据了过多页面面积？
- 深色模式、键盘焦点、缩放和窄窗口下是否仍然可读、可操作？
