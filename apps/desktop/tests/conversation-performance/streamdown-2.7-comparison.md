# Streamdown 2.5 → 2.7：Electron 对比

2026-10-29 在 Windows 上验证 Streamdown 2.5.0 与 2.7.0。保留项目的分块适配、64ms 长文本合并刷新、代码源码即时更新和逐字动画实现，产品渲染代码没有改动。

## 测量条件

- Electron 39.8.10 / Chromium 142.0.7444.265，生产构建，隐藏窗口，关闭 GPU。
- 固定 960 × 480 的滚动容器，16px / 1.7 Arial 与系统中文字体兜底；加载 Streamdown 动画 CSS。没有加载完整应用样式，数字用于依赖版本对比，不代表所有实际会话的绝对耗时。
- 通过实际 `AssistantMarkdown` 与 `AppearanceProvider` 更新。每轮两次预热、八次被测追加；每次等待新增文字真正进入 DOM，再发送下一次更新，避免跳过输出造成虚假提速。
- 每个版本分别进行三轮测试，覆盖动画开启、关闭。另保存 2.5 渲染构建，以 A/B、B/A 顺序交替运行两个版本，动画开启，每个场景两轮、共 16 次被测更新。
- 两个构建使用相同输入。构建时核对的 780 个渲染源码文件 SHA-256 一致：`159855c7543da1628e5cfdfa55e21256c1656c715fc5d9cc994163371fad9290`。版本升级只涉及 Streamdown 及其依赖，未加入新的刷新策略。

## 交替对照结果

下表为两轮主线程 `TaskDuration` 总增量除以 16 次更新，排除挂载、预热和最终静态渲染，包含流式过程的动画清理。没有把等待刷新计时器的空闲时间计作 CPU 耗时。

| 场景 | 初始规模 | 2.5 平均每次更新 | 2.7 平均每次更新 | 降幅 |
| --- | --- | ---: | ---: | ---: |
| 纯中文单段落 | 约 10.4 万字符 | 73.1ms | 67.1ms | 约 8% |
| 包含加粗和链接的单段落 | 约 3.4 万字符、800 组行内格式 | 689.3ms | 285.6ms | 约 59% |
| 连续有序列表 | 2,000 项、约 10.2 万字符 | 2,672.3ms | 667.8ms | 约 75% |

纯段落的收益小，容易受机器负载影响，不应视为明确的大幅提速。复杂段落和长列表的改善在交替顺序下仍然成立。两轮共 16 次更新中，复杂段落与列表的超过 50ms 任务均由 32 次降为 16 次；长列表依然会明显阻塞主线程，升级没有解决所有大块解析开销。

## 正确性与范围

两个版本的 Markdown 专项 Electron 检查均通过：全部追加文字可见，列表项数量正确，加粗与链接结构保留，逐字节点不超过 512 个，关闭动画时没有逐字节点，停顿和完成后正确清理，结束前后正文一致。

2.7 另外通过：

- 167 项 Markdown、文件链接、中文强调、分块等价性、内存、代码高亮、逐字动画、正文样式和外观偏好回归测试。
- 渲染端 TypeScript 检查。
- 原有 Electron 会话性能检查：1,000 / 10,000 条历史下的滚动跟随、历史导航、面板拖动与键盘操作，以及连续代码块和高亮身份保持。

本次保留原有解析器适配与动画实现。下一步是否调整刷新频率或改变解析边界，应另行评估；不能将本次结果解释为长列表已经没有长任务。
