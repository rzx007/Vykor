# 列表段落规则缓存：正确性与性能对比

2026-10-29，基于 `4129342c` 的 Streamdown 2.7.0 和 `mdast-util-to-hast` 13.2.1，对比本次列表转换补丁前后的行为。保留此前链接安全检查与链接处理优化，应用层分块、刷新、动画和列表组件均未改动。

## 改动范围

转换函数每次创建的 `state` 增加一个 WeakMap，按父列表节点保存是否保留段落标签的判断。同一列表第一次沿用原规则计算，后续列表项读取结果，包含 `false`。嵌套列表各自保存，下次转换创建新的缓存；不改写输入语法树，不跨更新保存结果。补丁同步内部状态的类型声明。

通过根目录的 `patches/mdast-util-to-hast@13.2.1.patch` 和 pnpm 补丁配置安装，没有新增插件、组件状态、定时器或调度器。

## 正确性

新增 12 项回归测试，先在原版确认两项复杂度测试失败，其余行为用例通过，再验证补丁：

- 256 / 1,024 项紧凑列表的标记读取次数受线性上限约束，避免只缓存 `true` 而漏掉 `false`。
- 同一个列表对象从紧凑改为多段落、再改回紧凑，每次转换重新判断；冻结输入仍可转换，输入内容不被修改。
- `spread` 为 `null` 或缺失时，继续根据列表项的段落数量判断。
- 有序列表起始编号、列表项之间和内部的空行，以及外紧内松、外松内紧的嵌套规则。
- 嵌套任务列表的勾选、禁用状态和样式标记；流式追加段落、嵌套任务项和完成时的正文一致性与动画清理。

Streamdown 的列表项组件会去掉单独的段落包装，因此段落规则在转换后的 HTML 语法树上检查，任务列表与流式场景另外检查实际 DOM。

相关 211 项 Markdown、文件链接、中文强调、分块、代码、动画、样式与外观测试通过；补齐新测试的必填回调后，12 项列表测试再次通过。渲染端 TypeScript、改动文件 ESLint 和冻结锁文件安装通过。

## 转换阶段的单独对照

Electron 39.8.10 / Chromium 142.0.7444.265，隐藏页面，关闭 GPU。使用真实 remark 解析及 GFM 扩展生成输入树，在同一个页面分别调用原版和补丁版转换器；各预热八次，按 A/B、B/A 交替测量 32 次。计时不含 Markdown 解析、JSON 比较、React 和布局。

每次输出与原版完整语法树进行 JSON 比较，并检查输入未被修改。计数所用的 getter 会影响 V8 的属性访问优化，因此仅在全部计时结束后安装，用于独立统计；表中不使用计数提前介入的试跑结果。

| 场景 | 原版每次平均耗时 | 补丁每次平均耗时 | 标记读取次数：原版 → 补丁 |
| --- | ---: | ---: | ---: |
| 2,000 项紧凑有序列表，含加粗与链接 | 78.9ms | 52.4ms | 4,000,000 → 2,000 |
| 8,000 项紧凑有序列表，含加粗与链接 | 628.0ms | 203.1ms | 64,000,000 → 8,000 |
| 2,000 项带空行列表 | 47.2ms | 48.8ms | 0 → 0 |
| 2,000 项任务列表 | 43.5ms | 16.4ms | 4,000,000 → 2,000 |
| 80 个父项、各 100 个任务子项，共 8,080 项 | 51.8ms | 47.2ms | 806,400 → 8,080 |

紧凑列表转换阶段分别减少约 34% / 68%，任务列表约 62%，嵌套任务列表约 9%。父列表已标记为带空行时，原版本来就不扫描子项；该控制组略慢约 3%，当前不能区分测量波动和缓存查询的额外成本，不把它描述为收益。

读取次数证明这段检查由平方增长变为线性增长；耗时比例只属于本次转换阶段，不能套用到整条渲染链路。

## 完整渲染对照

保存修改前构建，再用同一套 [Markdown 场景](markdown.tsx) 构建补丁版。使用真实 `AssistantMarkdown` 与外观设置，960 × 480 容器、16px / 1.7 Arial、Streamdown 动画 CSS；未加载完整应用样式。复用同版本 Electron 二进制，运行前结束构建与检查任务。

每轮两次预热、八次被测追加，始终等待新文字进入 DOM。采用 A/B、B/A 两轮，共每个构建、每种场景 16 次更新；计时不运行 CPU 采样、getter 计数或属性观察器。下表是 Chromium `TaskDuration` 总增量除以更新次数，排除挂载、预热和完成后的静态转换，包含流式更新的动画清理。

| 场景 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 约 10.4 万字符纯中文段落，动画开启 | 68.1ms | 68.8ms |
| 2,000 项列表，动画开启 | 478.3ms | 502.9ms |
| 2,000 项列表，动画关闭 | 531.8ms | 437.8ms |

动画关闭时两轮均有下降；动画开启时一轮变慢、一轮小幅下降，当前没有稳定的整体提速结论。列表两种状态均仍有 16 个超过 50ms 的任务。补丁只移除了转换中的重复扫描，Markdown 整段解析和其他插件处理仍然存在。

两套构建均确认全部追加可见、列表项数量正确、加粗和链接结构保留；动画开启时节点数受限且实际出现，关闭时为零，停顿后清理，完成前后正文一致。

入口 JS 的差异仅为缓存实现和构建引用名。SHA-256：修改前 `5d22cc9830574e8f70902addc448ac5a9ad13cb7123106ce90f563cfb2759fb2`，修改后 `9b213c51c1e57cfe2ef70ba229ff04b599df6d675491bd9e30e68cc544409866`。

原始 JSON、构建副本和临时比较脚本保存在本次工作区的忽略目录；标准完整渲染验证继续使用 [README 中的性能命令](README.md)。复现比较时需保留原版与补丁版的构建或转换器副本，使用相同输入交替测量，并将计数观测放在计时之后。
