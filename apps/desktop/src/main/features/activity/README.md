# 全局活动状态

这里把后台会话、目标和定时运行的事件整理成桌面活动摘要，供侧栏未读标记和系统通知使用。摘要不携带对话正文。

- `global-activity-subscription-service.ts` 是入口：每个窗口保持一个全局事件订阅，先重放历史事件形成基线，再通过 `activity:updated` 把后续变化交给渲染进程。
- `activity-reducer.ts` 保存活动判断需要的会话、运行和待处理权限，跳过正文等无关数据。
- `activity-projection.ts` 根据这些记录得出运行中、完成、失败或等待处理的状态。`activitySeq` 表示最近一次需要注意的事件位置，渲染进程用它判断未读和避免重复提醒。
- `__test__/goal-activity.test.ts` 覆盖目标映射及真实订阅到渲染状态处理的流程；同目录既有测试覆盖权限、历史重放、删除和重连。

会话及定时活动缓存、每个会话最近的目标记录都归订阅实例所有；删除会话时同时清除其目标，关闭窗口时取消整个订阅。目标记录从 `session.goal.created` 和 `session.goal.updated` 事件恢复，不写进通用客户端状态。

目标仍在推进时，单个成功回合结束继续显示运行中，直到整个目标完成。真实的回合失败立即保留失败状态，目标随后记录同一次失败时不重复推进提醒位置。目标提问用问题 ID 标识，阻塞或自动停止用目标版本和修订号标识；用量进展事件不会重新提醒。权限请求始终优先，已解决的审批不会因为目标仍保留旧等待记录而再次出现。后来开始的普通运行自行决定状态，不受旧目标终态影响。

所有会话共用同一条提醒位置规则：完成、失败或待处理事项首次显露或更换时，用当前事件更新 `activitySeq`。子任务的权限可能挂在父会话中，并遮住父运行的结果；处理或过期后，显露出的结果使用这次事件的位置，避免被其他会话较新的提醒吞掉。

定时运行的完成提醒由定时记录统一产生。会话摘要从当前运行的 `metadata.scheduledRunId` 保留所属定时运行 ID，让下游合并同一次执行的完成和失败提醒；跳过的定时运行显示空闲，不能当作成功完成。

新增事件先在订阅入口明确其状态归属，再在投影函数补状态规则。跨事件与渲染状态的回归用例放进本目录 `__test__/`；不要在这里保存正文或直接调用系统通知。
