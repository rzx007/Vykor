# 托盘和系统通知

本目录负责托盘菜单、托盘闪烁、系统通知和任务栏未读标记。

- `ipc.ts` 接收界面发来的 `tray:notify` 请求，把主窗口和通知焦点查询交给 `tray.ts`。
- `tray.ts` 创建托盘并发送原生通知；`attention-badge.ts` 保存当前进程内的未读数量并绘制标记。
- `notification-actions.ts` 构造 Windows 通知的点击、文字回复和一次性授权动作，并通过 Electron 的统一激活回调接收结果；复用后台现有消息、权限和目标接口。
- `notification-navigation.ts` 等待主页面订阅完成后派发原会话 ID，避免冷启动或重载时丢失跳转。
- `__test__/tray-delivery.test.ts` 用原生通知替身验证发送确认、失败重试、去重和焦点边界；`tray.test.ts` 保留现有模式、正文脱敏及点击行为测试。

## 通知如何发送

界面调用 `window.desktop.tray.notify`，经过预加载桥接和 `ipc.ts` 进入 `sendTrayNotification`。发送端重新读取通知模式和事件开关，再检查事件是否已经显示或仍在等待系统结果。通知焦点由 `WindowManager.getNotificationFocusWindow()` 判断：主窗口中的会话或设置页聚焦时遵循 `when_unfocused` 模式，宠物窗口聚焦不会阻止通知。

窗口不在前台时先增加未读标记；模式允许且系统支持原生通知后，才向系统提交。任务正文使用固定的完成、失败或等待处理提示，不把命令或任务内容放进通知。点击通知会恢复主窗口，并把原会话 ID 发回界面，由界面查询并打开对应会话。每条通知保留自己创建时的会话 ID，之后切换当前对话不会改变点击去向；连续点击或查询期间主动切页时，界面只接受仍有效的最近选择。

跨模块回归放在 `main/__test__/permission-notifications.integration.test.ts`，用真实活动转换和通知入口配合原生通知替身，覆盖完成、失败、需要回复、定时任务、窗口焦点和点击恢复，不操作真实系统通知。

## 状态归属

`pendingNotificationIds` 只保存在当前主进程内，用来阻止同一事件在系统尚未反馈时重复提交；`pendingNotifications` 持有这些原生通知对象，直到本次投递收尾。收到原生 `show` 事件后，才把事件 ID 写入桌面偏好的 `notifiedEventIds`，最多保留最近 1,000 条；每次确认都合并最新记录，避免多个通知先后返回时覆盖彼此。

每次投递只接受一个最终结果。原生 `failed`、构造或发送异常、显示前关闭，以及 5 秒内没有收到系统确认，都会解除等待状态，不写入已显示记录；它们不会自动重新发送。无论以哪种结果收尾，都会清掉等待计时器和本次结果监听，避免旧投递迟到的结果影响同一事件的新尝试。前台抑制、事件关闭和系统不支持同样不会消耗事件 ID，因此后续仍可重试。

新增托盘交互或通知发送规则放在本目录；焦点角色规则放在窗口管理器；事件产生、会话恢复和页面导航仍由各自模块负责。新回归测试放在 `__test__/`，不得发送真实系统通知或操作真实窗口。

## Windows 交互通知

启动入口在应用身份、插件服务和 IPC 注册完成后安装 `Notification.handleActivation`。通知采用 Windows 原生 XML；正文点击携带“打开”动作，输入框携带“回复”动作，权限按钮只提供“允许本次／拒绝”。所有动作都绑定本机生成的通知 ID，不使用当前选中的对话，也不注册可从网页调用的授权协议。

通知 ID、原会话、权限请求或目标问题保存在本机桌面偏好的 `notificationTargets`，最多保留最近 1,000 条。统一激活回调读取这份记录，因此通知对象被回收或桌面重启后仍能定位目标。未知 ID 不执行动作。点击正文会显示主窗口；页面先安装监听再发送 `tray:notification-ready`，主进程才派发暂存的最新会话。子框架加载和同文档路由不影响就绪状态。

普通回复通过既有 `sessions.admitPrompt` 入队，权限回复调用 `permissions.reply` 并限定为 `once`；AskUser 的文字回答不会被解释为工具批准。授权前重新检查请求仍在等待，返回过期记录时不显示批准成功。后台重启或其他窗口已处理的旧请求不能再次放行。

回复发送前保存输入 ID 与文字，失败后用原文字填回原生通知供重试，桌面重启也会恢复尚未确认的回复；重复激活由当前进程的 `inFlight` 集合合并，HTTP 结果不确定时重用同一个后台请求 ID。后台确认成功后清除保存的文字，并用状态通知替换原通知。任务正文仍使用固定状态句，不加入命令、任务输出或密钥。

`__test__/notification-actions.test.ts` 覆盖历史目标恢复、重复回复、失败重试、权限动作和过期结果；`__test__/notification-navigation.test.ts` 覆盖页面尚未订阅、重载及子框架导航。桌面偏好的实际文件保存回归放在 `settings/__test__/notification-targets.test.ts`。
