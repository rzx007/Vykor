# 桌面后台服务启动

这里维护桌面系统常驻开关和无窗口启动入口。窗口进程使用 SDK 查找或按需启动后台。

- `daemon-entry.ts` 识别常驻、看护和按需模式。看护先判断登记进程是否还活着。常驻和按需模式都调用共享注册后台，传入系统首选显示语言，并显式启用桌面浏览器桥接和 Agent 开发工具的宿主支持。
- `computer-pairing.ts` 管理 Windows 按需后台的一次性启动通道。Desktop 核对本次启动的进程 ID、注册地址和规范数据库后发送挑战。后台在写入登记后检查挑战和自己的身份，再沿子进程通道返回独立凭证。凭证只留在两端内存，通道随后关闭。
- `daemon-autostart-service.ts` 管理桌面常驻开关和系统启动项。设置状态由用户配置和操作系统保存。
- `daemon-surface.ts` 判断登记地址是否指向本机。 `ipc.ts` 注册界面的常驻开关入口。
- `native-daemon-fetch.ts` 用 Node HTTP 连接本机私有路由。Browser 和 Computer 都使用它，避免发送浏览器来源请求头。

测试覆盖启动模式和语言初始化。新增后台启动行为放本目录，会话连接放相邻的 session 目录。

无窗口启动向后台显式传入规范 workspaces 根，让系统常驻和按需后台中的无项目定时任务与窗口聊天使用同一目录。渠道装配独立使用规范 channels 根。
