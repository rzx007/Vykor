# Desktop 电脑操作

[`availability.ts`](availability.ts) 核对 Windows x64、试点开关和随包文件。主窗口据此公布入口，主进程在接受任务前再次核对，并确认驱动摘要与固定版本一致。执行驱动前核对本轮副本的摘要与发布者签名。 [电脑操作](../../../../../../docs/computer-capabilities.md)

[`ipc.ts`](ipc.ts) 接收专用的电脑操作消息，核对当前主窗口和实际发起调用的顶层页面。会话服务复用正常聊天的消息校验，并将这条消息提交到私有后台连接。首次配对如果需要重启后台，会话服务在当前聊天重新取得状态后才提交，让首步的授权提示能送到原聊天。主窗口销毁、重新导航或渲染进程退出后，这个页面持有的连接会关闭。

已启用电脑能力时，主聊天的普通发送也可走私有入口，让模型根据消息决定是否使用 Computer。自动调用在本轮首次使用某个应用时要求当次批准。配对或会话资格检查明确未接收消息时，会话服务可继续发送普通消息；私有提交结果未知时保留原消息 ID 供核对。

[`interaction.ts`](interaction.ts) 仅向发起任务的主聊天发送应用授权、临时窗口预览和操作状态。前台键鼠取得控制时，[屏幕提示层](computer-control-overlay.ts) 从主进程显示屏幕边缘和 Esc 提示。原生键盘监听收到 Esc 后直接禁止派发并释放输入，再通知 daemon 中断这次运行。切换聊天、隐藏或最小化主窗口时撤销旧会话的电脑操作授权，已提交且尚未开始的操作也失效。暂停和继续放在聊天输入框的电脑操作选项里。退出或安装更新时先关闭新任务准入，再等待键鼠释放。

[`computer-bridge.ts`](computer-bridge.ts) 维护到本机 daemon 的认证事件流。每次连接从新的编号开始，提交时记录所属聊天。一个运行持有控制时，其他运行不能替换它的任务状态。聊天里的 Stop 先在 Desktop 主进程撤销该次运行的控制，再通知 daemon 结束运行。撤销或断线会取消正在执行的操作和等待的审批，丢弃迟到结果。收到运行结束或明确的提交拒绝后回收本轮记录。之后显式提交的新任务可以独立运行。

宿主遇到需要授权的操作时，通过私有连接把当前动作交给 daemon，在聊天中显示一次性审批卡。回复来自当前主窗口的顶层页面，且须与页面实际订阅的会话和正在等待的动作匹配。Windows 系统通知可以打开这段聊天，审批通过聊天卡片完成。

[`computer-host.ts`](computer-host.ts) 先查找登记的应用，再确认本任务有权使用。已有唯一目标时直接复用，没有窗口时启动并限时等待。应用或窗口有多个合格匹配时，通过 [`interaction.ts`](interaction.ts) 让用户选择，随后复查所选身份。接续到新应用或所属对话框时重新核对窗口并发放引用。已打开文档用 Windows 可核对的路径或标题匹配。

窗口预览只在 Electron 主进程和当前聊天中显示。捕获返回一个短期引用，同一个画面按需送给模型。接管立即拦截新输入、清除画面和控件引用，并等待键鼠释放与后台截图撤回的回执。继续前复核窗口和许可，再观察一次。运行终态、Stop 和断线均销毁控制。已经送到模型的图片无法撤回。

用户需要看到结果时，助手也可请求一次结果截图。Desktop 仍核对目标窗口和截图权限，daemon 在任务完成时把有效的图片加入助手消息。结果图没有坐标操作引用。

输入框的「分享窗口截图」由 [`window-share.ts`](window-share.ts) 在本机列出可选窗口。用户点选后沿用单窗截图的身份和安全校验，图片回到原聊天的附件草稿。这个入口不创建 daemon 运行。Browser 桥在执行同一聊天的命令前释放前台键鼠、清除旧截图和控件引用，并等待本机确认释放。浏览器仍按自己的来源权限执行。

[`windows-apps.ts`](windows-apps.ts) 从 Windows 应用目录查找已登记的打包应用和普通桌面程序，用宿主掌握的登记或已查证的程序路径启动。[`windows-window-query.ts`](windows-window-query.ts) 核对窗口和进程归属、登录用户、进程创建时间、对话框所属窗口与输入桌面。窗口图像、控件读写和前台输入接入时，应使用宿主已核对的目标。

[`windows-driver.ts`](windows-driver.ts) 在临时目录校验上游 Cua 驱动的固定哈希和发布者签名，以本机输入输出管道读取指定窗口的控件树。[`windows-semantic-query.ts`](windows-semantic-query.ts) 先检查窗口归属和认证界面，再读取字段值和生成操作引用。识别到凭据界面时交还给用户。触发、选择、滚动或写入前重新核对输入桌面和窗口归属。写入前通过当前控件核对完整旧值，以免覆盖刚发生的编辑。控件令牌只在本次观测中有效，取消与关闭会销毁驱动连接和临时状态。

[`windows-foreground.ts`](windows-foreground.ts) 管理这次前台输入独占的本机子进程。[`windows-foreground-query.ts`](windows-foreground-query.ts) 只截图已核实的一个窗口，并拒绝桌面不可用、凭据和密码控件等场景。点击前重新校对画面、窗口位置、缩放、显示器和命中控件。键盘输入前复核焦点控件的可访问性身份。文本输入还需核实编辑控件的窗口句柄。助手每次通过专用消息泵确认输入观察钩子，键鼠消息只进入已核实的目标窗口队列。接管后只向原接收窗口提交尚未入队的抬起消息。窗口消息进入队列、进程退出和应用效果分别核对。依赖物理键盘状态的应用快捷键可能需要应用语义操作或人工接管。

[`computer-semantics.ts`](computer-semantics.ts) 把控件名、类型、可读状态和支持的动作交给模型，并分发本轮控件引用。宿主在派发前核对窗口和控件快照。写入、选择和滚动使用读回值确定结果，按钮或菜单只报告观察到的界面变化。需要审批时先关闭当前驱动，批准后重新打开并复查。换窗、目标消失或操作后需要重新使用新引用。

当前目标、一次性许可和窗口引用留在当前连接的任务内存中。用户明确保存的应用许可放在 Desktop 本地偏好设置，可在运行设置撤销。切换应用、阻挡对话框或断线后，旧引用不能继续用。

[`windows-daemon-identity.ts`](windows-daemon-identity.ts) 只在需要替换已登记的后台时核对 Windows 进程身份。配对凭证保留在 Electron 主进程的 daemon 连接服务。运行和审批记录由 daemon 持有。新动作加到电脑宿主，认证、事件与取消行为由桥处理。回归用例放在 [`__test__/`](__test__/README.md)。
