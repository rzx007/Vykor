# Desktop 电脑操作

[`availability.ts`](availability.ts) 在主进程核对 Windows x64、试点开关、驱动摘要、固定版本清单和许可证。主聊天尝试使用电脑能力前和截图菜单打开时都会查询当前资源。执行驱动前核对本轮副本的摘要与发布者签名。 [电脑操作](../../../../../../docs/computer-capabilities.md)

普通消息从[会话入口](../session/ipc.ts)提交。[电脑操作的 IPC](ipc.ts)核对实际发起调用的顶层页面、主窗口可见性和当前聊天。符合条件时，会话服务使用已配对的本机 daemon 连接，让模型可以按需选择 Computer。首次配对如果需要重启后台，会话服务等当前聊天重新取得状态后再提交，让首步授权提示能送到原聊天。主窗口销毁、重新导航或渲染进程退出后，这个页面持有的连接会关闭。

首次请求应用授权时，用户可在当前聊天选择仅本任务或始终允许。已记住的授权可在运行设置撤销。配对或会话资格检查明确未接收消息时，会话服务继续发送普通消息。私有提交结果未知时，重试前先核对原消息 ID。

[`interaction.ts`](interaction.ts) 仅向发起任务的主聊天发送应用授权、临时窗口预览和操作状态。[屏幕提示层](computer-control-overlay.ts) 随前台控制显示屏幕边缘和 Esc 提示。宿主等提示层完成首帧并显示后才派发键鼠，提示无法显示时释放本次控制。原生键盘监听收到 Esc 后直接禁止派发并释放输入，再通知 daemon 中断这次运行。切换聊天、隐藏或最小化主窗口时撤销旧会话的电脑操作授权，已提交且尚未开始的操作也失效。暂停和继续放在聊天输入框的电脑操作选项里。退出或安装更新时先关闭新任务准入，再等待键鼠释放。

[`computer-bridge.ts`](computer-bridge.ts) 维护到本机 daemon 的认证事件流。每次连接从新的编号开始，提交时记录所属聊天。一个运行持有控制时，其他运行不能替换它的任务状态。聊天里的 Stop 先在 Desktop 主进程撤销该次运行的控制，再通知 daemon 结束运行。撤销或断线会取消正在执行的操作和等待的审批，丢弃迟到结果。收到运行结束或明确的提交拒绝后回收本轮记录。之后显式提交的新任务可以独立运行。

应用获准后，宿主通过私有连接把需要审批的动作交给 daemon，按当前聊天的授权模式决定。需要用户确认时，聊天里会显示一次性审批卡。回复来自当前主窗口的顶层页面，且须与页面实际订阅的会话和正在等待的动作匹配。完全访问的前台输入会持续显示屏幕提示，并保持 Esc 可用。

[`computer-host.ts`](computer-host.ts) 先查找登记的应用，再确认本任务有权使用。已有唯一目标时直接复用，没有窗口时启动并限时等待。应用或窗口有多个合格匹配时，通过 [`interaction.ts`](interaction.ts) 让用户选择，随后复查所选身份。接续到新应用或所属对话框时重新核对窗口并发放引用。已打开文档用 Windows 可核对的路径或标题匹配。

[`computer-platform.ts`](computer-platform.ts) 定义宿主使用的本机能力，包括发现和启动应用、判断两次扫描是否指向同一个窗口实例、读取和操作控件、截图及前台键鼠。[`windows-computer-platform.ts`](windows-computer-platform.ts) 为主进程会话服务接好现有 Windows 实现，并用原生窗口、线程和进程创建信息判断窗口身份。宿主管理任务授权、窗口和画面引用及停止流程。平台实现负责核实本机状态和派发动作。

窗口预览只在 Electron 主进程和当前聊天中显示。捕获返回一个短期引用，同一个画面按需送给模型。可用该引用选取窗口内的一小块区域，按原始像素捕获，返回新引用和局部坐标。接管立即拦截新输入、清除画面和控件引用，并等待键鼠释放与后台截图撤回的回执。继续前复核窗口和许可，再观察一次。运行终态、Stop 和断线均销毁控制。已经送到模型的图片无法撤回。

用户需要看到结果时，助手也可请求一次结果截图。Desktop 仍核对目标窗口和截图权限，daemon 在任务完成时把有效的图片加入助手消息。结果图没有坐标操作引用。

输入框的「分享窗口截图」由 [`window-share.ts`](window-share.ts) 在本机列出可选窗口。用户点选后沿用单窗截图的身份和安全校验，图片回到原聊天的附件草稿。这个入口不创建 daemon 运行。Browser 在队列里核对标签页和动作许可后，才交接同一聊天的前台占用。交接时清除该占用的画面与控件引用，并等待本机确认键鼠释放。

[`windows-apps.ts`](windows-apps.ts) 从 Windows 应用目录查找已登记的打包应用和普通桌面程序，用宿主掌握的登记或已查证的程序路径启动。[`windows-window-query.ts`](windows-window-query.ts) 核对窗口和进程归属、登录用户、进程创建时间、对话框所属窗口与输入桌面。窗口图像、控件读写和前台输入接入时，应使用宿主已核对的目标。

[`windows-driver.ts`](windows-driver.ts) 在临时目录校验上游 Cua 驱动的固定哈希和发布者签名，以本机输入输出管道读取指定窗口的控件树。[`windows-semantic-query.ts`](windows-semantic-query.ts) 先检查窗口归属和认证界面，再读取字段值和生成操作引用。识别到凭据界面时交还给用户。触发、选择、滚动或写入前重新核对输入桌面和窗口归属。写入前通过当前控件核对完整旧值，以免覆盖刚发生的编辑。控件令牌只在本次观测中有效，取消与关闭会销毁驱动连接和临时状态。

[`windows-foreground.ts`](windows-foreground.ts) 管理这次前台输入独占的本机子进程，将截图坐标换算为屏幕位置。[`windows-foreground-query.ts`](windows-foreground-query.ts) 只截图已核实的窗口，拒绝桌面不可用、凭据和密码控件。鼠标派发前核对坐标附近的画面、窗口几何和命中控件。助手用带本次标记的 Windows 输入来操作鼠标，在系统将事件送进队列时再检查目标。拖拽每步重新检查前台窗口和几何。取消时先拦住新的按下、移动和滚轮，尝试取消原窗口的拖拽，再释放本轮实际按下的鼠标键和修饰键。系统释放与应用效果分别核对。键盘和文字继续使用定向窗口消息，按键前复核焦点，输入文字时还要核实原生编辑控件。

[`computer-semantics.ts`](computer-semantics.ts) 把控件名、类型、可读状态和支持的动作交给模型，并分发本轮控件引用。写入、选择和滚动核对目标控件及动作相关的旧状态。按钮或菜单也会核对周围状态，因为同一个按钮可能作用于不同的选中项。需要审批时先关闭当前驱动，批准后重新打开并复查。完全访问直接进入派发前检查。派发后的读回使用已经复查窗口身份的 Windows 原生控件值。窗口标题变化且文档身份无法核实时，结果待核对，由下一次观察确认新目标。

当前目标、一次性许可和窗口引用留在当前连接的任务内存中。用户明确保存的应用许可放在 Desktop 本地偏好设置，可在运行设置撤销。切换应用、阻挡对话框或断线后，旧引用不能继续用。

[`windows-daemon-identity.ts`](windows-daemon-identity.ts) 只在需要替换已登记的后台时核对 Windows 进程身份。配对凭证保留在 Electron 主进程的 daemon 连接服务。运行和审批记录由 daemon 持有。新动作加到电脑宿主，认证、事件与取消行为由桥处理。回归用例放在 [`__test__/`](__test__/README.md)。
