# 用量设置

设置中的“用量统计”页，回答所选范围用了多少 Token、何时产生、主要来自哪些模型或供应商。沿用 `billing` 路由，以 Token 趋势和占比为重点，不显示费用、估算价格或金额阈值。

## 放置边界

这里呈现用量信息；消息内的单次用量提示留在 conversation-page/message/notices。

组件、模型、类型和 hook 按本功能共同维护。测试、测试辅助文件和基准测试统一放在同级 `__test__`，沿用被测功能的文件名。

## 主要文件

- [usage-settings.tsx](usage-settings.tsx)：页面入口、筛选、每 30 秒刷新、CSV/JSON 导出与请求顺序保护。`maintenanceApi()` 仍供已有存储和诊断页面调用。
- [usage-analytics.ts](usage-analytics.ts)：按本地日期分组、合计已知字段、生成模型和供应商前四名及其他项；今天按小时，较长范围按天，超过 62 天按月。
- [usage-charts.tsx](usage-charts.tsx)：真实数值的输入/输出堆叠柱形图，以及接入的 [beUI 环形占比图](../../../charts/README.md)。支持 Token / 请求记录切换、模型 / 供应商分组和键盘检查时间点。
- [usage-request-table.tsx](usage-request-table.tsx)：每页十条请求，完整数字、简短任务 ID、未知状态与窄窗口内的横向滚动。
- [usage-token-budget.tsx](usage-token-budget.tsx)：默认收起的本月 Token 阈值表单，修改后明确保存。提醒沿用全项目本月统计和系统通知，不受页面筛选影响；启用或保存 Token 阈值时清除旧金额阈值，并用完整旧预算检查并发修改，不停止任务。已有启用的金额规则明确提示仍可能发送通知，由用户选择替换或关闭，读取页面不会改写它。
- [usage-ui.tsx](usage-ui.tsx)：复用 beUI Tabs 与 DigitSwap，组合统一的指标切换、数字读数和可聚焦的帮助 tooltip；只处理本页呈现。

## 数据与状态

页面通过桌面维护 API 读取真实请求记录，不使用示例数据，也不重新累计会话或任务汇总。服务端保存原始用量与提醒设置；时间、筛选、图表指标和明细页码只保存在当前页面。每次返回结果同时保存对应的时间边界与筛选；刷新失败或筛选尚未完成时明确显示上次结果，导出使用当前已显示结果的筛选。CSV/JSON 沿用后端，保留费用等兼容字段，不解释为实际扣款。

已知 Token = 输入 + 输出，缓存单独展示。未知字段保持 `null` 并显示“—”；有记录但全部未知的时间段不画成零，无请求记录的时间段不伪造活动。模型按供应商和模型共同分组，同名模型不会被错误合并。分组占比和趋势始终使用同一份筛选结果。

## 视觉与检查

保留 Vykor 的字体、主题与外壳，按用户反馈用 beUI Card 分隔概览、趋势、占比、明细和提醒。四项概览数字共享一个模块，使用已接入的 DigitSwap；时间切换复用 beUI Tabs，图表指标与分组使用其完整胶囊样式，提醒展开复用 beUI Collapsible。右上角复用 beUI OverflowActions 的圆角操作组，常驻“刷新用量”，展开更多操作后明确显示“导出 CSV”和“导出 JSON”。统计口径、缓存、历史缺失与操作解释收进可通过键盘访问的 tooltip；错误、旧规则状态等必须处理的信息仍直接显示。没有新增运行时依赖。

按项目约定，样式由用户查看反馈；代码检查与同级 `__test__/` 覆盖日期边界、聚合、导出、Tabs、展开编辑及提醒交互。
