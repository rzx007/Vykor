# 工具接入与运行准备

| 文件 | 用途 |
| --- | --- |
| `default-tool-registry.ts` | 调用工具工厂，组装默认工具注册表 |
| `tool-ports.ts` | 将技能、配置、MCP 和飞书能力适配为工具需要的接口 |
| `default-runtime-tools.ts` | 应用工具配置，生成模型可见、应用调用和委派使用的工具范围 |
| `prepare-run-tools.ts` | 根据本次能力快照重新绑定工具，登记本次运行可用的定义 |
| `__test__/` | 注册表、工具范围、权限结构、MCP 授权与运行视图测试 |

运行组装时建立基础注册表；提交时再依据当前允许的技能、插件和 MCP 来源准备本次工具。返回的绑定交给执行核心和查询引擎使用，后续配置变化通过下一次准备生效。

默认注册表包含只读 `ToolResult`，通过 `list` 找回可访问的引用、`read` 分页补读或 `search` 搜索正文。注册时记录实际内置定义身份，运行时结合捕获的身份与执行函数识别，防止同名替换工具获得结果查询的特殊待遇。该工具与其他工具一样遵守宿主上限和角色允许范围。


基础工具保存在运行资源的注册表中，本次能力由运行目录记录。新增本机工具适配和准备规则放在这里，具体工具实现放在 `@vykor/tools`，通用执行检查放在 `@vykor/core`。测试放在同层 `__test__/`。


普通权限与审批通过后，执行入口调用当前 Run 的 `checkToolDispatch`，核对 owner、会话、Run、输入归属、cwd、最终工具绑定和运行修订。检查失败终止本 Run；工具普通错误与 unknown 只反馈本次调用，不限制其他新调用，也不自动重试。实际调用 Promise 一直跟踪到工具真正结束。

宿主可提供 `bindToolDispatch(scope, tools)` 工厂；框架在可靠 Run 启动后用最终工具集合生成检查。模型、手动、嵌套及子 Run 共用入口，替换 preparation 不能删除顶层宿主工厂。子 Run 重新绑定自己的范围。独立 SDK 不需要数据库。
