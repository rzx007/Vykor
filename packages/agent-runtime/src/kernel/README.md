# 执行核心

管理一次 agent 运行的创建、输入、取消、结果交付和事件顺序。调用方注入查询引擎与执行能力，本目录负责协调这些能力。

| 文件或目录 | 用途 |
| --- | --- |
| `index.ts` | `createAgentKernel()` 等执行核心工厂与接口 |
| `agent.ts` | `KernelAgent`，协调提交、工具操作、检查与关闭 |
| `framework-agent-run.ts` | `FrameworkAgentRun`，管理一次运行并转换查询引擎事件 |
| `event-source.ts` | `AgentEventBus`，按顺序交付带有运行归属的事件 |
| `agent-errors.ts` | 状态类型、操作冲突与错误转换 |
| `equality.ts` | 比较配置等普通数据 |
| [children/](./children/README.md) | 子 agent 登记、生命周期和活动记录 |
| `__test__/` | 核心状态、事件、错误与工具流程测试 |

提交入口先检查当前状态，再创建运行和绑定输入。查询引擎产出的事件经运行对象交给事件总线，最终结果通过运行句柄交付。agent、运行对象和子登记表分别持有自己的状态。

本机配置、文件系统、网络连接和插件装配放在 `../node/`，通过接口传入执行核心。构建时会检查本目录的代码和类型声明，避免它们引入这些本机模块。新增生命周期协调代码放在本层，子管理规则放在 `children/`，测试放在同层 `__test__/`。
