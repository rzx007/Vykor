# 执行核心

管理一次 agent 运行的创建、输入、取消、结果交付和事件顺序。调用方注入查询引擎与执行能力，本目录负责协调这些能力。

| 文件或目录 | 用途 |
| --- | --- |
| `index.ts` | `createAgentKernel()` 等执行核心工厂与接口 |
| `agent.ts` | `KernelAgent`，协调提交、工具操作、检查与关闭 |
| `framework-agent-run.ts` | `FrameworkAgentRun`，管理一次运行并转换查询引擎事件 |
| `event-source.ts` | `AgentEventBus`，按顺序交付带有运行归属的事件 |
| `tool-safety.ts` | 校验工具记录与强制规则必须成对配置 |
| `tool-results.ts` | 在最终工具范围确定后绑定补读能力，拒绝复用范围较宽或来源不同的静态存储 |
| `agent-errors.ts` | 状态类型、操作冲突与错误转换 |
| `equality.ts` | 比较配置等普通数据 |
| [children/](./children/README.md) | 子 agent 登记、生命周期和活动记录 |
| [delivery/](./delivery/README.md) | 可选的输出格式、提交工具和交付回执 |
| `__test__/` | 核心状态、事件、错误与工具流程测试 |

提交入口先检查当前状态，再创建运行和绑定输入。查询引擎产出的事件经运行对象交给事件总线，最终结果通过运行句柄交付。agent、运行对象和子登记表分别持有自己的状态。

本机配置、文件系统、网络连接和插件装配放在 `../node/`，通过接口传入执行核心。构建时会检查本目录的代码和类型声明，避免它们引入这些本机模块。新增生命周期协调代码放在本层，子管理规则放在 `children/`，测试放在同层 `__test__/`。

可选的 `toolSafety` 由宿主提供工具操作记录和强制检查能力。提交、手动 `runTool()`、嵌套调用与子运行沿用同一能力；调用方替换本次准备过程不会移除已配置的宿主检查。仅从准备结果提供能力的宿主，在手动调用时也会完成准备，并在结束后释放资源。执行核心不访问数据库。

模型运行先按提交选项固定最终工具集合，再等待 `bindToolResults(finalTools)` 返回本轮补读能力。手动 `runTool()` 一律完成准备，按实际执行工具集合调用同一个绑定函数，结束后释放准备资源。工厂不会传给工具，以免工具重新申请更宽范围。

公开旧字段 `PreparedAgentRun.toolResults` 与手动 `options.toolResults` 已弃用，在 `tool-results.ts` 保留一处适配。没有工厂的旧准备存储，只有名称集合、来源、定义身份和调用函数完整等价时才能复用；收窄或替换后补读不可用。旧手动显式 store 保留可信宿主已经绑定的语义，但不再跳过准备。兼容检查保留是因为公开类型、README 与测试已有此承诺。新宿主统一使用准备工厂。`__test__/result-store-binding.test.ts` 覆盖收窄、旧字段兼容、来源替换、准备失败和工厂不泄露。

模型运行在可靠的 `run.started` 事件处理完成后才绑定结果存储，确保宿主已创建子运行记录。绑定成功且取消检查通过后才确认启动并进入模型；不能为绕过启动顺序而允许访问尚未存在的运行。手动入口仍要求宿主先提供有效运行范围。

`FrameworkAgentRun.settled` 等待真实工具调用（含迟到回执审计）与准备清理后固定实际结果，随后 `result` 等待终态保存。执行结果、终态事件与补偿输出均从这份结果派生。清理失败保留 active 和 `cleanupUnconfirmed`；再次明确停止只确认原清理，不重放执行。已发生的执行失败保留原失败；暂算的成功在确认停止前可被可信取消改变，确认后的迟到信号不重开结果。`AgentEventDeliveryError` 保留原事件；终态故障可通过原 settlement 的只读保存确认谓词解除 `projectionError`，不影响启动/工具接纳失败。
