# 查询执行

`QueryEngine` 是模型与工具循环的入口。它接收用户消息，维护当前历史，组织压缩、模型请求、工具调用和结束处理，并通过 `submitMessage()` 的异步事件流将进度与结果交给调用方。

## 文件与子目录

| 位置 | 用途 |
| --- | --- |
| `query-engine.ts` | 查询循环、请求配置应用、历史维护、手动工具执行与压缩入口 |
| `turn-context.ts` | 固定本轮请求的消息与工具列表，拼接系统提示和记忆提醒 |
| `index.ts` | `@vykor/core/engine` 公开入口 |
| [model/](./model/README.md) | 执行模型请求、处理流式响应和重试 |
| [tools/](./tools/README.md) | 准备、授权和执行工具调用 |
| [results/](./results/README.md) | 保存有容量上限的 SDK 结果引用，统一文本分页和字面检索 |
| [compaction/](./compaction/README.md) | 缩减历史消息并保留继续任务所需的线索 |
| [trajectory/](./trajectory/README.md) | 根据工具结果生成后续行动提示 |
| [usage/](./usage/README.md) | 累计模型请求用量 |
| `__test__/` | 查询循环、请求配置、记忆注入、目标上下文等整体流程测试 |

## 状态与调用关系

`QueryEngine` 实例保存消息历史、当前模型和提示词、最近工具结果以及累计用量。每轮先准备历史和请求，再调用 `model/`；出现工具调用时交给 `tools/`，将结果写入历史后继续。`compaction/` 返回缩减后的历史，由引擎接管。

自动压缩在本轮系统提示和可见工具确定后执行：从上下文容量中扣除输出额度、安全余量，以及系统提示、工具定义、记忆和运行说明的估算占用，再判断历史是否需要缩减。目标续跑使用同一条路径。若接口在请求阶段或流式事件中返回明确的上下文超长错误，同一轮最多尝试一次被动压缩；优先使用提供商的结构化标记，无标记时仅匹配明确的输入超长描述，不把工具定义或输出额度限制当成历史过长。只有历史估算确实变小才重建请求，恢复不重新执行已有工具，也不额外消耗工作轮数。

摘要请求使用当前模型输出上限、运行上限和摘要自身 20,000 上限中的最小值；手动压缩前重新解析当前模型和客户端配置，切换后也使用新的上限。运行内的摘要仍经过当前运行的预算和取消检查，进度通过 `context_compaction` 事件返回。显式 Token 预算下，失败请求的用量未知时仍会暂停目标，不为自动恢复伪造零用量。

每轮请求配置可以提供 `supportsImageInput`。值为 `false` 时，`turn-context.ts` 将发给模型的用户消息、工具结果中的图片替换为文字说明，保留其余正文与工具调用关系。替换只作用于本次请求；引擎历史和已保存的原图不变，切回支持图片的模型后可继续发送。调用方未提供该能力时，保留原有图片发送行为。

运行上下文由调用方传入，提供取消信号、执行限制、事件发送和请求准入等能力。会话落盘与运行调度应放在调用方所在包。

工具批次后的恢复决策放在 `tools/tool-batch-recovery.ts`：纠错次数、重复失败恢复额度和轨迹要求收尾的决定一起返回下一轮控制状态，额度耗尽则抛出现有错误。状态仍是本次 `submitMessage()` 的局部变量。引擎保留执行顺序：完整结果入历史 → 交付结束事件 → 执行失败与取消检查 → 内部工具成功结束运行 → 纠错上限 → 观察轨迹 → 恢复额度 → 轮数、请求配置和后续输入；普通决策函数通过回调保留观察轨迹的时机。

宿主提供 `toolResults` 时，引擎先等待完整结果保留成功，再给模型裁剪正文并交付事件。事件保留完整内容及可信 `resultRef`；模型历史的大小限制只作用于正文，补读引用提示在裁剪后补上。`ToolResult` 的已捕获内置定义按身份识别，其查询输出不再次保留；未知执行结果不提供完整结果引用。保留失败会终止本轮，避免模型以为已保存的正文实际丢失。`__test__/tool-result-reading.integration.test.ts` 覆盖大结果尾部、跨 Run 找回、工具范围收窄、伪造引用和保存失败。

取消会撤销本轮归档能力；这时不再申请补读引用，已经结算的工具仍交付真实结果和结束事件。取消发生在异步保留期间也遵循此规则，避免归档错误盖住原取消原因。活跃运行的保留失败终止本 Run，保留 completed 事实且不发布引用。

新增代码只有负责协调多个步骤时才放在本层；模型、工具或压缩的具体规则放入对应子目录。模块测试跟随各子目录，跨步骤测试放在本层 `__test__/`。

设置子运行 hardMaxTurns 时，普通工作请求的系统提示使用当前有效上限与 turnCount 计算剩余轮次；提示不进入持久历史。最后一轮仍由既有无工具收尾处理，报告不把 max_turns 改成成功。轮次限制工作循环，同轮网络重试冻结原请求，压缩和网络尝试仍由各自机制控制。
