# 模型请求

处理一次模型请求如何发出、如何读取流式结果、失败后何时重试，以及如何记录请求开始和结束。

| 文件 | 用途 |
| --- | --- |
| `model-attempt-runner.ts` | `runModelAttempt()` 发出一次主生成请求，读取文本、推理、工具参数和用量 |
| `model-attempt-control.ts` | 标记请求准入和结算过程中的失败，供上层识别 |
| `query-model-attempt.ts` | 创建可取消的请求信号，描述失败，生成请求结束事件 |
| `model-retry.ts` | 规范重试策略，计算延迟与次数限制，等待期间响应取消 |
| `buffered-model-retry.ts` | 为摘要、记忆等辅助请求提供重试，完整接收后再返回内容 |
| `__test__/` | 重试策略、辅助请求、查询重试和请求准入测试 |

主生成由 `QueryEngine` 调用 `runModelAttempt()`，模型事件直接传回上层，汇总结果交回引擎更新历史。辅助请求先缓存在当前调用内，确认完成后才输出，避免失败请求的残缺内容进入摘要。

请求准入指“发给模型之前先检查本次运行是否允许继续请求”；准入和用量结算能力由调用方通过运行上下文提供。请求内的缓冲与取消状态留在本目录，主生成的重试计数和历史更新由 `QueryEngine` 管理。

新的模型请求或重试规则放在这里；模型供应商的 HTTP 协议实现放在 `@vykor/api`。测试放在同层 `__test__/`，对外导出由 core 的公开入口统一维护。
