# 历史消息压缩

当长对话接近模型的上下文容量时，缩减旧消息，同时尽量保留最近工具调用和继续任务所需的信息。

| 文件 | 用途 |
| --- | --- |
| `compact-service.ts` | `CompactService` 入口，选择压缩步骤、处理重试并报告进度 |
| `compact-types.ts` | 压缩来源、进度、检查点、补充上下文和摘要客户端接口 |
| `compact-messages.ts` | 估算消息大小，清理旧工具输出、截断长内容并保护工具调用与结果的配对 |
| `compact-prompt.ts` | 构造摘要提示，提取近期文件与工具工作记录 |
| `compact-summary.ts` | 收集和格式化模型摘要，识别上下文超长错误 |
| `compact-continuity.ts` | 保留继续任务所需的原文片段，管理压缩前后的衔接信息 |
| `__test__/` | 压缩阶段、回退、取消与上下文保留测试 |

`QueryEngine` 在模型请求前调用自动压缩，也可通过 `compact()` 手动触发。服务先清理旧工具输出和截短长文本，再按需请求模型摘要；没有摘要客户端或摘要失败时，使用简单压缩作为后备处理。压缩结果交回引擎替换历史。

`autoCompact()` 接收本轮历史以外的输入估算，用于为系统提示和工具定义留出空间。接口已报上下文超长时，`reactive` 来源会绕过“本地估算未超限”的跳过判断，并尝试将历史估算至少缩小 20%；仍按原有保留窗口保护最近消息。引擎只在历史确实缩小后重试一次，避免反复发送同样超长的请求。

主请求恢复和摘要重试共用 `isPromptTooLongError()`：先检查提供商给出的 `contextLengthExceeded`，`false` 阻止文字兜底，仅对请求无效类错误放行；没有分类时通过契约包的共用规则识别实际错误说明开头的上下文溢出。认证、配额及普通工具参数限制不能触发历史压缩。

压缩阈值、连续失败次数和检查点保存在 `CompactService` 实例中。摘要客户端与额外任务上下文由调用方注入。新增压缩规则放在对应文件，测试放在同层 `__test__/`；完整设计见 [上下文压缩说明](../../../../../docs/compact-service-design.md)。

日常续做的原文摘录保留真实用户约束、工具 `executionState`、`isError` 和完整结果引用；再次压缩时继续携带这些已有字段。旧摘要没有执行字段时不推断成功。摘录仍受原有字数预算限制，缺失片段会明确标记；结果引用仍须经过当前会话及工具权限校验。生成的摘要不能把计划或未知结果变成已完成事实，也不能授权重复执行外部操作。

`compact-continuity.test.ts` 检查反复压缩后的执行状态和结果引用；Server 的 `daemon-daily-continuation.integration.test.ts` 验收持久记录关闭重开、压缩后补读和未知写入阻断。
