# 历史消息压缩

当长对话接近模型的上下文容量时，缩减旧消息，同时尽量保留最近工具调用和继续任务所需的信息。

| 文件 | 用途 |
| --- | --- |
| `compact-service.ts` | `CompactService` 入口，选择压缩步骤、处理重试并报告进度 |
| `compact-types.ts` | 压缩来源、进度、检查点、补充上下文和摘要客户端接口 |
| `compact-messages.ts` | 估算消息大小，清理旧工具输出、截断长内容并保护工具调用与结果的配对 |
| `compact-prompt.ts` | 构造摘要提示，提取近期文件与工具工作记录 |
| `compact-transcript.ts` | 将历史转成有界文本，保留工具身份、参数、结果配对及显式执行事实 |
| `compact-summary.ts` | 收集、验收和格式化模型摘要，识别上下文超长错误 |
| `compact-continuity.ts` | 保留继续任务所需的原文片段，管理压缩前后的衔接信息 |
| `__test__/` | 压缩阶段、回退、取消与上下文保留测试 |

`QueryEngine` 在模型请求前调用自动压缩，也可通过 `compact()` 手动触发。服务先清理旧工具输出和截短长文本，再按需请求模型摘要；没有摘要客户端或普通摘要请求失败时，使用简单压缩作为后备处理。压缩结果交回引擎替换历史。

新生成的摘要必须包含一个闭合、正文非空的 `<summary>`；可选的 `<analysis>` 草稿会被移除，不能单独充当摘要。空响应、未闭合、重复或嵌套摘要不通过验收。第一次不合格时，使用同一摘要客户端请求一次格式纠正；纠正额度覆盖整个压缩操作，不因上下文超长重试而重置。所有实际请求仍经过既有预算、取消和用量结算，格式不合格不改写已完成请求的计费事实。

最终验收失败，或格式纠正请求失败时，服务抛出内部 `CompactSummaryValidationError`，不使用简单压缩替代旧历史，也不计入普通请求失败的熔断计数。自动、手动和被动压缩都在成功后才提交候选历史；验收失败会结束本轮，不继续发送主请求或执行工具，不报告 `compact_end` 或触发 `post_compact`。取消、预算和请求准入错误保持原来的传播方式。旧的已保存摘要不重新验收或迁移。

`compact-summary.test.ts` 覆盖摘要结构与清理，`compact-service-advanced.test.ts` 覆盖纠正额度、失败后历史保留和后备边界；上层 `engine/__test__/summary-validation.test.ts` 覆盖主循环停止、请求准入、用量结算和取消。

`collectSummary()` 通过 `buildCompactTranscript()` 转录传入的旧历史。转录器先统计调用和结果 ID，再保持原消息顺序输出；只有调用与结果 ID 均唯一、且调用在结果之前时才附加配对工具名。重复 ID 标记 `ambiguous`，孤立或逆序结果标记 `unmatched`，不按相邻消息、工具名或结果引用猜测配对。工具调用保留名称、ID 和参数；参数解析失败只保留 `inputError`，不把占位 `{}` 当作有效输入。

每条源消息转录后最多 4,000 字符，包含角色、标签、JSON 转义、换行和省略提示。先为调用身份、解析状态及结果的显式执行状态、错误标志、完整结果引用和受控事实留出空间，再分配参数与正文。长参数保留头尾并明确标记为不完整 JSON 摘录，预算须同时容纳标记与摘录；过量调用、超长身份或引用整项省略，不截短不透明 ID。`compactSummary` 沿用既有事实处理，正文中已前置的同一事实块只保留一次；与 `resultRef` 匹配的宿主补读提示也去重，由完整引用元数据统一保留或省略。旧结果缺少状态时不推断成功。

转录器只生成本次请求的字符串与临时索引，不修改消息、不执行工具、不展开引用。前置 context collapse 保留匹配的宿主补读提示全文，使转录器仍能识别并统一处理，避免先压短出残缺引用。图片替换为占位说明，不读取或序列化来源。`compact-transcript.test.ts` 覆盖实际发送的摘要请求、配对、预算和事实保留；服务集成用例同时验收 micro/collapse 后的转录和既有格式纠正保护。

`autoCompact()` 接收本轮历史以外的输入估算，用于为系统提示和工具定义留出空间。接口已报上下文超长时，`reactive` 来源会绕过“本地估算未超限”的跳过判断，并尝试将历史估算至少缩小 20%；仍按原有保留窗口保护最近消息。引擎只在历史确实缩小后重试一次，避免反复发送同样超长的请求。

主请求恢复和摘要重试共用 `isPromptTooLongError()`：先检查提供商给出的 `contextLengthExceeded`，`false` 阻止文字兜底，仅对请求无效类错误放行；没有分类时通过契约包的共用规则识别实际错误说明开头的上下文溢出。认证、配额及普通工具参数限制不能触发历史压缩。

压缩阈值、连续失败次数和检查点保存在 `CompactService` 实例中。摘要客户端与额外任务上下文由调用方注入。新增压缩规则放在对应文件，测试放在同层 `__test__/`；完整设计见 [上下文压缩说明](../../../../../docs/compact-service-design.md)。

日常续做的原文摘录保留真实用户约束、工具 `executionState`、`isError` 和完整结果引用；再次压缩时继续携带这些已有字段。旧摘要没有执行字段时不推断成功。摘录仍受原有字数预算限制，缺失片段会明确标记；结果引用仍须经过当前会话及工具权限校验。生成的摘要不能把计划或未知结果变成已完成事实，也不能授权重复执行外部操作。

`compact-continuity.test.ts` 检查反复压缩后的执行状态和结果引用；Server 的 `daemon-daily-continuation.integration.test.ts` 验收持久记录关闭重开、压缩后补读和未知写入阻断。
