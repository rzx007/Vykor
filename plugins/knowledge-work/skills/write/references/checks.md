# 写作检查工具

只在研究后成稿、忠实改写检查或用户要求审校时读取。纯文风修改不需要额外研究。

## 研究覆盖

`KnowledgeWritingGate` 直接接收研究台账：

```json
{
  "required_families":["产品能力","使用限制"],
  "sources":[{"url":"https://example.org/product/docs","families":["产品能力","使用限制"],"status":"usable","published":"2026-10-12"}],
  "min_sources":1
}
```

上例日期、URL 和分类只展示形状，实际值须来自已读取来源。`required_families` 是保留说法需要的证据分类，不是任意主题标签；同一来源只标它正文实际支持的分类。归一后的重复 URL 只计一个来源；百科、首页和泛分类入口不算具体证据。`min_sources` 默认 1，可按用户要求设置 1–20；URL 数量仍不证明证据独立。

返回的 `decision` 为 `READY_TO_DRAFT` 或 `CONTINUE_RESEARCH`，另有缺失分类、无日期分类和被忽略行。无日期来源仍可覆盖分类，是否足以支持当前说法由智能体判断。缺口有望解决时定向补查；无法解决时缩小或删除依赖该证据的说法，再检查保留内容。不能为了通过随意删掉仍在稿件中的分类。

从报告成稿前先读取真实 check.json，不用报告自称“已核验”作为 usable 的依据。对保留的关键事实沿用引用及其限制；原句不匹配、来源缺失或尚未核实的说法不能通过分类数量变成已确认事实。用户原始比较项仍是文章结构依据，不能沿用报告偷换的定义。

## 稿件审校

`KnowledgeContentAudit` 直接接收文字；可选源文用于忠实改写的词法对照：

```json
{"text":"当前完整稿件","source_text":"编辑前的原文","max_findings":100}
```

默认返回最多 100 条候选问题，支持 1–1000 条。结果保留原版的 `summary/findings/links`，提供源文时还有 `source_comparison`；重要问题优先返回，截断与实际统计明确标记。

- 统计：拉丁词、汉字、段落、Markdown 标题、HTTP(S) 链接；代码块和行内代码不作普通稿件扫描。
- 待核验项：待补占位、数字和日期、直接引用、模糊出处。
- 表达候选：宣传、空泛重要性、泛化开场和结尾、助手回复残留、机械对比、重复句首、长句。
- 源文对照：数字／日期、引用标记的增加或遗漏，披露整体或赞助／资助身份变化，以及新增桥接推断的词法匹配。

`citation_marker_present` 只表示该行有链接或引用标记，不说明链接支持数字。`source_comparison` 只对比文字标记与特定表达；重述后的事实、否定、范围、限制和披露是否语义完整，仍要读原文逐项核对。链接清单未联网检查，不能称为“所有链接有效”。

查看完整候选后再修改，不为消除风格提示而破坏准确表达或作者语气。如任务要求发布决定，由智能体在事实、引用、披露和用户要求检查后作出；工具没有自动发布通过状态。

研究文章、整篇改写和缩短稿件交付前运行审校；改写的 source_text 来自刚读取的编辑前全文。保存真实 audit.json，并结合原文处理保留的限制和引用，不凭模型记忆判断用户有没有手工修改。篇幅计数区分正文与全文，不能只数汉字后声称包含英文、数字和来源的全文满足同样上限。
