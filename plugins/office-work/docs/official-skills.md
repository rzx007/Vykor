# 官方 Skill 接入（0.12.0 清理完成）

## 默认使用方式

插件直接加载 `vendor/officecli/skills` 下的四份官方技能：`officecli`、`officecli-docx`、`officecli-pptx`、`officecli-xlsx`。来源固定到插件归档中引擎相同的 v1.0.139，原始 Git blob 与 SHA-256 记录在 `vendor/officecli/SOURCE.json`，原文不改写。没有安装全局技能，运行时不下载引擎。

三个专家加载通用技能与对应格式技能，使用 OfficeCLI 原生命令入口。插件自身的调用说明位于工具描述及专家指令中，说明参数传递、工作副本和结果交付；不复制官方文档制作方法。

## 执行入口

官方示例 `officecli add "$FILE" /body --type paragraph --prop text="更新时间：10.17"` 对应：

```json
{"command":"add","path":"office-work/report.docx","expected_sha256":"刚读取的摘要","args":["/body","--type","paragraph","--prop","text=更新时间：10.17"]}
```

- `command` 是原生命令动词；`path` 是工作区文件；`args` 不包含文件名、shell 引号、管道或变量。无需转义 `$`，不会启动 shell。
- 帮助示例：`{"command":"help","args":["docx","paragraph","--json"]}`。属性、语义路径和枚举以当前引擎 help 为准，入口不维护旧工具的编辑属性白名单。
- `batch` 的 JSON 数组传入 `operations`，自动停止于首个错误；不从任意输入文件或 shell 管道读取。其他命令不用 `operations`。
- 写入需最新 `expected_sha256`，用户原文件默认另存；每次使用顶层返回的实际 `path` 和 `sha256` 继续。原生结果内可能包含工作副本路径，不能使用该临时路径交付。
- 复用已有同文件排队、工作副本、关闭清理、重启恢复和成果记录。每次调用都释放工作副本，模型不用调用 `open/save/close`。
- 现有只读 Check／Preview／Review 仍可使用；截图与历史检查记录本轮未重写。

## 首轮边界

已接入单文件 create、get、query、文本类 view、raw、validate、dump、add、set、remove、move、swap、batch、raw-set、add-part，以及 help／版本查询。资源文件限制在工作区内，模型不能指定任意输出文件参数。跨文件合并／导入、批处理文件输入、原生截图输出与专项技能未在本轮接入；说明缺失能力，不自动安装依赖或绕过入口。

编辑可选 scope_targets，范围核对通过返回版本绑定的 change_check 与 scope_verified:true；不传时 scope_verified:false。编辑执行成功本身仍返回 structure_checked:false；只有显式 validate 的读取结果才声明完成了结构检查。没有把旧业务工具的限制搬进新入口，也不声称通用命令经过了旧工具的逐对象／逐单元格范围证明。智能体依据官方技能和用户要求回读、检查、看图并报告实际证据。

旧 Create／Read／Edit 工具、对应的重复实现及三个自定义 Skill 已删除。仅保留官方技能、一个编辑入口与九个检查／预览／记录工具。[范围核对](editing-scope.md) 是可选检查，不是编辑命令白名单。

## 已验证与未验证

真实插件加载器能加载四份官方技能和三个专家绑定；官方文件摘要一致。临时 Word 文件通过了原生追加、文字替换、按位置插入与删除、批量字体修改、读取和结构检查，并核对源文件不变、过期版本和非法路径被拒绝。

这验证了实际命令链和加载能力，尚未证明模型在真实对话中会正确选用技能并完成整套验收。临时 PPT 已验证原生建页、表格和局部修改，临时 Excel 已验证多表、前导零、跨表公式、图表和区域格式；仍待真实业务案例及模型对话验收。0.12.0 的 Word Preview 首次截图曾失败，修正与复测见下文。

## 0.12.1 复测修正

- 插件技能完整名称（如 `office-work:officecli`）在与用户技能同名时仍可解析；短名继续遵循原优先级。需要应用更新后的 Skill 注册表，单独重装插件不能替代公共层修复。官方四份 Skill 原文未修改。
- Word 截图改用 OfficeCLI 原生分页总览（`--grid 2`），完整分页和继承页眉页脚后按实际 A4 页面边界裁出指定页，保留截图原始像素，不放大、不依赖固定偏移。新版证据标记 `word-grid-page-v3`，旧有效检查历史保留，不把缺页截图当作证据。
- 公式检查增加 `missing_cache_cells`。OfficeCLI v1.0.139 原生命令修改输入值后会清掉相关公式的保存缓存；读操作可预测结果，但只读检查不会回写源文件。因此预测可用、缓存缺失、原生重算未验证可以同时成立。
- 清理核对应在所有 Office 调用完成后进行。0.12.0 会话的目录检查与最后一次读取在同批并发运行，所见副本不能作为清理失败证据。临时文件实测两路同文件读取串行完成，返回后锁与副本均消失，未调整锁恢复或删除规则。

## 0.12.2 基础正文补齐与完整性检查

上游 skills/officecli/SKILL.md 为指向 ../../SKILL.md 的符号链接。插件将 v1.0.139 根目录 SKILL.md 的完整原文直接放入基础技能入口，不要求运行时解析链接；SOURCE.json 同时保留原链接及正文的 Git blob 与 SHA-256 来源。其他三份格式技能原文保持不变。

构建脚本检查四份技能的入口、名称、Markdown 正文、固定版本来源和两种摘要，基础技能还检查关键章节与链接来源。市场生成 ZIP 后可用同一校验脚本从包内重新执行检查；缺文件、只剩路径占位或正文被截断均使校验失败。专项回归测试覆盖这些失败情况。

## 0.12.3 市场发行

独立 Node 构建准备六个平台的固定版本程序和公共引擎模块，不依赖桌面打包。官方技能检查支持整个插件归档，只展开待验证的文本；Office 文档读取仍保留原有大小限制。升级沿用相同插件 ID、权限和 dataDir，文档操作与检查回执逻辑不变。
