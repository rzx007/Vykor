# 演示文稿

首版仅 Windows x64；工具仅处理当前工作区里的 .pptx。输入使用实际文件路径，当前桌面附件上传不接受 Office 文件。无需安装 PowerPoint、WPS、Python 或 LibreOffice；完整插件 ZIP 自带固定版本 OfficeCLI。引擎缺失或校验失败时直接说明并请求重新安装完整插件，不临时下载、安装、启动浏览器或改走其他脚本。

## 内容与创建

用户只要大纲时直接返回逐页提纲，不创建空 PPT。创建前读取用户报告或文字资料，确定受众、用途、页数和每页重点。默认中文、16:9，用户已给的信息优先。明确请求直接执行，只有缺失条件会实质改变结果时才提问。

研究报告不是自动可信的事实库：一并读取存在的来源和检查文件；保留推断及证据缺口，不把近似案例改写成直接证据。每页保留相关来源链接或出处文字；没有资料的数字不编造。页序与指定标题原文保留。

使用 OfficePptCreate 一次提交完整 slides，最多 24 页。path 默认 `office-work/<topic>/presentation.pptx`，用户路径优先。每页 title 必填，body 可选；复杂区域用 shapes、tables、images，不堆叠同区域的 body 与自由文本。

```json
{"path":"office-work/example/presentation.pptx","slides":[
  {"title":"方案比较","shapes":[{"text":"关键结论","name":"takeaway","x":"2cm","y":"3cm","width":"25cm","height":"2cm","size":"28pt","color":"17365D"}],"tables":[{"rows":[["方案","适用范围"],["文件","大文件"]],"x":"2cm","y":"6cm","width":"25cm"}]}
]}
```

所有关键文字、形状、表格均为原生可编辑对象。图片只接受工作区内 PNG/JPEG 的 src，位置用带单位的长度，例如 `2cm`；不支持远程图片、图表、复杂母版、动画或旧 .ppt/.dps/.key 格式。不要通过把整页做成图片冒充可编辑 PPT。

表格默认使用 16pt 字号，根据列宽、换行与文字长度估算每行高度，并明确写入单元格字号与行高；这是估算，不是视觉检查。可指定 size（如 `16pt`）、colWidths（如 `8cm,10cm,12cm`，总和须等于 width）、rowHeight 或 height。过小的高度或页面放不下的内容会被拒绝：优先精简文字、调整列宽或拆页，不能为通过检查把字号缩到 12pt 以下。修改整张表的高度不能代替行高调整；需要调整时用表格的 rowHeight，或精确修改 `/table[...]/tr[...]` 的 height。已有文件的文字修改不会自动重排无关行列。

创建时，表格最终高度还会与同页显式定位的文本框比较，要求至少留出 6pt 垂直间距。出现冲突时工具会指出页码、表格和文本框，并给出下方文本可用的最小 y；空间不足时精简或拆页。证据限制、来源等文本不要按预想表高固定在表格下面，应按工具计算后的表格底部安排。检查仅覆盖有明确 x/y/width/height 和物理单位的文本框，不代替看图；装饰背景不参与这项检查。工具不会自动挪动作者的内容。

## 读取和持续修改

先 OfficePptRead(path)，再按 `/slide[2]` 单页读取；保存返回的 sha256，从实际结果中选择稳定元素 path（如 `/slide[2]/shape[@id=2]`），不能猜形状编号。结果过大时缩小到单页或元素。

OfficePptEdit 传入最新 expected_sha256 与 operations，每项仅 path、props，支持文字和基础样式，不支持删页、增页、重排或复杂对象改造。例如：

```json
{"path":"office-work/example/presentation.pptx","expected_sha256":"这里替换为刚读取返回的64位摘要","operations":[{"path":"/slide[2]/shape[@id=2]","props":{"text":"修改后的标题"}}]}
```

文字替换会替换目标元素的全文，可能不保留元素内部混合字样；有此要求时先说明边界，不承诺无损修改复杂演示稿。用户已有文件默认另存 `-edited.pptx`；插件创建或修订的成果根据插件记录持续修改同一文件。实际返回路径为准，重名时选择明确的新路径，不循环创造无关版本。

文件摘要不匹配则重新读取当前文件，在保留手工修改的前提下重新定位；不能用旧摘要或旧计划直接覆盖。临时修改通过结构检查和页面差异核对后才保存。OfficePptEdit 自动比较修改前后的页面 XML 与其他文件包内容，返回 page_diff：requested_pages 是请求修改页，changed_pages 是实际变化页，unchanged_pages 是未变化页。指定页没有实际变化时不能声称已经修改。未请求页面、页数页序、共享资源或其他受保护内容变化时拒绝保存；不要绕过检查重建整份演示稿。不比较 ZIP 压缩方式和核心元数据，页面差异核对不等于视觉检查。锁文件表示另一个操作或前次异常中断，不能擅自删除锁重试覆盖。

同文件工具调用会自动等待前一个操作结束，等待受当前调用期限与取消控制；不同文件可独立执行。有关联的检查和回读仍优先顺序调用，避免不必要的排队。读取、检查也在临时副本运行 OfficeCLI，不让引擎驻留原始文件。检测到 `~$` Office 占用标记或明确的占用错误时，提示用户关闭 PowerPoint/WPS 中此文件后再试，不杀应用进程、不删除占用标记，也不反复调用直到超时。标记可能残留，已关闭时应确认实际占用与目录权限。

工具为关闭和清理工作副本预留时间，关闭失败最多自动重试一次。返回 `cleanup_complete:false` 时按实际 `cleanup_warning` 或错误说明临时目录未清理；有成果路径和摘要的成功结果仍代表文件已保存，不要因此重复创建或覆盖。关闭未确认时保留副本并报告 `temporary_directory`，不能擅自删除，也不把关闭超时解释成队列太长。该状态不代表文件结构、内容或视觉检查自动通过。

## 检查与交付

创建或修改后调用 OfficePptCheck，并回读指定页，核对页数、标题顺序、修改文字和应保留的内容。只对变化部分补读，不为同一不变文件重复整套检查。检查失败不能宣称已完成；交付最后有效文件与具体问题。

支持图片输入的模型可调用 `OfficePptPreview({"path":"office-work/example/presentation.pptx","page":2})`，每次只查看所需单页。修改后优先查看 page_diff.changed_pages；不要为同一 sha256 和页码重复截图。工具固定使用 OfficeCLI 的 HTML 渲染，不启动 PowerPoint；图片通过工具图片结果返回，保存在插件 dataDir/previews，工作副本会清理。若截图失败，报告具体原因，不安装浏览器、不自动切换渲染器或反复重试。不支持看图的模型跳过截图并说明视觉未检查。

收到图片后观察该页文字是否可读、表格是否拥挤、是否存在明显重叠或裁切，并按页码说明发现。`rendered:true` 仅表示截图生成成功；工具保持 `visual_checked:false`，不能直接改称视觉通过。没有实际看到图片时不得声称看过。此阶段只检查并报告，不自动循环修复；有新的修改授权时再执行局部修改。HTML 渲染不能证明 PowerPoint/WPS 的字体、动画或显示完全一致。

实际看图后调用 OfficePptReview 保存检查记录：expected_sha256 使用截图返回的 sha256，pages 每项提供 preview_id、conclusion（passed 或 issues）及非空 findings。没有发现问题时也写明实际观察到的内容，例如“标题、正文清晰，未见明显裁切或重叠”；不能只因截图成功就填写 passed。不传猜测的页码，工具从已保存的截图记录中确定实际页码，并核对截图摘要、源路径和当前文件版本。

```json
{"path":"office-work/example/presentation.pptx","expected_sha256":"截图返回的64位摘要","pages":[{"preview_id":"截图返回的编号","conclusion":"issues","findings":"第2页表格第二列文字拥挤，末行疑似裁切。"}]}
```

记录位于插件 dataDir/visual-reviews，按文件路径与 sha256 区分版本。同版本分批查看的页面合并，重新检查某页仅替换该页记录。OfficePptCheck 只附带当前摘要匹配的 visual_review；文件变更后没有新版本记录就视为尚未记录视觉检查，不套用旧结论。交付中说明 sha256、checked_pages 和逐页发现，scope=checked_pages_only，不把部分页面通过说成全稿通过。记录来源为 model_reported，表示模型报告的观察，不代表程序能证明模型实际看过图片。

工具记录实际路径、sha256 和结构检查状态于插件 dataDir/presentations，供后续修改识别当前成果；PPT 保存在工作区，不放插件安装目录。报告当前 PPTX 路径与修改范围，分别说明结构检查、页面差异核对和实际查看过的页码；字体替换、动画与目标软件兼容性仍由用户在 PowerPoint/WPS 中验收。

每次 Review 返回的 record_path 指向独立检查快照，后续复查不会覆盖它；当前汇总结果另存，复查仅更新当前汇总中的对应页。已有历史文件保留。交付请引用本轮返回的 record_path。

应用异常退出后，新版工具只在确认本机原持有者进程已退出时，关闭并清理其已登记工作副本，再恢复操作。活跃或无法确认的持有者、旧版空锁与无登记目录不自动回收；遇到 office_recovery_required 应报告具体路径和原因，不通过 Shell 删锁、强杀进程或反复重试，不擅自换目录重建成果。
