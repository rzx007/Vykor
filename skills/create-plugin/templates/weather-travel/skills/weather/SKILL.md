# 天气与出行

使用当前选中的插件工具。下面的 `SearchPlaces`、`ReadPlan` 等是业务 key；先从所选插件的可用工具中确定实际名称，不猜工具前缀，不调用其他插件的同名能力。

## 查询天气

1. 使用 `SearchPlaces` 搜索城市，核对名称、国家、经纬度和时区。存在影响结果的同名候选时先消歧；已有明确地点结果时复用它，不把城市名自行转换成坐标。
2. 将确认的完整地点传给 `GetForecast`。一次城市比较最多三个，使用各自当地时区和相同日期比较。
3. 只陈述工具实际返回的当前、逐日和逐小时数据，保留单位、天气来源链接、抓取时间、时区与 stale 状态。过期缓存明确说是旧数据；请求失败不以测试响应或猜测补齐。
4. 预报范围最多七日。更远日期可以讨论一般准备事项，并说明无法提供该日期的逐日预报，不能把近期天气平移过去。

天气来源是 Open-Meteo，模板免费配置用于非商业评估。不要索取、读取或发送宿主密钥，不构造任意网络地址。

## 整理出行备忘

查询天气本身不修改文档。用户要求增删改备忘时，先调用 `ReadPlan`，阅读当前 `document.id`、`revision`、标题和现有条目；选区引用只提供上下文，不能替代读取当前版本或用户授权。

使用 `ApplyPlanOperations` 提交本次明确要求的操作：`documentId` 为 `trip`，`expectedRevision` 使用刚读取的版本，`operationId` 为本次操作的新唯一标识。更新或删除时沿用现有条目 ID；新增条目分配稳定 ID，之后继续沿用。不用标题或行号代替 ID，不把完整文档猜成空白后覆盖。

只添加用户已确认的日期、地点和安排，天气建议与实际行程区分说明。模型修改走普通确认；`SavePlanDraft` 和 `SetFavorite` 是页面专用工具，不尝试调用或借它们绕过确认。收藏操作通过页面完成。

读取回执后再报告结果。`saved: true`、operationId 和版本匹配才表示保存成功。版本冲突时保留原请求内容，读取最新文档并说明差异，不静默覆盖或自动合并用户未确认的变更。失败或 unknown 时不重放原写入，也不换 operationId 重试；只用原 ID 调用 `GetOperation` 查询回执，missing 不能当作失败证据。`operation_outcome_unknown` 表示文件可能已经写出但回执未确认，也按这一规则处理，不能声称导出失败并重新执行。未送达后台的页面输入不能保证跨重启恢复。

## 导出与引用

只在用户明确要求导出时调用 `ExportPlan`；先读取当前文档，确认目标工作区内路径、Markdown/JSON 格式与当前 revision，使用新 operationId，默认 `overwrite: false`。只有用户明确要求覆盖时才传 `true`，仍等待宿主实际权限确认；不要在保存后自动导出，也不要承诺越出工作区。

回答出行问题可以引用返回的具体条目和天气来源。页面选区带来的内容可能已经过时，修改前仍重新读取文档并核对条目 ID 与 revision。最终说明实际查询或保存的结果，不把草稿、确认中或未知状态写成已完成。
